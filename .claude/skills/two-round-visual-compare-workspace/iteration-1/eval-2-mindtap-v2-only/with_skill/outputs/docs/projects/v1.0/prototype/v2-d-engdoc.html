capture.pipeline.runOcrBatch(notes: Note[], opts?: BatchOpts) → Promise<OcrResult[]>
● stable since v1.1.0 2 open issues

Batch a list of notes through the OCR pre-pass, collapsing calls that arrive within the same 30s window into a single job. Drops wall-time on bursty capture sessions by 4–8× with no regression on the validation set.

Caveats

  • EU builds gate the 32k tokenizer behind hasEntitlement("tokenizer-32k"). Use swapTokenizer() only after the 26.2 entitlement lands.
  • The 30s window is an advisory boundary — backpressure from the OS scheduler may push it to 31s in practice.
  • Don't combine runOcrBatch with the per-keystroke preview render; the latter is retired in v1.1.

See also

  • groupByWindow() — the grouping primitive runOcrBatch uses internally.
  • swapTokenizer() — second lane of the cost-reduction plan.
  • dropPreviewRender() — third lane, ships in v1.1.
