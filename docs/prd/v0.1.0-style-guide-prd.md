## 一、背景与目标

### 1.1 项目背景

轻念 · Mindtap 是面向开发者的极简桌面记录应用,强调**克制、清晰、有质感**的产品气质。

V0.1.0 阶段仓库刚初始化,**唯一交付物是设计语言本身**——用一份"风格指南"演示页,把"玻璃质感设计语言"落地为开发者可以肉眼查看、可以复制粘贴的视觉规范,作为后续浮窗、主窗时间线等业务功能的视觉地基。

V0.1.0 不是给终端用户用的产品,**用户就是项目开发者自己**——通过风格指南验证设计语言的玻璃组件、视觉规范、交互状态在真实窗口中呈现是否符合期望。

### 1.2 项目目标

1. **玻璃设计语言可看**:核心 UI 组件、设计规范、玻璃等级全部在演示页可点开看
2. **窗口体验一致**:透明窗口背景 + 整窗可拖 + 焦点视觉 + 系统级降级(Reduce Transparency / Reduce Motion)4 个体验一致
3. **设计稿可落地**:每个规范都能在源码里查到,每个组件都能在演示页找到用法范例
4. **新组件可走评审**:组件接口契约写明(视觉规范 / 交互状态 / 无障碍),后续评审有据可依

### 1.3 核心用户

| 角色 | 关注点 |
|---|---|
| 项目开发者(本仓库 owner) | 写代码时查规范 / 组件用法,做评审时查组件契约 |
| 后续贡献者(若开放) | 从风格指南入门,理解设计语言 |
| 终端用户 | **本版本不接触**,V0.2 起才接触浮窗 / 主窗 |

## 三、功能详细设计

### 3.1 风格指南演示页

**功能描述**:一个本地开发用的演示页,左侧侧栏导航 + 右侧展示区渲染 7 个子页(Glass / Tokens / Components / Surface / Button / Card / Form)。每个子页三段式:标题栏(标题 + 简介)+ 分段切换(预览 / 代码 / 属性)。

**用户场景**(开发者):
- 改 Button 字号时,打开 `/button` 看预览渲染对不对,看代码复制实现
- 调玻璃透明度时,打开 `/tokens` 看规范表,改基础规范后回 `/glass` 看 L1/L2/L3 渲染
- 设计新组件时,参考 `/components` 的组件契约表,套对应玻璃等级 + 规范

**业务规则**:
- 演示页只能本地开发模式访问,**不暴露生产端口**
- 演示页代码片段**只能展示源码真实片段**,不允许"伪代码示例"
- 每个规范 / 组件在演示页**必须可点击跳转到对应 4 文档**

**异常处理**:
- 路由不存在 → 兜底路由重定向到 `/glass`(首页)
- 演示页崩溃 → 侧栏仍可见,可切换其他路由

### 3.2 玻璃设计规范系统

**功能描述**:4 块规范体系,统一管理整个产品的视觉语义。

**业务规则**:
- **色彩规范**:基于冷蓝调,基底 92% 不透明度(防穿透)
- **玻璃 4 要素**:填充度 / 模糊半径 / 饱和度 / 亮度——每个等级(L1/L2/L3)有对应 4 要素值
- **圆角规范**:button / card / modal / pill 4 档,统一 10px button 圆角
- **间距规范**:对齐默认阶梯(第 5 档 = 20px 而非 24px)
- **字号规范**:全局小号 = 14px(Button 等控件统一)
- **动效规范**:所有动效有 ease-out 缓动 + 150-300ms 时长

**反模式**(强制约束):
- ❌ 任何组件**不允许自创颜色 / 阴影 / 模糊值**——必须用规范
- ❌ 间距**不允许**用魔法数字,必须用阶梯规范
- ❌ 字号**不允许**用像素直写,必须用阶梯类名
- ❌ 内容层(用户阅读区)**不允许**用最重玻璃等级(违反设计规范 §1 铁律)

### 3.3 11 个 UI 组件

**功能描述**:风格指南的核心交付,每个组件都有 4 状态(default / hover / active / focus)+ 无障碍注解。

**业务规则**:
- Button:3 档(小 / 中 / 图标)统一圆角 10px + 字号 14px
- Card:有内边距属性(无 / 小 / 中 / 大),默认中 = 16px
- Label + Input 间距 8px(行业推荐 6-8pt)
- SidebarNavLink:统一 active + 键盘焦点可见 + hover 三态
- Section:active 状态与 PageHeader 一致(主色块)
- Tabs:3 个分段(预览 / 代码 / 属性),无障碍角色=tablist
- 其他组件契约详见组件格式文档

**异常处理**:
- 组件禁用状态**必须保留可见性**(不透明度 0.5,不消失)
- 键盘焦点必须可见(键盘用户可识别当前位置)

### 3.4 透明窗口 + 整窗拖动

**功能描述**:macOS 26 透明窗口 + 隐藏标题栏 + 整窗可拖。

**用户场景**(开发者):
- 开发模式启动后,窗口背景透明,可见桌面壁纸的玻璃质感
- 鼠标在窗口**任意空白处按下并拖动**,窗口跟随移动
- 点击控件(button / input / nav)不污染拖动

**业务规则**:
- 透明窗口仅 macOS 26+ 生效,其他平台 fallback 普通窗口
- 整窗拖动由两层组成:原生窗口背景拖动 + 浏览器侧拖动区域
- button / input / a 自动取消拖动(no-drag),避免污染
- 拖动区域**不要**包住整个窗口——只侧栏顶部 + 主区顶部固定条
- 红绿灯按钮留出空间(侧栏顶部加间距)

**异常处理**:
- macOS < 26 → 用普通窗口 + 标题栏拖动 fallback
- Windows / Linux → 用普通窗口 + 标题栏拖动 fallback

### 3.5 焦点 3 层模型

**功能描述**:Window / Navigation / Keyboard 3 层焦点状态,统一焦点视觉。

**用户场景**(开发者):
- 切到其他 app → 侧栏玻璃质感降低(填充 -8% / 模糊 -6px),提示窗口失焦
- 鼠标点击导航项 → **不**显示焦点环(用键盘焦点可见 而非 鼠标焦点)
- 键盘 Tab → 显示焦点环,加粗 3px 偏移

**业务规则**:
- Window 焦点:窗口失焦钩子监听窗口可见性变化,自动应用"窗口失焦"视觉态(侧栏玻璃质感降低)
- Navigation 焦点:导航项用键盘焦点可见,active 跟 hover 视觉不冲突
- Keyboard 焦点:键盘焦点可见 偏移 2px → 3px(对比强化,Reduce Transparency 下也保留)

**异常处理**:
- 浏览器失焦事件不触发 → 兜底用 visibilitychange + 5s 轮询
- Reduce Motion 模式下,焦点环无过渡但环仍可见(无障碍优先)

### 3.6 无障碍降级(Reduce Transparency + Reduce Motion)

**功能描述**:系统级无障碍开关联到玻璃表面。

**业务规则**:
- Reduce Transparency 开启:玻璃模糊失效,背景 95% 不透明度,键盘焦点偏移 +1px(对比强化)
- Reduce Motion 开启:全部动画 / 过渡时长 → 0.01ms,滚动行为 → 自动,键盘焦点过渡 → 无(但环仍可见)

**异常处理**:
- 旧 macOS 无 prefers-reduced-* 支持 → 不降级(保留默认玻璃体验)

### 3.7 测试栈 + 持续集成工具链

**功能描述**:组件单测 + 编译期检查就绪。

**业务规则**:
- 组件单测覆盖率:核心窗口失焦监听必须有测试
- 编译期:静态类型检查通过 + 编译成功
- 持续集成 / 本地手动跑均可,不强制集成 GitHub Actions

## 四、反需求(本期明确不做)

1. ❌ **不做业务功能**:计时器 / 数据库 / 跨进程通信 / 主窗时间线 / 历史可见性 / 设置中心——这些是 V0.2+ 的事
2. ❌ **不在内容层用最重玻璃等级**:违反设计规范 §1 铁律,会被立即驳回
3. ❌ **不用鼠标焦点替代键盘焦点可见**:鼠标点击后焦点环残留,被 V0.1.1 retro 明确驳回
4. ❌ **不暴露生产端口**:风格指南仅本地开发模式,不上线
5. ❌ **不跨平台**:仅 macOS 26+ 验证,Windows / Linux 由后续版本单独验证
6. ❌ **不做自定义配置界面**:所有规范值硬编码在源码,不允许运行时改
