# L0 PRD — 产品需求文档(模板)

> **本文件夹**: `docs/prd/`
> **职责**: 纯业务,只讲用户故事/场景/规则/验收/反需求,**不出现任何技术名词**
> **写作者**: 产品视角(可以是开发兼,但写时必须切产品脑回路)
> **读者**: 业务评审者、新 agent 接手时第一时间读

## 一、命名

```
docs/prd/v<MAJOR>.<MINOR>-<feature>-prd.md
```

例:
- `docs/prd/v0.2.0-floating-window-prd.md`
- `docs/prd/v0.3.0-native-dynamic-material-prd.md`
- `docs/prd/v0.2.1-task-switching-prd.md`（历史参考，已 superseded）

## 三、写作纪律

1. **严禁出现**: 表名、字段名、API 命令、模块名、文件路径、`SQLite`、`Rust`、`React`、`Tauri`、`JSON`、`HTTP`
2. **可以出现**: 业务名词(用户、任务、计时、通知、状态)、业务动作(开始、暂停、完成)、业务数据(累计毫秒、字符上限)
3. **业务规则用业务语言**:"全局唯一 1 个进行中的任务" 而不是 "partial unique index on status='active'"
4. **每条业务规则配异常处理**: 写"如果 X 怎么办"才能完成 §3.x
5. **PRD 不引用 PRD**: 每个版本的 PRD 自包含,允许引用下层文档,但不允许引用其他版本的 PRD
