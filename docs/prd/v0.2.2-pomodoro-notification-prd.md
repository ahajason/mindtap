## 一、背景与目标

### 1.1 项目背景

V0.2.0 / V0.2.1 让用户能记录"我在做什么 + 花了多久",但**完全没有提醒**:
- 做了 2 小时没休息 → 用户自己都没意识到
- 完成一个任务 → 没有"完成感"的反馈 → 容易继续无意义地做下去

需要两层增强:
1. **时间盒(番茄工作法)**:25min 焦点 + 休息的循环节奏,避免长时间连续工作
2. **完成通知**:任务完成时弹 Windows 系统通知,给用户"完成感"

### 1.2 项目目标

| 指标 | 目标 |
|---|---|
| 焦点段振动提醒到达时间 | 距用户配置的焦点时长偏差 ≤ 1 秒 |
| 完成通知响应延迟 | ≤ 2 秒(完成 → 系统通知弹出) |

### 1.3 核心用户

同 V0.2.0 / V0.2.1(单人本地 Windows 11 用户)。

## 三、功能详细设计

### 3.1 时间盒(番茄工作法)

**功能描述**:25min 焦点 + 休息的循环节奏,避免长时间连续工作。

**用户场景**:
- Alice 上午写代码 → 开了时间盒 → 25min 后系统振动提醒"该休息了" → 休息 5min → 自动回到"开始新焦点"

**业务规则**:
- 时间盒是**可开关**的(用户能关掉,关掉时不振动不提醒)
- 焦点段长度:TBD(待 grill,候选 25min)
- 休息段长度:TBD(待 grill,候选 5min)
- 焦点段结束:振动 + 视觉提醒
- 休息段结束:视觉提醒(可配置是否振动 → TBD)
- 时间盒启动条件:TBD(用户手动开始 / 进入进行中自动开始 → 待 grill)

**异常处理**:
- 时间盒运行中用户完成当前任务:TBD(休息段是否中断 → 待 grill)
- 时间盒运行中用户切换任务:TBD(计时是否延续 → 待 grill)

### 3.2 完成通知(Windows toast)

**功能描述**:完成时弹 Windows 系统通知,给用户"完成感"。

**用户场景**:
- Alice 完成"重构 timer_session"任务 → 系统右下角弹 toast "已完成: 重构 timer_session" → 用户看到"我完成了 1 件事",获得满足感

**业务规则**:
- 完成 = 用户手动点"完成"按钮触发(同 V0.2.0)
- toast 走 Windows 系统通知(Windows 11 系统级 toast)
- toast 至少包含:**已完成任务名**
- toast 文案:TBD(待 grill)
- toast 交互按钮:TBD(候选:"查看历史" / "开始新任务",待 grill)
- 点击 toast 行为:TBD(打开主窗?折叠态?待 grill)

**异常处理**:
- 系统通知被禁用:toast 不弹,降级为浮窗内红字 message(TBD)

### 3.3 时间盒配置(本期范围)

**业务规则**:
- V0.2.2 时间盒配置**有限**:只能开关
- 焦点段 / 休息段**默认值固定**(TBD,待 grill)
- **不**暴露给用户改时长(等 V0.3.2 设置中心)
