## 一、背景与目标

### 1.1 项目背景

V0.2.0 浮窗已发版,但用户 L3 真实环境实测发现 V0.2.0 ~ V0.2.0.11 共 11 次 PATCH 都未真修下列 4 类问题:

1. **浮窗右键菜单**:HTML 实现导致菜单跑到浮窗 viewport 内部 / 边角外不可见 / 误读为状态切换
2. **折叠态状态指示位置**:技术文档"右上角 absolute"前提是错误,V1.0 原始实现是 inline-block flex 第 1 child(最左)
3. **浮窗黑边**:WebView2 半透明合成 + 系统阴影 → 出现 1px 黑边;focus 后更明显
4. **Active 任务开启路径**:展开态内 input blur 会吞 onCancel,导致 Start/右键等按钮点击失效

这 4 类问题在过去 11 个 PATCH 中"声称已修但实测未修",破坏 V0.2.0 浮窗收口承诺,需要建立 V0.2.3 PRD 重新锁住业务真值。

### 1.2 项目目标

| 指标 | 目标 |
|---|---|
| 浮窗右键菜单弹出位置 | 100% 在浮窗外 OS 层,不裁剪 |
| 折叠态状态指示位置 | 100% 在折叠态最左(标题前面),不跑到右上角 |
| 浮窗边缘透明度 | 100% 无黑边(focus / unfocus 一致) |
| Active 任务开启成功率 | 100%(展开态内点 Start 能折叠 + 进入 active) |

### 1.3 核心用户

同 V0.2.0(单人本地 Windows 11 用户)。

## 三、功能详细设计

### 3.1 浮窗右键菜单(操作系统原生菜单)

**功能描述**:浮窗右键 = 操作系统原生菜单,作为独立 OS 窗口在浮窗外层弹出,不依附浮窗 viewport。

**用户场景**:
- Alice 在浮窗右键 → 弹出 4 项菜单(显示主窗 / 退出 / 自动启动 / 取消),菜单位置在浮窗外、可视
- 对比 V0.2.x 误导描述:"右键弹菜单",实际 V0.2.6 误改成 HTML React 组件菜单,菜单被浮窗 viewport 裁剪/跑到屏幕边缘看不见

**业务规则**:
- 菜单弹在操作系统层面(独立 OS 窗口,不受浮窗 transparent / decorations / 系统阴影配置影响)
- 4 项菜单:显示主窗 / 退出 / 自动启动 / 取消(退出前弹确认框)
- 菜单弹出后浮窗保持当前折叠/展开态不变
- **右键浮窗不折叠**:折叠态 / 展开态右键都触发菜单,展开态不被折叠(B-2-1, V0.2.0.13 PATCH 锁定)

**验收标准(用户视角)**:
- [ ] 右键浮窗(折叠态):菜单在浮窗外可见,可点击 4 项
- [ ] 右键浮窗(展开态):同上,菜单同样可见,展开态不被折叠
- [ ] 菜单点击"退出":弹退出确认框,确认后退出应用
- [ ] 菜单点击"显示主窗":主窗从隐藏变显示,菜单自动关闭
- [ ] 浮窗透明 + focus 切换:菜单始终可用,不被黑边挡住

**异常处理**:
- 用户按 Esc:菜单关闭,不触发任何动作

**实现参考**:浮窗右键 = Rust 原生 Tauri Menu(实现提示,具体见 [`docs/tech/v0.2.3-floating-window-tech.md`](../tech/v0.2.3-floating-window-tech.md))

### 3.2 折叠态状态指示位置

**功能描述**:折叠态最左(标题前面)显示 8×8 inline-block 小圆点,反映当前任务状态。

**用户场景**:
- Alice 看到折叠态标题前面有个 8×8 小圆点:active 绿色呼吸、paused 橙色常亮、completed 灰色
- 对比 V0.2.x 误导描述:"右上角小圆点",V1.0 原始设计就是最左 inline-block flex 第 1 child

**业务规则**:
- 状态指示位置 = 折叠态 flex 容器最左子元素(标题前面)
- 非 absolute / 非右上角定位
- 颜色: active=绿(带呼吸) / paused=橙(常亮) / completed=灰(常亮)

**验收标准(用户视角)**:
- [ ] 折叠态最左(标题前面)能看到 8×8 小圆点
- [ ] active 状态:圆点绿色 + 呼吸节奏(~1.6 秒一次)
- [ ] paused 状态:圆点橙色 + 常亮
- [ ] completed 状态:圆点灰色 + 常亮
- [ ] 圆点不跑到右上角 / 不被裁剪 / 时有时无

**异常处理**:
- status 为 null(initial 状态):不显示圆点

**实现参考**:StatusDot = inline-block flex 最左(实现提示,V1.0 archive 原始设计)

### 3.3 浮窗无黑边(透明无系统阴影)

**功能描述**:浮窗(用户视角)贴桌面像无装饰,1px 黑边不出现;focus 后黑边也不变明显。

**用户场景**:
- Alice 看到浮窗与桌面"无缝贴边",即使清空所有 TS 内容只剩空 html 标签,黑边仍不出现
- Alice 切 IDE 焦点再切回浮窗:黑边不加重 / 不出现新黑边
- 对比 V0.2.x:WebView2 transparent 半透明合成 + 系统阴影 → 1px 黑边;focus 后 DWM 重新合成时阴影加重

**业务规则**:
- 浮窗跟"完全无装饰"一样贴在 Windows 桌面上
- focus 与 unfocus 视觉表现完全一致(无黑边、无可见阴影加重)
- 浮窗尺寸不变化(无 resize / 无系统阴影偏移)

**验收标准(用户视角)**:
- [ ] 浮窗静态显示:无 1px 黑边(即使内容清空只剩空 html)
- [ ] 浮窗 focus 切换瞬间:无新黑边、无黑边加重
- [ ] 浮窗与桌面"无缝贴边",边缘透明
- [ ] 浮窗尺寸固定 320×36(折叠态)

**异常处理**:N/A(透明 / 阴影是 OS 渲染层特性,失败时降级路径见 Tech 文档)

**实现参考**:Rust 浮窗配置 = `transparent: true` + `backgroundColor: "#00000000"` + `shadow: false`(实现提示,完整字段见 Tech 文档)

### 3.4 折叠/展开架构(单一 root div 容器)

**功能描述**:折叠态 / 展开态 / active-session 态 三态共用**同一个 root div 容器**,共享同一背景/圆角/padding,切换时容器不卸载不重建,无视觉闪动。

**用户场景**:
- Alice 在浮窗(折叠态)展开 → 容器平滑扩展(物理尺寸变化),但 root div 本身从未卸载,背景/圆角一致
- Alice 完成 active 任务 → 容器从 active 模式平滑切回 empty 模式,FoldedBar / ControlRow 替换内容,**root div 仍是同一个**
- 对比 V0.2.0.13 PATCH 旧架构: 折叠态/展开态各挂一份 `PANEL_STYLE` + `rounded-2xl` + `p-3`, 嵌套多 2 层容器(`.floating-root-folded` + `.folded-bar-inner`),切换折叠/非折叠闪一下,圆角/背景不一致(A-2 偏差)

**业务规则**:
- 单一 root div:`<div ref={panelRef} className="floating-root flex h-full w-full flex-col gap-2 overflow-hidden rounded-2xl p-3" style={PANEL_STYLE}>`
- 根 div 永远存在,内容 3 段互斥/部分覆盖:
  - **FoldedBar**: always 渲染(StatusDot + 标题 + 计时器)
  - **ControlRow**: 仅 active session 时渲染(暂停 / 恢复 / 完成 三按钮,在 FoldedBar 下方)
  - **ExpandedPanel**: 仅 `!session && expanded` 时渲染(input + 开始/取消按钮)
- panelRef 在 root div 上,覆盖整个 panel 区域(FoldedBar + ControlRow + ExpandedPanel)
- document mousedown listener + `panelRef.current.contains(e.target as Node)` check: panel 外 click → `setExpanded(false)`; panel 内 click → 不动
- 容器物理尺寸 = 折叠 320×36 / 展开 360×280(setSize IPC 驱动);圆角/背景/PANEL_STYLE 全程不变
- 切换折叠/非折叠时不闪: root div 始终是同一个 DOM node,容器样式/PANEL_STYLE 不变

**验收标准(用户视角)**:
- [ ] **A-2**: 折叠态/展开态切换时容器不闪,圆角/背景一致(肉眼逐像素对比应无差异)
- [ ] **A-2**: 折叠态/展开态切换时 root div 始终存在(浏览器 DevTools 选中节点,DOM tree 路径不变)
- [ ] **A-2**: 折叠态/展开态根 div className 一致(`floating-root flex h-full w-full flex-col gap-2 overflow-hidden rounded-2xl p-3`),无 `.floating-root.expanded` / `.floating-root folded` 切换
- [ ] **B-2-1**: 展开态(ExpandedPanel 内 input 之外)右键: 不折叠, 弹原生菜单
- [ ] **B-2-1**: 折叠态(FoldedBar 区域)右键: 不展开, 弹原生菜单
- [ ] **C-3**: 展开态点 panel 外背景: 折叠(panelRef.contains(target)=false → onDismiss)
- [ ] **C-3'**: panel 外 click 折叠后, taskTitle 输入仍保留(切回展开仍能看到旧输入)
- [ ] **C-4**: 点 Start 创建 active session 后, 浮窗折叠 + ControlRow 在 FoldedBar 下方显示(不是 V0.2.0.13 的"保持展开")

**异常处理**:
- 物理 resize(setSize IPC)失败: console.error + 保留上一尺寸(避免崩溃)
- 容器闪动回归: 锁住测试 App.test.tsx + App.fix.test.tsx 检查 root div className 永远一致

**实现参考**:
- V0.2.0.14 PATCH A-2 重构: 单一 root div + panelRef 在 root + PANEL_STYLE 提到顶层常量
- FoldedBar / ExpandedPanel 不再有自己的根 div / PANEL_STYLE / 圆角, 只返回内容 fragment
- ControlRow 从 ExpandedPanel 移到 App.tsx 渲染(因为 active session 时它在 FoldedBar 下方, 不是 ExpandedPanel 内)

### 3.5 Active 任务开启路径

**功能描述**:展开态内点击任何按钮(Start / 暂停 / 恢复 / 完成)能正确触发对应动作,不因 input blur 而误折叠回折叠态。

**用户场景**:
- Alice 展开浮窗 → 输入"重构 timer_session" → 点 Start → 浮窗折叠 + 进入 active 计时;展开态点 Start/暂停/恢复/完成/右键都能正确触发,不被"按钮点了但浮窗却折叠"误伤
- 对比 V0.2.x:展开态点 Start,input blur 同步触发 onCancel → 浮窗折叠 → Start 按钮 click 失效

**业务规则**:
- 展开态 input 失焦:默认折叠(失去焦点 = 折叠),但 panel 内点击 button 不算"失焦触发的折叠"
- 展开态内:点 panel 内任何按钮(Start / Pause / Resume / Complete / Esc)执行对应动作;点 panel 外 = 折叠
- 展开态按 Esc / Enter:执行对应动作(折叠 + onCancel / 折叠 + Start)
- **panel 外 click 折叠 + taskTitle 输入保留**(C-3', V0.2.0.14 PATCH 锁定):
  - 折叠行为 = `setExpanded(false)`,不修改 taskTitle state
  - 用户切回输入不丢输入(展开态 → panel 外 click → 折叠 → 重新点浮窗 → 展开 + 旧输入仍显示)
  - 仅用户显式 Esc / 取消按钮才清空 taskTitle(`handleClearAndDismiss`)
- **active session 时浮窗折叠 + ControlRow 显示**(C-4, V0.2.0.14 PATCH 锁定,取代 V0.2.0.13 的"保持展开"):
  - 监听 active session 变化 → useEffect 自动 `setExpanded(false)`
  - 折叠态 FoldedBar 下方显示 ControlRow(暂停 / 恢复 / 完成 三按钮)
  - "开新任务"才需展开(展开态 = 单一用途:"开新任务")
  - V0.2.0.13 旧行为"开完任务后保持展开"会让浮窗保持展开遮挡内容,user L3 改主意

**验收标准(用户视角)**:
- [ ] 展开态输入任务名 → 点 Start:浮窗按预期折叠 + 进入 active(不"按钮点了无反应")
- [ ] 展开态点 Pause:仅在 active 状态显示,点击执行暂停(不误折叠)
- [ ] 展开态点 Resume:仅在 paused 状态显示,点击执行恢复(不误折叠)
- [ ] 展开态点 Complete:active / paused 都显示,点击执行完成 + 折叠
- [ ] 展开态按 Esc:折叠不创建 session,**taskTitle 输入清空**(显式取消意图)
- [ ] 展开态按 Enter:Start 路径(同点 Start)
- [ ] 展开态点 panel 外(如背景):折叠,**taskTitle 输入保留**
- [ ] 展开态右键:不折叠,弹原生菜单(同 3.1)
- [ ] **C-3'**:展开态输入文字 → panel 外 click → 折叠 → 重新展开 → 旧输入仍显示
- [ ] **C-4**:点 Start 成功创建 active session → 浮窗**折叠** + ControlRow 在 FoldedBar 下方显示(暂停/恢复/完成)
- [ ] **C-4**:点 Complete → active 变 completed → 浮窗保持折叠态(empty 模式,无 ControlRow)

**异常处理**:
- panel 内点击 button 时 button click 可能晚于 input blur 一拍:用 capture phase 在 panel 根 div 提前判定"是否点 panel 内",若点 panel 内则保留 blur listener 不触发 onCancel
- V0.2.0.14 PATCH 根除 race: 用 `document mousedown` listener + `panelRef.contains(target)` check 替代 input blur listener(更可靠,不依赖 input 是否失焦)

**实现参考**:
- V0.2.0.12 PATCH: Radix pointerdown capture 守住 panel 内点击
- V0.2.0.13 PATCH: 拆 `onCancel` → `onDismiss`(只折叠,保留 taskTitle)+ `onClearAndDismiss`(清 taskTitle + 折叠)
- V0.2.0.14 PATCH: 单一 root div + panelRef 在 root 上 + document mousedown listener + panelRef.contains check(具体见 Tech 文档)

| B-2-1 | 浮窗(展开态)右键 | 同上,展开态不被折叠;**不折叠**(panelRef 在 root, 整个 panel 都是 panel 内) |
| B-2-2 | 浮窗右键菜单(主窗可见时) | 菜单文案 = "隐藏任务栏";浮窗隐藏后文案变 "显示任务栏" |
| C-3 | 展开态点 panel 外(背景) | 浮窗折叠;taskTitle 输入**保留**(切回展开仍能看到) |
| C-3' | 展开态按 Esc / 点取消按钮 | 浮窗折叠;taskTitle 输入**清空**(用户显式取消意图) |
| C-4 | 点 Start 创建 active session | 浮窗折叠 + ControlRow 在 FoldedBar 下方显示(暂停/恢复/完成);**不是 V0.2.0.13 的"保持展开"** |
| C-4 | 点 Complete | active → completed → 浮窗保持折叠态(empty 模式,无 ControlRow) |
| E-3 (透明无黑边) | 浮窗静态显示 | 无 1px 黑边 |
| E-3 (透明无黑边) | 切 IDE 焦点再切回浮窗 | 黑边不加重 |
| F-6 | 展开态输入任务名 → 点 Start | 浮窗折叠 + 进入 active(不"按钮点了无反应") |
| F-7 | 展开态输入任务名 → 按 Enter | 同 F-6 |
| F-9 | 展开态按 Esc | 浮窗折叠,不创建 session,taskTitle 清空(C-3') |
