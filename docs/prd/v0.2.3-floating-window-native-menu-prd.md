## 一、背景与目标

### 1.1 项目背景

V0.2.0 浮窗已发版,但用户 L3 真实环境实测发现 V0.2.0 ~ V0.2.0.11 共 11 次 PATCH 都未真修下列 4 类问题:

1. **浮窗右键菜单**:HTML 实现导致菜单跑到浮窗 viewport 内部 / 边角外不可见 / 误读为状态切换
2. **折叠态状态指示位置**:技术文档"右上角 absolute"前提是错误,V1.0 原始实现是 inline-block flex 第 1 child(最左)
3. **浮窗黑边**:WebView2 半透明合成 + 系统阴影 → 出现 1px 黑边;focus 后更明显
4. **Active 任务开启路径**:展开态内 input blur 会吞 onCancel,导致 Start/右键等按钮点击失效

这 4 类问题在过去 11 个 PATCH 中"声称已修但实测未修",破坏 V0.2.0 浮窗收口承诺,需要建立 V0.2.3 PRD 重新锁住业务真值。

### 1.2 项目目标

| 指标 | 目标 |
|---|---|
| 浮窗右键菜单弹出位置 | 100% 在浮窗外 OS 层,不裁剪 |
| 折叠态状态指示位置 | 100% 在折叠态最左(标题前面),不跑到右上角 |
| 浮窗边缘透明度 | 100% 无黑边(focus / unfocus 一致) |
| Active 任务开启成功率 | 100%(展开态内点 Start 能折叠 + 进入 active) |

### 1.3 核心用户

同 V0.2.0(单人本地 Windows 11 用户)。

## 二、需求概述

### 2.1 需求范围

**本期做** — 锁住 V0.2.3 的 4 个核心业务规则(对应 V0.2.0 PATCH 反复修未真修的 4 类问题):

1. **浮窗右键 = 操作系统原生菜单**(独立窗口,弹在浮窗外 OS 层)
2. **折叠态状态指示位置 = 折叠态最左**(标题前面 8×8 小圆点,inline-block flex 第 1 child,非 absolute 右上角)
3. **浮窗无黑边**(用户视角:浮窗贴桌面像无装饰;focus 后也不明显)
4. **Active 任务开启路径**:展开态内点击不误折叠回折叠态

**本期不做**(同 V0.2.0 + V0.2.1):
- 主窗时间线 / 设置中心(V0.3+)
- 复盘 / 多用户 / 同步(V1.0)
- macOS(V0.3,本版本锁定 Windows 11)

### 2.2 功能清单

| # | 功能模块 | 业务规则 | 优先级 |
|---|---|---|---|
| 1 | 浮窗右键菜单 | 操作系统原生菜单(独立 OS 窗口,弹在浮窗外 OS 层,不裁剪);4 项菜单(显示主窗 / 退出 / 自动启动 / 取消) | P0 |
| 2 | 折叠态状态指示 | 最左(标题前面)8×8 inline-block 小圆点;active 绿色呼吸 / paused 橙色常亮 / completed 灰色 | P0 |
| 3 | 浮窗边缘 | 无黑边(focus / unfocus 都一致) | P0 |
| 4 | Active 任务开启路径 | 展开态内点击任何按钮(含 Start / 暂停 / 恢复 / 完成 / 右键)不误折叠回折叠态 | P0 |

## 三、功能详细设计

### 3.1 浮窗右键菜单(操作系统原生菜单)

**功能描述**:浮窗右键 = 操作系统原生菜单,作为独立 OS 窗口在浮窗外层弹出,不依附浮窗 viewport。

**用户场景**:
- Alice 在浮窗右键 → 弹出 4 项菜单(显示主窗 / 退出 / 自动启动 / 取消),菜单位置在浮窗外、可视
- 对比 V0.2.x 误导描述:"右键弹菜单",实际 V0.2.6 误改成 HTML React 组件菜单,菜单被浮窗 viewport 裁剪/跑到屏幕边缘看不见

**业务规则**:
- 菜单弹在操作系统层面(独立 OS 窗口,不受浮窗 transparent / decorations / 系统阴影配置影响)
- 4 项菜单:显示主窗 / 退出 / 自动启动 / 取消(退出前弹确认框)
- 菜单弹出后浮窗保持当前折叠/展开态不变

**验收标准(用户视角)**:
- [ ] 右键浮窗(折叠态):菜单在浮窗外可见,可点击 4 项
- [ ] 右键浮窗(展开态):同上,菜单同样可见,展开态不被折叠
- [ ] 菜单点击"退出":弹退出确认框,确认后退出应用
- [ ] 菜单点击"显示主窗":主窗从隐藏变显示,菜单自动关闭
- [ ] 浮窗透明 + focus 切换:菜单始终可用,不被黑边挡住

**异常处理**:
- 用户按 Esc:菜单关闭,不触发任何动作

**实现参考**:浮窗右键 = Rust 原生 Tauri Menu(实现提示,具体见 [`docs/tech/v0.2.3-floating-window-tech.md`](../tech/v0.2.3-floating-window-tech.md))

### 3.2 折叠态状态指示位置

**功能描述**:折叠态最左(标题前面)显示 8×8 inline-block 小圆点,反映当前任务状态。

**用户场景**:
- Alice 看到折叠态标题前面有个 8×8 小圆点:active 绿色呼吸、paused 橙色常亮、completed 灰色
- 对比 V0.2.x 误导描述:"右上角小圆点",V1.0 原始设计就是最左 inline-block flex 第 1 child

**业务规则**:
- 状态指示位置 = 折叠态 flex 容器最左子元素(标题前面)
- 非 absolute / 非右上角定位
- 颜色: active=绿(带呼吸) / paused=橙(常亮) / completed=灰(常亮)

**验收标准(用户视角)**:
- [ ] 折叠态最左(标题前面)能看到 8×8 小圆点
- [ ] active 状态:圆点绿色 + 呼吸节奏(~1.6 秒一次)
- [ ] paused 状态:圆点橙色 + 常亮
- [ ] completed 状态:圆点灰色 + 常亮
- [ ] 圆点不跑到右上角 / 不被裁剪 / 时有时无

**异常处理**:
- status 为 null(initial 状态):不显示圆点

**实现参考**:StatusDot = inline-block flex 最左(实现提示,V1.0 archive 原始设计)

---

### 3.3 浮窗无黑边(透明无系统阴影)

**功能描述**:浮窗(用户视角)贴桌面像无装饰,1px 黑边不出现;focus 后黑边也不变明显。

**用户场景**:
- Alice 看到浮窗与桌面"无缝贴边",即使清空所有 TS 内容只剩空 html 标签,黑边仍不出现
- Alice 切 IDE 焦点再切回浮窗:黑边不加重 / 不出现新黑边
- 对比 V0.2.x:WebView2 transparent 半透明合成 + 系统阴影 → 1px 黑边;focus 后 DWM 重新合成时阴影加重

**业务规则**:
- 浮窗跟"完全无装饰"一样贴在 Windows 桌面上
- focus 与 unfocus 视觉表现完全一致(无黑边、无可见阴影加重)
- 浮窗尺寸不变化(无 resize / 无系统阴影偏移)

**验收标准(用户视角)**:
- [ ] 浮窗静态显示:无 1px 黑边(即使内容清空只剩空 html)
- [ ] 浮窗 focus 切换瞬间:无新黑边、无黑边加重
- [ ] 浮窗与桌面"无缝贴边",边缘透明
- [ ] 浮窗尺寸固定 320×36(折叠态)

**异常处理**:N/A(透明 / 阴影是 OS 渲染层特性,失败时降级路径见 Tech 文档)

**实现参考**:Rust 浮窗配置 = `transparent: true` + `backgroundColor: "#00000000"` + `shadow: false`(实现提示,完整字段见 Tech 文档)

### 3.4 Active 任务开启路径

**功能描述**:展开态内点击任何按钮(Start / 暂停 / 恢复 / 完成)能正确触发对应动作,不因 input blur 而误折叠回折叠态。

**用户场景**:
- Alice 展开浮窗 → 输入"重构 timer_session" → 点 Start → 浮窗折叠 + 进入 active 计时;展开态点 Start/暂停/恢复/完成/右键都能正确触发,不被"按钮点了但浮窗却折叠"误伤
- 对比 V0.2.x:展开态点 Start,input blur 同步触发 onCancel → 浮窗折叠 → Start 按钮 click 失效

**业务规则**:
- 展开态 input 失焦:默认折叠(失去焦点 = 折叠),但 panel 内点击 button 不算"失焦触发的折叠"
- 展开态内:点 panel 内任何按钮(Start / Pause / Resume / Complete / Esc)执行对应动作;点 panel 外 = 折叠
- 展开态按 Esc / Enter:执行对应动作(折叠 + onCancel / 折叠 + Start)

**验收标准(用户视角)**:
- [ ] 展开态输入任务名 → 点 Start:浮窗按预期折叠 + 进入 active(不"按钮点了无反应")
- [ ] 展开态点 Pause:仅在 active 状态显示,点击执行暂停(不误折叠)
- [ ] 展开态点 Resume:仅在 paused 状态显示,点击执行恢复(不误折叠)
- [ ] 展开态点 Complete:active / paused 都显示,点击执行完成 + 折叠
- [ ] 展开态按 Esc:折叠不创建 session
- [ ] 展开态按 Enter:Start 路径(同点 Start)
- [ ] 展开态点 panel 外(如背景):折叠
- [ ] 展开态右键:不折叠,弹原生菜单(同 3.1)

**异常处理**:
- panel 内点击 button 时 button click 可能晚于 input blur 一拍:用 capture phase 在 panel 根 div 提前判定"是否点 panel 内",若点 panel 内则保留 blur listener 不触发 onCancel

**实现参考**:Radix pointerdown capture 守住 panel 内点击(实现提示,具体见 Tech 文档)

## 四、术语表

| 术语 | 业务含义 |
|---|---|
| 折叠态 | 浮窗默认 UI 态:显示任务名 + 计时器 + 状态指示 |
| 展开态 | 浮窗输入态:显示输入框 + 控制按钮(Start/Pause/Resume/Complete) |
| 状态指示 | 折叠态最左 8×8 圆点,反映 timer_session 状态 |
| 浮窗右键菜单 | 浮窗右键弹出的操作系统原生菜单(显示主窗 / 退出 / 自动启动 / 取消) |
| Active 任务 | timer_session status='active' 的任务,即"用户当前正在做什么" |
| blur 误折叠 | input blur 同步触发 onCancel 折叠回折叠态,使按钮点击失效 |
| OS 层菜单 | 操作系统原生弹出的菜单窗口,独立 HWND,不受浮窗 viewport 限制 |

## 六、反需求(本期不做)

| 不做 | 原因 |
|---|---|
| 自定义右键菜单内容 | 4 项菜单是 V0.2.3 锁定值,自定义在 V0.3+ |
| 浮窗菜单点击"自动启动"切换开机启动 | 本期只是菜单项存在,实际切换 autostart 在 V0.3 |
| StatusDot 颜色主题 | active 绿 / paused 橙 / completed 灰固定 |
| 浮窗 resize / 缩放 | 浮窗尺寸固定 320×36 / 展开态 360×280,不开放 user 拖拽 resize |
| 浮窗左 / 下 / 上 / 全方向定位 | 浮窗默认右上角 -16px(沿用 V0.2.7 锁定) |
| 展开态内 animation / transition | 本期(沿用 V0.2.0.11 移除 transition) |
