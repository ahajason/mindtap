## 一、背景与目标

### 1.1 项目背景

创意人群每天在多任务间频繁切换，上午打开 IDE + 邮件 + 飞书，半小时后已经忘了 IDE 里那个任务叫什么；下午复盘时回忆"这周做了什么"全凭主观感觉。

番茄钟类工具的失败模式：主动启动 → 主动停止 → 主动分类，每一步都打断心流。人进入心流时完全感知不到时间流逝，番茄钟 25 分钟振动是"已经晚了"的提醒。

### 1.2 项目目标

| 指标 | 目标 |
|---|---|
| 浮窗触发到开始计时 | ≤ 3 秒 |
| 工作流被打断 | 0 次（非用户主动操作不抢当前焦点） |
| 一周后能回忆每天做了什么 | ≥ 80% 任务 + 时长 |

### 1.3 核心用户

单人本地 Windows 11 用户，需要轻量记录"我在做什么 + 花了多久"。

## 二、需求范围

### 2.1 本期做

- 浮动窗（常驻桌面，显示当前任务 + 计时）
- 全局快捷键唤起 / 隐藏浮窗
- 本地持久化（重启后进行中任务和计时恢复）
- 手动开始 / 暂停 / 恢复 / 完成
- 主窗沿用 V0.1 风格（本期不修改主窗内容）

### 2.2 本期不做（推迟到后续版本）

- 平台原生动态材质（V0.2.1）
- 选择已有任务（后续独立重新立项）
- 时间盒 / 番茄钟（V0.2.2）
- 完成通知 toast（V0.2.2）
- 主窗概览页 / 设置页（V0.3+）
- 灵感 / 打卡 / 复盘 / 习惯（V1.0）
- 导出 / 导入 / 云同步 / 多设备 / macOS / 语音输入

## 三、四状态矩阵

浮动窗有四个 UI 状态，由"是否有活动任务"和"折叠/展开"两个维度组合。

| | 折叠态（360×36） | 展开态（360×280） |
|---|---|---|
| **空闲**（无活动任务） | 状态点 + "未命名任务" + 空计时 | 任务输入框 + "开始"按钮 |
| **活动**（有进行中任务） | 状态点 + 任务名 + 计时 | 状态点 + 任务名 + 计时 + 暂停/恢复/完成按钮 |

折叠与展开共用同一个浮动窗，切换只改变高度，宽度始终为 360。

## 四、用户可观察行为

### 4.1 空闲折叠态

**用户看到的**：桌面上一个 36 像素高的横条，左侧灰色状态点，中间显示"未命名任务"，右侧计时显示 `00:00:00`。

**用户能做的**：
- **点击横条** → 展开为空闲展开态（窗口变高，位置不变）
- **拖动横条** → 移动浮窗到屏幕任意位置
- **右键横条** → 弹出系统原生右键菜单

**用户看不到的**：输入框、按钮、第二行内容。

### 4.2 空闲展开态

**用户看到的**：展开的面板，内有一个输入框（占位提示"做什么…"之类）和一个"开始"按钮。

**用户能做的**：
- **输入任务名** → 输入框接受文字
- **点"开始" 或按 Enter** → 创建任务、开始计时、折叠回活动折叠态
- **点面板外 / 按 Esc** → 折叠回空闲折叠态，不创建任务

**约束**：
- 输入为空或全空格时，"开始"按钮不可用
- 全局同时只能有一个进行中任务

### 4.3 活动折叠态

**用户看到的**：桌面上一个 36 像素高的横条，左侧绿色状态点（呼吸动画），中间显示当前任务名（过长截断），右侧显示累计计时（每秒更新）。

**用户能做的**：
- **点击横条** → 展开为活动展开态
- **拖动横条** → 移动浮窗位置
- **右键横条** → 弹出系统原生右键菜单

**用户看不到的**：暂停 / 恢复 / 完成按钮（这些只在展开态出现）。

**反需求**：活动折叠态不允许出现第二行；不允许用视觉隐藏代替物理折叠。

### 4.4 活动展开态

**用户看到的**：展开的面板，上方一行显示状态点、任务名、计时；下方有暂停 / 恢复 / 完成控制按钮。

**用户能做的**：
- **点"暂停"** → 任务变为暂停状态，计时冻结，按钮变为"恢复"
- **点"恢复"** → 任务从暂停恢复为进行中，计时继续
- **点"完成"** → 任务标记为完成，浮窗折叠回空闲折叠态
- **拖动面板** → 移动浮窗位置
- **点面板外 / 按 Esc** → 折叠回活动折叠态（保持活动任务）

## 五、全局行为

### 5.1 不抢焦

浮窗在启动、显示、折叠和展开等非用户主动操作中，不抢占当前应用的输入焦点。用户主动点击输入框后，输入框正常获得焦点。

### 5.2 拖动

- 折叠态：整个横条都可以拖动
- 展开态：面板可以拖动（输入框和按钮区域响应各自的点击，其余区域可拖动）
- 拖动时浮窗跟随鼠标移动

### 5.3 默认位置

浮窗启动时出现在主屏右上角附近。用户拖动过的位置在重启后保持。

### 5.4 右键菜单

右键浮窗弹出系统原生菜单，包含退出应用等选项。不用 HTML 模拟菜单。

### 5.5 全局快捷键

- `Ctrl+Shift+Space`：唤起 / 隐藏浮窗
- 快捷键被其他程序占用时，启动时提示用户

### 5.6 窗口关系

- 关闭主窗 → 主窗隐藏，浮窗继续运行，应用继续驻留
- 浮窗右键菜单中的"退出"是正常退出入口
- 启动时主窗 + 浮窗都显示

### 5.7 持久化

- 所有任务和计时记录存在本地
- 重启后进行中任务的计时从最后记录时刻继续（用户看到的数值和离开时一致）
- 记录永久保留，只增不减

## 六、反需求

以下行为明确禁止，出现即为 bug：

- 折叠态出现第二行内容（36px 必须只能容下一行）
- 仅在界面中隐藏内容、但窗口实际高度不变（窗口物理尺寸必须变化）
- 浮窗在非用户主动操作中抢走键盘输入焦点
- 用浮窗内部元素模拟右键菜单（必须是系统原生菜单）
- 展开态宽度变化（宽度恒为 360，只改变高度）
- 全局同时存在两个进行中任务

## 七、非功能需求

| 类型 | 要求 |
|---|---|
| 性能 | 启动到浮窗显示 ≤ 2 秒 |
| 性能 | 计时器更新不卡 UI（≤ 1ms/秒） |
| 兼容 | Windows 11 24H2 x64（本期唯一平台） |
| 数据 | 永久本地存储，不上传任何数据 |
| 视觉验收 | 在 Windows 11 WebView2 实机上通过（含 100% / 125% / 150% DPI） |

---

## 八、术语

| 术语 | 定义 |
|---|---|
| 浮动窗 | 常驻桌面的小窗口，显示"正在做什么 + 花了多久" |
| 折叠态 | 360×36，单行显示状态点 + 任务名 + 计时 |
| 展开态 | 360×280，显示输入框和控制按钮 |
| 空闲态 | 没有进行中的任务 |
| 活动态 | 有一个进行中的任务（全局唯一） |
| 进行中 | 任务正在计时的状态 |
| 暂停 | 任务计时暂时冻结 |
| 已完成 | 任务已结束，记录不再变化 |
| 不抢焦 | 启动、显示和状态切换不抢占其他应用的输入焦点；用户主动点击输入框除外 |
| 单人本地 | 单用户使用，数据存本地电脑 |
