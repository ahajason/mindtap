## 一、背景与目标

### 1.1 项目背景

V0.2.0 实现了浮动窗最小可用,但**每次开始新任务都得手动输入完整任务名**。当用户一天中重复做同一件事(写代码、查资料、回邮件)时,反复输入相同任务名是浪费。

需要一个"从历史任务里挑"的入口。

### 1.2 项目目标

| 指标 | 目标 |
|---|---|
| 切换到已有任务的操作步数 | ≤ 2 步(展开 + 点选) |
| 历史列表覆盖 | 用户最近 5 个不同的任务名(末次使用倒序) |

### 1.3 核心用户

同 V0.2.0(单人本地 Windows 11 用户)。

## 二、需求概述

### 2.1 需求范围

**本期做**:
- 展开态新增"选择已有任务"入口
- 从已完成的历史记录里挑出最近 5 个不同的任务名
- 选中后创建新记录复用该任务名
- 首次 / 0 条已完成时的引导气泡

**本期不做**(同 V0.2.0 +):
- 时间盒 / 番茄钟(V0.2.2)
- 完成通知 toast(V0.2.2)
- 主窗 / 概览页(V0.3+)

### 2.2 功能清单

| # | 功能模块 | 功能点 | 优先级 | 说明 |
|---|---|---|---|---|
| 1 | 展开态 | "选择已有任务"入口(折叠在展开态内) | P0 | 仅在"无进行中"时显示 |
| 2 | 历史列表 | 最多 5 个不同任务名(末次完成倒序) | P0 | |
| 3 | 历史列表 | 列表项不截断,内部滚动 | P0 | 长任务名支持 |
| 4 | 选中行为 | 选中后输入框显示完整任务名 | P0 | 可二次编辑 |
| 5 | 选中行为 | 按 Enter / 开始 → 创建新记录 | P0 | 不复用旧记录 |
| 6 | 空状态 | 0 条已完成时显示引导气泡 | P0 | 引导用户先新建 |
| 7 | 状态机 | 完整 3 态(进行中 / 暂停 / 已完成) | P0 | V0.2.1 不引入第 4 态 |

## 三、功能详细设计

### 3.1 选择已有任务入口

**功能描述**:V0.2.1 在展开态新增"或选择已有任务"折叠区段。

**用户场景**:
- Alice 上午 10:00 写代码 → 完成 → 11:00 又要写代码 → 展开浮窗 → 点"或选择已有任务" → 看到"写代码" → 选中 → 输入框显示 → Enter → 新进行中

**业务规则**:
- 仅在**无进行中任务**时显示(已有进行中时隐藏)
- 折叠态不变(折叠态不显示这个入口)
- 数据源:已完成的历史记录里挑出最近 5 个不同的任务名(末次完成倒序)

**异常处理**:
- (本期不涉及)

### 3.2 历史列表展示

**功能描述**:列表项显示完整任务名,内部滚动。

**业务规则**:
- 列表项任务名**不截断**(显示完整字符串)
- 列表内**支持滚动**(内部 `overflow-y`)
- 任务名上限仍是 50 字符(同 V0.2.0)

**异常处理**:
- 0 条已完成 → 改显示引导气泡(见 §3.4),不显示列表

### 3.3 选中行为

**功能描述**:选中列表项后创建新记录复用任务名。

**业务规则**:
- 选中 → 输入框显示完整任务名(**可二次编辑**)
- 用户按 Enter / 点"开始" → 创建**新**记录(任务名 = 该值,初始状态 = 进行中,计时从 0 起算)
- **不**复用旧记录(避免历史被覆盖)

**异常处理**:
- 选中后用户改任务名 → 按 Enter 时按改名后的任务名创建(走 §3.2 V0.2.0 输入路径)

### 3.4 引导气泡(空状态)

**功能描述**:首次启动 / 0 条已完成时,引导用户先新建。

**业务规则**:
- 列表区域**不显示**折叠按钮
- 改显示引导气泡文案:**"👋 还没有历史任务,先新建一个试试?"**(具体文案待 V0.2.1 UX grill 定稿)
- 引导气泡可点击 → 焦点跳到输入框
- **仅首次**(空状态)显示,有 1 条已完成后即换为"选择已有任务"入口

**异常处理**:
- (本期不涉及)

### 3.5 状态机完整性

**功能描述**:V0.2.1 完整化 3 态状态机。

**业务规则**:
- V0.2.1 **沿用** V0.2.0 3 态(进行中 / 暂停 / 已完成)
- **不**新增第 4 态(如"暂存")
- 选中已有任务只改前端 UI,**按 Enter 才落库**——数据库永远不出现"半提交"行

**异常处理**:
- (同 V0.2.0 §3.3 异常处理)
