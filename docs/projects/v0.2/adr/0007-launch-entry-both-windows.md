# 0007 — 启动入口：都显示（主窗 + 浮窗同时启动）

**Status**: accepted · 2026-07-11 · V0.2 立项
**引用警告**: 本 ADR 锁定 V0.2 启动行为；V0.2 主窗**内容**待 V0.2 spec 阶段 grill

V0.2 启动时**同时**显示主窗和浮窗。不做"仅浮窗"或"仅主窗"。

## 候选方案

| 选项 | 启动行为 |
|---|---|
| A 仅浮窗 | 用户首启看不到主窗（settings / 关于不可达）|
| B 仅主窗 | 浮动窗入口丢失，违背 V0.2 核心交互 |
| **C** ✅ 都显示 | 主窗 + 浮窗同时开 |

## 为什么选 C

- 浮窗是 V0.2 核心入口（折叠 + 计时）—— 不能丢（用户决策）。
- 主窗是后续版本（V0.3+）设置/时间线/复盘的承载页——**首启就要占位**（推断：避免 V0.3 时改启动行为造成 backward compat 问题，但 V0.2.0 是 V0.2.x 第一个版本，**没有"已发布用户"**，backward compat 担忧不成立）。**是否占位待 V0.2 spec 阶段 grill**。
- V0.2 主窗 V0.2 阶段是"占位 + 设置入口（少量项目）"——**具体内容待 V0.2 spec 阶段 grill**。

## 后果（候选，待 V0.2 spec 确认）

- **+** V0.2 用户首启同时看到浮窗 + 主窗占位。
- **−** Windows 11 任务栏占两个口（任务栏合并视图下可能合并为一个，需 dev 实测）。
- **−** V0.2 主窗内容未定——**V0.2 spec 阶段须 grill**：是空壳页 / 还是"关于"页 / 还是简易设置 / 还是 onboarding？

## V0.2 spec 阶段必 grill

- 主窗 V0.2.0 范围具体内容（候选：①空壳 ②关于页 ③简易设置 ④ onboarding）
- 双窗口 IPC 同步策略（主窗是否监听 `timer_session::updated` 事件以显示"当前正在做 X"）
- 关闭主窗 / 关闭浮窗 / 关闭应用 三者关系（关主窗是否关浮窗？关浮窗是否关主窗？）

## V0.2 spec v1.1 补充 (2026-07-11)

### 主窗内容锁定

**V0.2.0 主窗 = 沿用 V0.1.6 Style Guide**（用户决策 spec v1.1 grill 9.8 = E "现有出口"）。

- V0.2 实施时**不修改** `src/App.tsx` / `src/routes/` 任何组件
- 主窗 webview = 当前 V0.1.6 react-router-dom 7 路由（Overview / Surface / Button / Input / Feedback / Overlay / Tokens）
- V0.2 spec 阶段早期候选 (空壳 / 关于 / 设置 / onboarding) **全部作废**，按用户 "现有出口" 决策执行

### 关窗关系锁定

**关主窗 = 隐藏主窗（不退出应用）**；**浮窗右键菜单 → 退出 = 正退出**（用户决策）。

V0.2 浮窗展开态须加**右键菜单**作为唯一正退出入口，包含 "退出" 项。

### IPC 同步锁定

**主窗静态（不订阅 `timer_session::updated` 事件）**（spec v1.1 grill 9.9 IPC = B）。

理由：主窗 = Style Guide（与 timer_session 无关），订阅 timer_session 事件无意义。浮窗是唯一与 timer_session 交互的 webview。
