## 一、产品定位

### 1.1 一句话定位

一款常驻桌面的**个人工作台账**：随时低成本记下任务，多线并行推进，忘记有兜底，随时看得见"我的工作进行到哪了"。

### 1.2 产品基因（继承自"闪念"，不可妥协）

四条顶层准则贯穿所有功能：

1. **3 秒记录**——从触发到保存 ≤3 秒、≤3 次点击；
2. **1 秒查看**——关键信息一眼定位，无干扰元素；
3. **0 思考成本**——录入时无分类、无标题、无格式决策；
4. **全量本地存储**——无登录、无云端、无上传，数据完全属于用户。

### 1.3 解决的核心问题

知识工作者（程序员、设计师）的真实工作状态是**多线并行**：多个窗口、多个 AI Agent、多件事同时推进，注意力高频切换。痛点分三层加一个元痛点：

| 痛点 | 描述 |
|---|---|
| **念头留不住** | 想到的事没立刻记下，转头就忘 |
| **现场找不回** | 切走半小时再回来，想不起上次做到哪 |
| **全局看不见** | 一天下来不知道推进了什么、晾着什么、时间花在哪 |
| **元痛点：漏记** | 忘了记、忘了停，台账与现实脱节——以上三层全部失效。这是本产品必须解决的第一优先级问题 |

生活侧痛点（闪念原始洞察，保留）：灵感、收支、物品位置等信息转瞬即逝，传统工具打开慢、录入流程长、决策成本高，导致"记录惰性"，难以坚持。

### 1.4 设计原则

1. **记录优先于整理**——记下来零成本，整理稍后批量做；
2. **本地优先**——无账号、无云端，被动采集的数据也只存本地、永不上传；
3. **不无故打扰**——平时静默，不弹通知、不抢焦点；但"漏记"是唯一允许提高打扰级别的理由，打扰强度与漏记确定性匹配（见第四章）。**当"不打扰"与"台账可信"冲突时，台账可信优先**。

### 1.5 明确不做（护栏）

- 不做番茄钟 / 倒计时 / 专注训练（计时只为"看见投入"）
- 不做云同步、账号体系、团队协作、社交分享
- 不做项目管理（子任务、依赖、甘特图、看板泳道）
- 不做效率打分、应用使用评分、网站分类报表（不做人身监控）
- 不做复杂报表与数据可视化（汇总只出数字，不出图表）
- 不做会员体系与任何商业变现功能
- 不做移动端（旧移动端需求仅作存量记录，桌面化后再评估）

## 二、目标用户与核心场景

**用户**：个人桌面知识工作者（点子多、任务多、切换频繁），Windows 与 macOS 双端体验一致。

| # | 场景 | 描述 |
|---|---|---|
| **S1** | 灵光一现 | 想到一件事 → 快捷键唤起 → 输入 → 回车 → 继续干活。≤3 秒，手不离键盘 |
| **S2** | 多线并行推进 | 同时推进 3~5 个任务（写代码、等 Agent 跑、改方案），浮窗上每张卡实时显示各自累计投入时长 |
| **S3** | 切换找回现场 | 切回一个半小时前放下的任务，看卡片上的进度备注（"接口写完，差联调"），立刻接上 |
| **S4** | 每日整理（约 2 分钟） | 收件箱逐条裁决：转待办 / 仅留档 / 删除 |
| **S5** | 下班前复盘（约 2 分钟） | 一屏回答：今天推进了什么、各投入多久、哪些晾着、哪些未闭合；未闭合任务逐条做决定 |
| **S6** | 漏记自愈 | 忘了记/忘了停时：系统自动暂停、按信号强度分级提醒、复盘时列出未覆盖时段——台账不用人盯着也能保持可信 |
| **S7** | 生活速记 | 灵感、收支、物品位置等生活信息，3 秒内随手记下（远期） |

> **S1~S6 是生死场景**，一切设计为它们让路；S7 是产品基因的自然延伸。

## 三、业务模型

### 3.1 统一实体：Item（一条记录）

产品内所有记录是同一个实体，用 type 区分两族：

- **任务族（type = task）**：工作台账核心，有状态机、计时、并行推进；
- **速记族（type = 灵感/收支/运动/学习/人脉/手账/物品/复盘）**：生活记录，无状态流转，只留存"内容 + 模块类型 + 时间戳"（远期建设，见路线图阶段三）。

| 字段 | 说明 | 适用族 |
|---|---|---|
| `id` / `created_at` / `updated_at` | 标识与时间戳 | 全部 |
| `content` | 内容，≤200 字 | 全部 |
| `type` | 记录类型 | 全部 |
| `status` | 见 3.2 状态机 | 任务族 |
| `focus_ms` | 累计投入时长（自动累计） | 任务族 |
| `last_active_at` | 最近活跃时间（开始/暂停/备注/完成均刷新） | 任务族 |
| `progress_note` | 进度备注："我做到哪了"，≤100 字，可空 | 任务族 |
| `source` | 来源：`manual` / `suggested` / `hook` | 任务族 |
| `payload` | 速记族结构化数据（金额、体重、进度档等），JSON | 速记族 |
| `tag` | 预留字段 | 全部 |

**关键决策**：
- 想法与待办是同一实体，区别只在状态；生活记录与工作待办也是同一实体，区别只在 type。**全产品只有一张表、一套存储、一个列表入口**，业务上不存在第二套体系；
- **"需要关注"不是状态，是从 `last_active_at` 派生的展示维度**（见 3.3），状态机保持五态、简单可维护。

### 3.2 任务族状态机（五态，支持多并行）

```
            ┌──── 捕获 ────┐
            ▼              │
        【收件箱】──转待办──►【待办】──开始──►【进行中】◄──┐
            │  ▲             ▲        │        │ 暂停/挂起 │
            │仅留档           └────────┴──完成──▼【完成】   │
            ▼                                  │ 次日自动 │
        【归档】◄────────────────────────────────┘         │
            │                                              │
            └──重新激活──► 待办          恢复 ──────────────┘

任意状态 ──► 删除（5 秒内可撤销）
```

**流转规则**：
1. 捕获一律进收件箱，无任何前置选择；
2. **进行中数量不限**，但超过 5 个时浮窗轻提示"在推进的事有点多"（WIP 软上限，提示而非禁止）；
3. 任务间切换零成本：在另一张卡上点"开始"即可，上一个的计时自动暂停；
4. 完成条目保留在"今日完成"，次日自动归档；归档只读，可重新激活；
5. **暂停不占状态位**——"暂停/挂起"即退回待办，从待办重新点"开始"继续计时。状态机保持五态，无独立暂停态；
6. **进行中不跨天**——跨天遗留的"进行中"任务启动时自动退回待办并停表，时长不膨胀；
7. **重复捕获不自动合并**——同名任务可并存，系统只轻提示，不擅自合并计时或内容（判断交还用户）。

### 3.3 注意力维度（派生展示规则，非状态）

**"进行中"（active）的语义**：不是"被启动"的开关，而是**"正在被投入"**——这张卡此刻真实占有用户的时间投入。计时只是度量投入的手段，不是投入本身。因此"进行中"天然带"当下"边界：不跨天，切走/空闲/锁屏即停止。

仅对"进行中"任务生效，按 `last_active_at` 自动变化：

| 维度 | 规则 | 表现 |
|---|---|---|
| **活跃** | 2 小时内有动作 | 正常显示，计时滚动 |
| **冷却** | 2~24 小时没碰 | **失真信号**：触发确认气泡（见 4.2），不再以卡片变暗呈现 |
| **晾着** | 超过 24 小时没碰 | **失真信号**：触发确认气泡（见 4.2），复盘视图中单独列出提示做决定 |

> 冷却/晾着是"进行中"的**真实性衰减**（active 已失真、计时还在跑），不是独立状态。系统不静默变暗，而是主动询问（见 4.2 失真确认闭环），把"这段投入要不要计入"的判定权交还用户。

接入 Claude Code hooks（阶段三）后，该维度增加事件驱动来源（Agent 等待输入时直接标记"等待你处理"），从时间推断升级为真实信号。

### 3.4 业务不变量

1. 捕获无门槛：内容非空即可保存；
2. 计时自动：点"开始"即累计，暂停/切走/空闲/锁屏即停止，**不需要用户维护计时的正确性**；
3. 归档/完成内容只读，只可重新激活；
4. 数据永存本地，不自动清理；删除必须用户主动且可撤销；
5. 整理动作只做判断、不做创作；
6. **未经确认的被动活动数据（窗口标题、时间线）永远只是建议，用户确认后才进台账**；用户主动配置的事件源（hooks）视为授权，可直接驱动。

## 四、防漏记体系（元痛点专项，产品第一优先级）

### 4.1 四层防线

| 层 | 机制 | 治什么 |
|---|---|---|
| L1 | 捕获 ≤2 步 | 降低漏记发生概率 |
| L2 | 信号自动感知 | 系统发现"你在干活但台账没动" |
| L3 | 分级提醒 + 一键确认 | 把建议递到眼前，一次点击转正 |
| L4 | 事后兜底 | 复盘时列出未覆盖时段，一键关联任务 |

### 4.2 信号分级与打扰策略

**核心依据**：漏记发生的那一刻，用户恰恰没有在看浮窗。纯静默提示在最需要它的时刻必然失效。因此提醒按漏记确定性分级，不抢键盘焦点，但要进入眼角余光：

| 信号 | 漏记确定性 | 打扰级别 | 处理方式 |
|---|---|---|---|
| Claude Code hooks 事件 | 高 | 无需打扰 | 直接自动开始/暂停/标记"等待你处理"（用户配置即授权） |
| 计时在跑 + 人离开（空闲超时） | 高 | **系统通知**（可关） | 自动暂停计时 → 通知"XX 已自动暂停" → 回来后一键确认是否计入 |
| 前台窗口明显切换且计时未动（持续 10 分钟） | 中 | **浮窗视觉强化**（呼吸/变色，眼角可见，不抢焦点）+ 可选系统通知 | 一键确认建卡 / 忽略 |
| 键鼠空闲 | 低 | 无 | 自动暂停（不提示） |

### 4.2a 失真确认闭环（"进行中"任务失真的统一处理）

"进行中"任务一旦失真（冷却/晾着），统一走同一套主动询问闭环，不再静默变暗：

```
检测到"进行中"任务失真（冷却阈值 2 小时无更新 / 跨天）
  → 弹出独立确认气泡（不抢焦点）：
       「写代码 还在进行中，还要继续吗？」[继续] [暂停]
  → 用户 5 秒内无操作（可能忘了 / 可能还在专注）
       → 自动暂停退回待办，计时只停不抹
       → 失真窗口（失真点 → 暂停点）标记为"待确认"
  → 用户回来 → 看到「刚才这 X 时间要计入吗？」[记入] [丢弃]
       [记入] → 结算进累计投入
       [丢弃] → 丢弃该窗口，投入不变
  → 跨天无人回应 → 跨天兜底退回待办，防膨胀
```

**三条原则**：
1. **超时暂停 ≠ 抹除投入**：计时只停止继续累计，已累计的投入只增不减；失真窗口是"待确认"，不预先吃时间也不预先丢时间；
2. **判定权在用户**：那段失真窗口到底算不算投入，由用户回来一键决定（记入/丢弃），系统不武断替用户判定；
3. **跨天兜底**：active 不跨天，气泡无人回应时靠跨天检测退回待办，防时长膨胀。

### 4.3 三条铁律

1. 被动活动数据只存本地、永不上传、仅本人复盘可见；
2. 未经确认的被动数据永远只是建议，用户确认才进正式台账；
3. **打扰分级制**：默认形态是浮窗视觉强化（常驻置顶、眼角可见、不抢键盘焦点）；仅高确定性漏记允许系统通知；每类信号的打扰级别用户可逐条配置，也可全局关闭。

### 4.4 Claude Code hooks 事件映射（阶段三）

| hooks 事件 | 映射动作 |
|---|---|
| `SessionStart` | 自动开始对应项目的任务卡计时（无卡则建议创建） |
| `Stop` / `TeammateIdle` | 自动暂停该卡计时，标记"等待你处理" |
| `Notification` | 标记"等待你输入" |
| `TaskCompleted` | 建议将该卡标记完成（一键确认） |

价值：多 Agent 并行时，"哪个 Agent 在等我"由真实事件驱动，不再靠冷却时间猜测。

## 五、功能开发路线图

### 现状盘点（已实现存量）

桌面浮窗（折叠/展开/暂停/完成）、任务名历史复用、原生右键菜单、全局快捷键、开机自启、SQLite 持久化、双窗架构、玻璃设计系统。**注意：计时 session 雏形存在，但业务核心需按本文档重构为"任务族 Item + 状态机"，原计时逻辑从主流程移除或改造复用。**

**激活时间段留痕**：每次"开始"的投入时间段（开始时刻 → 结束时刻）都必须被详细记录、不丢失；累计投入时长是从这些明细可重算的缓存。这是后续"并行时间统计 / 合并 / 跨天切片"业务的计算基础（多 active 并行场景下，同一时段可能有多个任务同时在投入，需要能按任务、按日聚合）。

---

### 阶段一：工作台账核心（生死场景 S1~S4，最高优先级，详细描述）

#### 任务 1.1 全局快捷键捕获

**根本原因**：念头留不住是记录工具的第一死因。闪念时期的结论至今成立——记录流程每多一步、每多一秒，放弃率就翻一倍；用户不是在"决定记不记"，而是在"念头消失的 3 秒窗口内"和工具赛跑。任何前置选择（分类、标题、项目归属）都是在消耗这个窗口。因此捕获必须做到肌肉记忆级：一个快捷键、一个输入框、一次回车。

**制作过程**：
- 任意应用内按下全局快捷键 → 浮窗展开并聚焦输入框（不抢原窗口焦点状态，仅临时获得输入权）；
- 输入内容 → 回车 → 保存进收件箱、浮窗自动收起、**焦点归还原窗口**，用户接着打字无感知；
- 空内容不保存；Esc 取消；输入框无 placeholder 文案、无模板、无历史下拉（历史复用已有存量，保留在浮窗展开态）；
- 快捷键遵循平台习惯且可自定义，避免与 IDE 高频快捷键冲突。

**验收**：任意应用内唤起 → 输入 → 回车全程 ≤3 秒；焦点回到原窗口；连续捕获 10 条无一次打断当前输入流。

#### 任务 1.2 常驻浮窗·并行任务条

**根本原因**：用户的问题不是"没有任务列表"，而是"列表在另一个窗口里，切过去看本身就打断工作"。多窗口、多 Agent 并行的真实场景下，需要一个**始终处于视野边缘、不抢注意力但随时可读**的载体。浮窗是唯一答案——它是"记录 + 推进 + 找回现场"的统一入口，90% 的使用发生在这里。同时它是防漏记提醒的载体（视觉强化依赖常驻置顶）。

**制作过程**：
- 折叠态：单行条，**滚动展示进行中任务卡**（内容 + 累计投入实时滚动，每 2-3 秒轮换一张；「+N」指示其余并行卡），存在感最低；无进行中时显示收件箱未整理数 + 捕获入口；
- 折叠条右侧捕获入口（「+」）：点击直达新增面板（不嵌套在列表内）；
- 展开态：显示全部进行中任务卡，每张卡四要素——**内容、累计投入时长（实时滚动）、冷却状态（颜色深浅）、进度备注（直接显示，不需点开）**；
- 支持拖动调整位置、位置记忆、置顶显示；右键原生菜单（已有存量）；
- 视觉延续玻璃设计系统（已有存量），但冷却/晾着状态用透明度与颜色表达，不增加新控件。

**验收**：5 个并行任务同时计时，浮窗显示各自时长与冷却状态互不干扰；折叠态滚动展示所有进行中卡，每张内容 + 时长可见；切到任何全屏应用，浮窗仍置顶可见。

#### 任务 1.3 收件箱与待办清单（状态流转落地）

**根本原因**：捕获零成本的代价是收件箱必然堆积，如果整理成本高，收件箱会变成第二个焦虑源，用户连捕获都会放弃。闪念时期的教训是"重记录轻查看"，但工作台账的查看不是浏览而是**裁决**——每条记录必须在一次点击内决定去留，否则整理这个动作本身就无法坚持。同时，"全局唯一进行中"已被证伪：真实工作是多线并行，状态机必须支持多个进行中，否则用户为了迁就工具会放弃记录真实状态。

**制作过程**：
- 收件箱列表：按时间倒序，每条三个动作按钮——**转待办 / 仅留档（归档）/ 删除**，一次点击生效，无二次确认（删除除外，5 秒可撤销）；
- 待办清单：每条支持"开始"（进入进行中并行区）；"进行中"卡片支持暂停（退回待办）、完成；
- 超过 5 个进行中时浮窗轻提示文案，不阻止操作；
- 完成条目进入"今日完成"区，次日自动归档；归档可在主窗查看、可重新激活。

**验收**：整理 20 条收件箱 ≤2 分钟；任务 A 计时中点任务 B 的"开始"，A 自动暂停、B 开始计时，一步完成。

#### 任务 1.4 自动计时与空闲保护

**根本原因**：计时的价值不是自律，是回答"我这个任务进行到哪了、花了多久"。但手动维护计时必然失真——人一定会忘了停、忘了开，这正是元痛点。所以计时必须**不需要用户维护正确性**：点开始即跑，切走即停，人离开即停，回来一键确认。Toggl 的空闲检测、RescueTime 的键鼠监控都已验证这条路线成熟可靠。

**制作过程**：
- 点"开始"即对该任务累计 focus_ms，每秒精度即可，低频写库；
- 同一时刻多张卡可并行计时（多 Agent 场景：人在写码、Agent 在跑，两张卡都在投入）；
- 键鼠无操作超过阈值（默认 10 分钟）→ 自动暂停 → **系统通知"XX 已自动暂停"**（防漏记高确定性信号，可关）→ 回来后浮窗一键确认：计入 / 不计入；
- 休眠、锁屏自动暂停，唤醒后时长不膨胀；
- 跨天任务计时按自然日切片，供复盘视图按日统计。

**验收**：无操作 10 分钟后计时自动暂停并收到通知；锁屏 1 小时后恢复，时长不凭空膨胀；强制结束进程后重启，状态与累计时长无损。

### 阶段二：可信台账与复盘（场景 S5、S6，中等详细）

#### 任务 2.1 每日复盘视图（含未覆盖时段兜底）

**根本原因**：记录不是终点，"看见自己的工作情况"才是。Sunsama 的晚间仪式验证过：未闭合的任务会持续制造认知张力（蔡格尼克效应），必须逐条做决定，不允许有"没人管的孤儿任务"。同时它是防漏记的最后一道防线——前三道防线都没接住的漏记，在这里被翻出来。

**制作过程**：
- 主窗复盘页一屏四块：今日完成清单（含各任务投入时长）、时间分布（按任务的数字汇总，无图表）、晾着的任务（>24h 未动）、**未覆盖时段**（被动时间线中没有任务覆盖的活动时段，列出供一键关联任务或忽略）；
- 未闭合任务逐条操作：顺延 / 完成 / 删除；
- 打开即读，不需要任何操作；处理动作一次点击。

**验收**：复盘全流程 ≤2 分钟；未覆盖时段一键关联后，该时长时间计入对应任务。

#### 任务 2.2 活动信号与智能提示

**根本原因**：防漏记 L2/L3 层。靠自觉永远解决不了漏记，必须让系统发现"你在干活但台账没动"。但提示力度必须克制且分级——纯静默 badge 在漏记时刻必然失效（用户没在看浮窗），弹窗轰炸又会毁掉信任。浮窗视觉强化（呼吸/变色）是平衡点：不抢键盘焦点，但进入眼角余光。

**制作过程**：
- 监听前台应用切换（系统标准 API）；检测到明显工作切换且持续 10 分钟、计时未动 → 浮窗进入视觉强化状态并显示建议"看起来你在做 X，要记一下吗？"；
- 一键确认（建卡并开始计时）/ 一键忽略；同一信号反复被忽略 → 降频但汇入复盘批量处理，**不静默消失**；
- 首次启动明确告知监听行为；每类信号打扰级别可逐条配置（静默/视觉强化/系统通知）；可全局关闭，关闭后完全不监听。

**验收**：前台应用持续切换 10 分钟且计时未动时浮窗视觉强化并出现建议；一键确认即建卡计时；关闭开关后无任何监听行为。

#### 任务 2.3 主窗管理、托盘与数据底线

**根本原因**：浮窗解决"快"，主窗解决"全"。误删、改名、搜索是数据可控的底线，成本极低但缺失会让用户"怕输错"而不敢记。

**制作过程**：主窗承载全部条目列表（搜索、按状态/type 筛选、编辑内容）；托盘/菜单栏入口 + 开机自启（已有存量）；删除 5 秒撤销。

### 阶段三：能力扩展（远期；细节已完整定义，启动顺序届时评估）

#### 任务 3.1 Claude Code hooks 事件集成

**根本原因**：多 Agent 并行时"哪个 Agent 在等我"是最易漏的信息；hooks 是真实事件而非时间猜测，是质量最高的信号源，能让注意力维度从推断升级为事实。

**制作过程**：
- 用户在 Claude Code 的 `settings.json` 中配置 hook，通过 http/command 将事件 JSON 上报到轻念本地接口，配置即视为授权（见 3.4 不变量 6）；
- 按 4.4 映射表驱动任务卡：SessionStart 自动开始计时（无卡则建议创建）、Stop/TeammateIdle 自动暂停并标记"等待你处理"、Notification 标记"等待你输入"、TaskCompleted 建议完成；
- hook 来源的任务卡在浮窗上带来源标识（source=hook），与手动卡视觉可区分；
- 上报失败静默丢弃，不重试不报错，不影响 Claude Code 自身运行。

#### 任务 3.2 生活记录模块族（闪念八模块桌面化）

**根本原因**：产品基因的另一半——生活信息（灵感、收支、物品位置、保质期）同样转瞬即逝，传统工具打开慢、录入流程长、决策成本高，导致"记录惰性"。闪念时期的全部设计要点在此完整保留，仅将移动端交互翻译为桌面形态：录入载体为主窗速记面板或浮窗快捷入口，"点系统返回键自动保存"翻译为"回车 / Esc / 点击空白处自动保存"，"唤起数字键盘"翻译为"数字输入框自动聚焦"，"拍照"翻译为"选择图片 / 截图识别"。八模块共用规则：**录入面板无保存按钮、无标题、无分类决策，全部自动保存并自动打秒级时间戳；语音转文字按钮固定在录入区，按住录音、松开转文字、实时显示**。

##### 3.2.1 灵感速记（含创意、梦境）

**根本原因**：灵感、梦境转瞬即逝，复杂工具多步录入来不及留存；被迫思考分类、标题、格式反而打断创意本身。

**操作逻辑**：主窗速记区点击"灵感速记"（或全局快捷键唤起时指定模块）→ 全屏录入面板自动聚焦输入框 → 文字/语音输入 → Esc/回车自动保存。

**设计要点**：仅一个空白输入框，无标题、无分类、无排版、无字数统计；语音转文字实时显示，无识别 loading 动画；全程 ≤3 次点击。

##### 3.2.2 收支速记

**根本原因**：日常收支金额小、频次高，专业记账工具要选类型、写备注、选账户，流程太重难以坚持；用户只需留存金额，不需要复杂统计分析。

**操作逻辑**：进入录入面板 → 数字输入框自动聚焦（默认显示 0.00，输入自动覆盖，支持小数点后两位）→ 输入金额后点击"收入"/"支出"任一按钮 → 自动保存。

**设计要点**：仅保留"金额 + 分类 + 时间戳"，无备注、无二级分类、无账户选择；收入/支出按钮高对比度、大尺寸，固定在输入区下方；无确认键、无重置键。

##### 3.2.3 身体运动（体重 + 运动数据）

**根本原因**：健身减重用户只需快速留存体重与运动时长，专业运动 APP 要连设备、设目标，流程繁琐；后期分析需求远低于记录需求。

**操作逻辑**：面板上方体重录入框（默认单位 kg，输入后回车即存）；面板下方运动预设标签 4 个（跑步/健身/散步/其他）+ 时长快捷按钮 4 档（10/20/30/60 分钟），点击"标签 + 时长"组合自动保存。

**设计要点**：运动记录仅保留"类型 + 时长 + 时间戳"，体重仅保留"体重 + 时间戳"；不支持自定义类型、不支持手输时长，只给预设以减少决策；按钮宫格布局、可点区域足够大；无消耗计算、无统计。

##### 3.2.4 学习项目（学习/项目进度）

**根本原因**：传统工具要建任务、设截止、拆子任务，成本过高；用户只需快速留存"大致进度"供回溯；复杂的进度管理反而降低更新意愿。

**操作逻辑**：名称输入框（可空，空则存为"未命名项目"）+ 固定五档进度条（0%/25%/50%/75%/100%），滑动到节点自动保存。

**设计要点**：仅保留"名称 + 进度 + 时间戳"，无任务分解、无截止时间、无备注；进度条只能停在预设节点，不可自由拖动；节点用颜色区分，不显示百分比数字。

##### 3.2.5 人脉维护

**根本原因**：人脉互动细节事后易忘，需在互动结束后 30 秒内留存；专业人脉工具字段多、门槛高。

**操作逻辑**：联系人名称输入框 + 高频联系人快捷按钮（自动同步最近录入的 3 个，不可手动增删）→ 场景标签单选 4 个（工作会议/朋友聚会/行业活动/线上交流，未选自动标记"未分类"）→ 可选语音录入/图片选择 → 自动保存。

**设计要点**：仅保留"联系人 + 场景标签 + 语音/图片文件 + 时间戳"，无联系方式、无分组、无生日字段；所有字段非必填，只填名称也可保存；语音/图片本地相对路径存储，不压缩、不上传。

##### 3.2.6 手账日记

**根本原因**：记录生活只为留存回忆，传统手账的模板、排版、滤镜是负担；编辑页干扰元素破坏专注。

**操作逻辑**：全屏纯文字编辑面板，自动聚焦，支持换行分段、无字数限制，Esc/点击空白自动保存。

**设计要点**：仅保留"内容 + 时间戳"，无标题、无天气、无心情标签；不支持图片插入、排版、表情，仅纯文字；面板无多余 UI 元素。

##### 3.2.7 物品管理

**根本原因**：整理时易忘物品存放位置，事后翻找浪费时间；只需留存"名称 + 位置"对应关系，不需要库存管理。

**操作逻辑**：物品名称输入框 + 存放位置输入框上下排列，名称回车自动跳到位置框，输入完成后 Esc/点击空白自动保存。

**设计要点**：仅保留"名称 + 位置 + 时间戳"，无分类、无购买信息；不支持条码扫描，仅手动录入；无保存/重置按钮。

##### 3.2.8 每日复盘（生活侧）

**根本原因**：复盘只需提炼 3~5 个关键结论，传统复盘模板、长文分析让人抵触，无法坚持。

**操作逻辑**：固定 3 个单行输入框，提示"输入当日关键词/核心总结"，支持语音转文字，输入完成自动保存并关联当日记录。

**设计要点**：输入框固定 3 个，不可增删调序；每个 ≤20 字，超出自动截断、无字数统计显示；无复盘标题、无分析结论。

##### 3.2.9 模块族增强项

- **自定义预设模板**：收支可添加 3 个常用金额快捷按钮，点击直填；运动可自定义 3 个常用类型标签，并记忆上次使用的时长；人脉高频联系人快捷按钮可扩充至最多 5 个。设置入口在对应录入面板，设置过程 ≤3 次点击。
- **记录关联**：手账录入面板新增"关联当日记录"按钮（仅当日有其他记录时显示），一键将当日任意 1 条记录以引用形式插入内容末尾，引用不可编辑、不可删除。
- **输入偏好**：灵感/手账可设置默认唤起语音或文字输入；可设置默认录音时长，最长 60 秒。入口在全局设置页。
- **模块入口自定义**：主窗速记区 8 个入口支持拖拽调序；可隐藏不常用入口，最多隐藏 3 个，可随时恢复。
- **规则微调**：学习项目进度可新增 30%/60%/80% 三个常用节点；复盘关键词可从 3 个放宽至最多 5 个；体重单位可在 kg/斤间切换。入口在对应录入面板，调整 ≤3 次点击。
- **分类筛选**：全局记录列表支持按 8 大模块、近 7 天/30 天筛选，可多选模块；结果仍按时间倒序，无额外排序。
- **极简数据汇总**：只出数字、不出图表——收支：当月收入/支出总额；运动：当月总时长、当月体重变化；学习：所有项目平均进度、当月更新次数；人脉：当月互动联系人数、高频互动联系人。
- **人脉升级**：新增"核心交集"可选字段（共同兴趣/朋友/合作项目，≤20 字，放在场景标签下方，非必填）；支持人脉记录与当日收支、物品记录关联。
- **本地数据管理**：支持按分类/时间范围批量删除（近 7 天/近 30 天/全部），删除前二次确认并明确提示"删除后数据无法恢复"；支持清除语音图片等本地缓存文件（保留文字记录）；支持本地加密备份。
- **轻量提醒**：人脉可设"下次联系提醒"（提前 1/3/7 天三档）；学习项目可设"进度更新提醒"（每日/每周/每月三档）。仅依赖系统通知，无后台推送；设置入口在对应录入面板，≤3 次点击。
- **物品管理升级**：新增物品名称关键词搜索（结果按时间倒序）；支持"在用/闲置/丢失"状态标签，默认"在用"，一键切换。

##### 3.2.10 物品过期智能提醒

**根本原因**：食品、化妆品、药品的限用/过期时间容易遗忘，导致浪费或误用；手动录日期、设提醒流程繁琐，难以坚持；用户缺少对临期状态的直观掌握。

**前置依赖**：物品管理已完成状态标签与搜索（3.2.9）。

**操作逻辑**：
1. 物品录入面板新增"图片识别"按钮，与手动录入并列；
2. 点击后选择图片或截图（对准包装上的限用/过期日期）；
3. 系统自动识别图中文字，提取"商品名称"与"过期/限用日期"，实时展示在极简确认框中；
4. 用户可点击修改识别错误的信息，确认后自动弹出提醒选择栏：**过期当天 / 提前 3 天 / 提前 7 天 / 提前 30 天**四档，一键勾选；
5. 勾选后系统静默完成三个动作：物品名称+过期时间+原图路径存本地 → 同步桌面系统日历生成可编辑事件 → 返回，无成功/失败弹窗；
6. 物品列表新增过期状态标识：绿（>30 天）/ 黄（≤7 天）/ 红（已过期）；默认按过期时间从近到远排序，过期物品自动置顶；
7. 点击条目可修改过期时间与提醒节点；删除条目时自动同步删除日历事件。

**设计要点**：识别页仅保留"选择图片 / 截图 / 取消"三个控件；识别失败自动切换为手动日历选择器，强制选日期后才可继续；商品名称支持模糊匹配，确认框可手动修改补充，无字数限制；提醒节点仅四档预设，不支持自定义时间、不支持多节点；日历同步完全静默，失败则下次启动自动重试；图片不压缩、不上传，仅本地保存；核心场景（识别成功、直接选节点）全程 ≤3 秒、≤5 次点击；日历为**单向同步**（轻念 → 系统日历），反向不同步。

#### 任务 3.3 导出、标签与周期复盘

- **导出**：任务族台账支持导出 Markdown/CSV（按日/按周，含任务名、状态、投入时长、进度备注）；速记族不支持批量导出（继承闪念边界，防止重查看倾向回潮）。
- **标签**：启用 Item 预留的 `tag` 字段，单标签、可选，录入时不出现，仅在主窗整理时可打。
- **周复盘**：本周时间分布（按任务的数字汇总）、本周完成/新增/晾着对比，只出数字不出图表。
- **当天工作摘要**：参考 Timing AI Summaries 先例，基于当日台账数据自动生成一段自然语言摘要；为守住本地优先原则，默认关闭，开启时由用户自选本地模型或自有 API，数据不出本机。

## 六、界面与交互

### 6.1 双窗分工

| 窗口 | 职责 |
|---|---|
| **浮窗** | 记录 + 并行推进 + 找回现场 + 接收建议（90% 的使用发生在这里） |
| **主窗** | 整理 + 复盘 + 管理 + 生活记录模块族 |

### 6.2 交互原则

| 原则 | 要求 |
|---|---|
| 捕获 ≤2 步 | 唤起、输入回车；所有录入 ≤3 次点击 |
| 切换任务 ≤1 步 | 点另一张卡的"开始"即可 |
| 找回现场 ≤1 眼 | 进度备注直接显示在卡片上，不点开详情 |
| 建议转正 ≤1 步 | 一次点击建卡/忽略；反复忽略则降频并汇入复盘，不静默消失 |
| 不抢焦 ≠ 看不见 | 浮窗常驻置顶，提醒靠视觉强化进入眼角余光，不抢键盘焦点 |
| 打扰与代价匹配 | 提醒强度随漏记确定性升级（静默 → 视觉强化 → 系统通知） |
| 无保存按钮文化 | 录入依靠回车/跳转/点击空白处自动保存（继承闪念） |
| 键盘优先 | 核心动作全部可纯键盘完成 |

### 6.3 关键流程

1. **捕获**：快捷键 → 输入 → 回车 → 保存收起、焦点归还
2. **推进**：待办点"开始" → 卡片进入浮窗并行区、计时滚动；切走直接点另一张卡，或自然冷却
3. **留现场**：切走前（可选）写一句进度备注；没写不阻塞，靠 `last_active_at` 与建议机制兜底
4. **漏记自愈**：空闲被自动暂停 → 回来一键确认；窗口切换被视觉强化提示 → 一键建卡；都没接住 → 复盘时从未覆盖时段里补
5. **复盘**：打开复盘视图 → 完成清单与时间分布 → 未覆盖时段处理 → 晾着的任务逐条做决定 → 关闭

| 维度 | 要求 |
|---|---|
| **平台** | Windows 10+、macOS 13+，功能与交互双端一致，快捷键遵循平台习惯且可自定义 |
| **性能** | 冷启动 <2s，唤起浮窗 <200ms，常驻内存 <100MB；计时精度到秒，不做高频写库 |
| **数据** | 本地 SQLite，每日自动备份、保留最近 7 份；被动时间线数据保留 30 天后自动清理（它是草稿，不是台账） |
| **隐私** | 无网络请求、无埋点、不采集内容；被动采集功能首次启动明确告知、默认可关 |

## 九、验收标准与成功指标

### 阶段一验收

| 任务 | 验收条件 |
|---|---|
| 1.1 捕获 | 任意应用内唤起 → 输入 → 回车 ≤3 秒，焦点回到原窗口 |
| 1.2 浮窗 | 5 个并行任务同时计时互不干扰；折叠态滚动展示所有进行中卡；全屏应用下浮窗置顶可见 |
| 1.3 状态流转 | **V0.2.1 生效**：整理 20 条收件箱 ≤2 分钟；A 计时中点 B"开始"，A 自动暂停一步完成；暂停退回待办可见；完成进"今日完成" |
| 1.4 计时 | **V0.2.1 生效**：空闲 10 分钟自动暂停 + 通知；锁屏恢复时长不膨胀；杀进程重启无损 |

### 阶段二验收

| 任务 | 验收条件 |
|---|---|
| 2.1 复盘 | 全流程 ≤2 分钟；未覆盖时段一键关联后时长计入对应任务 |
| 2.2 智能提示 | 窗口切换 10 分钟未计时 → 视觉强化 + 建议；一键确认即建卡；关闭后零监听 |

### 自用成功指标

- 单日捕获 ≥5 条（记录成本够低）
- 切回冷却任务看一眼卡片就能接上（找回现场成立）
- 每天复盘 ≤2 分钟，能说出"今天推进了什么、晾着什么"（工作情况可见）
- 一天结束时，台账记录的工作时间与实际工作时间的偏差主观上"基本无感"（漏记被兜住）

## 附录：调研借鉴

### 1. 多 Agent 并行管理工具（2026 年新品类，与痛点最贴近）

2026 年出现了一整类专门管理"多个并行 AI 编程会话"的工具：Vibe Kanban、Claude Squad、Conductor、Pane、Zentty、Nimbalyst 等。它们验证了几条可以直接借鉴的模式：

- **一个并行工作单元 = 一张卡片**。每张卡带阶段状态，一屏看全所有并行工作，不用在终端标签页之间来回翻。
- **"注意力状态"比任务状态更重要**。Zentty 的核心模型是 running / idle / needs input / needs approval / done——回答的不是"任务处于什么阶段"，而是"**哪件事现在需要我**"。
- **WIP（在制品）软上限**。业界建议同时推进的卡片控制在 3~5 张，超过会提示你"开得太多了"，而不是禁止。
- **本地优先是该品类的共识**。会话元数据包含仓库名、文件路径，没有团队愿意传到第三方。

**借鉴到 Mindtap**：任务卡支持多个并行"进行中"；增加"最近活跃/冷却/晾着"的派生维度；并行数量超过 5 个时轻提示。

### 2. Sunsama：日复盘仪式与"孤儿任务"

Sunsama 最被认可的不是任务管理，而是**晚间 shutdown 仪式**：回顾今天完成了什么，未完成的任务必须逐条做决定——顺延、委托或删除，**不允许有"没人管的孤儿任务"悬在那里**。其背后是蔡格尼克效应（Zeigarnik effect）：未闭合的任务会持续制造认知张力，直到被有意识地处理。

**借鉴到 Mindtap**：这正是"切换中丢失"的心理机制。产品必须提供**每日复盘视图**：今天推进了什么、哪些任务晾着没动、未闭合的回路有哪些。这是用户"了解自己的工作情况"的落点。

### 3. Timing：记录是副产品，归类是事后动作

Mac 上最成熟的自动时间追踪工具 Timing 的模式是：**后台自动记录一切活动 → 事后在 Review 屏幕上一键把时间块归入任务**，并带空闲检测、休眠自动停表、AI 生成当天工作摘要。Toggl 的官方实践也验证了同一件事：**有经验的用户最终都用"手动计时锚定重要任务 + 自动时间线兜底补漏"的混合模式**。

**借鉴到 Mindtap**：计时采用混合模式——用户点"开始"即对该任务自动累计投入时长；检测到空闲自动暂停并询问。计时是被动副产品，不是番茄钟、不是倒计时。

### 4. Toggl：无门槛存档与空闲纠偏

Toggl 允许**不关联任何项目也能保存时间条目**（Clockify 强制选项目，被证明是摩擦源）；空闲检测发现"计时在跑但你没动键盘"时，询问保留 / 丢弃 / 拆分。

**借鉴到 Mindtap**：捕获无门槛（非空即存）；空闲自动暂停，回来后一键确认。

### 5. 借鉴汇总

| 来源 | 借鉴点 | 落到 Mindtap 的决策 |
|---|---|---|
| 多 Agent 看板类 | 并行卡片 + 注意力状态 + WIP 提示 | 多任务并行进行中；活跃/冷却/晾着维度；>5 个轻提示 |
| Sunsama | 晚间复盘、无孤儿任务 | 每日复盘视图（产品价值终点） |
| Timing | 自动采集、事后归类、AI 摘要 | 计时自动累计；P2 做工作摘要 |
| Toggl | 手动+自动混合计时、空闲纠偏 | 点开始即计时；空闲自动暂停 |

### 6. 其他参考

- **IDE 心跳式自动计时**：WakaTime 插件模式（编辑心跳 + 超时自动停 + 项目自动检测）。
- **hooks 事件驱动**：Claude Code 官方 hooks 文档（SessionStart / Stop / TeammateIdle / Notification / TaskCompleted）。
- **3 秒记录、零思考成本、无保存按钮**：闪念时期产品定义，本文档继承为产品基因。
