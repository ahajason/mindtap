# V0.2.0 浮动窗 — 技术方案

> 对应 PRD: `docs/prd/v0.2.0-floating-window-prd.md`
> 对应 Domain: `docs/domain/v0.2-domain-model.md`
> 根因报告: `docs/reports/2026-07-28-floating-window-root-cause-retrospective.md`
> 回归治理: `docs/governance/ui-native-window-regression.md`
> 范围: 浮动窗最小可用(折叠 + 展开 + 手动完成 + 全局快捷键 + 持久化)
> 不在范围: 平台原生动态材质 / 时间盒 / 完成通知 / 主窗 UI 改动 / 任务历史复用

---

## 1. 分层 ownership（每个事实只有一个 owner）

> 多 owner 是 V0.2.0.x PATCH 链反复修同一件事的核心根因。
> 同一事实只能由一个地方控制。新增控制前先删旧的。

| 事实 | Owner | 位置 | 其他层不得干预 |
|---|---|---|---|
| 物理窗口尺寸 | Rust / Tauri 配置 + command | `tauri.conf.json` + `commands/floating_cmd.rs` | React / CSS 不得写死物理像素 |
| 窗口透明度 / 阴影 / 焦点 | Rust / Tauri 配置 | `tauri.conf.json` | CSS 不得用 `opacity` / `box-shadow` 模拟窗口阴影 |
| 拖动行为 | Tauri Window API | `win.startDragging()` | React 不得自己算 offset 移动 |
| 右键菜单 | Rust 原生菜单 | `src-tauri/src/commands/floating_cmd.rs` | React 不得渲染 HTML 菜单 |
| UI 状态（折叠/展开、active/empty） | React state | `src/floating/App.tsx` | CSS 不得独立决定状态 |
| CSS fallback 材质 | CSS pseudo-element | `.floating-root::before` | 仅在 CSS fallback 下承担网页基础表面；不得模拟或叠加 V0.2.1 的原生环境采样 |
| 设计 token | CSS 变量 | `src/styles/theme.css` | 组件内不得 hard-code 颜色/模糊值 |
| 持久化 | Rust SQLite | `src-tauri/src/db/` | 前端不得存 timer_session 状态到 localStorage |

## 2. 范围边界（bug 归属用）

### 2.1 在范围内（本方案管）

- 浮动窗折叠态（物理尺寸 / 位置 / 拖动 / 不抢焦 / 计时显示）
- 浮动窗展开态（物理尺寸 / 输入 / 失焦折叠）
- 全局快捷键 Ctrl+Shift+Space（唤起 / 隐藏浮窗）
- timer_session 4 动作（开始 / 暂停 / 恢复 / 完成）+ 3 态状态机
- 关主窗 = 隐藏；浮窗右键 = 退出
- 启动入口：主窗 + 浮窗都显示
- 数据持久化（数据库建表 / CRUD / partial unique index）
- 浮窗右键菜单 = Rust 原生 Tauri Menu
- 主窗 = V0.1.6 Style Guide 沿用，本期**不**修改

### 2.2 不在范围内（归其他方案/版本）

- 平台原生动态材质 → V0.2.1
- 选择已有任务 → 后续独立重新立项
- 时间盒 / 25min 振动 / 完成通知 toast → V0.2.2
- 主窗时间线 / 概览页 / 设置中心 → V0.3+
- macOS 适配 → V0.3+

### 2.3 bug 归属规则

任何 §2.1 列出的代码 / UI / 数据 / 事件路径上的 bug → 本版本 PATCH（V0.2.0.x）。
任何 §2.2 列出的 → 不归本版本，另开 task + 版本号。
**判断不出来时**，反向问："修这个 bug 不修，本方案 §7 DoD 哪一条会 FAIL？"能定位到任一条 → 在范围内；否则 → 不在。

### 2.4 平台层归属判定

改代码前先判定 bug 归属哪一层，不跨层绕：

| 症状 | 归属层 | 正确修法 |
|---|---|---|
| 黑边 / 灰边 / 透明边缘 | Windows compositor + Tauri 配置 | 调 `transparent` / `backgroundColor` / `shadow`，不在 CSS 层绕 |
| 物理尺寸不对 | Rust / Tauri | 改 `tauri.conf.json` 或 `set_floating_size`，不写 CSS width/height |
| 焦点被抢 | Tauri 配置 | 确保 `focus: false` + 永不调 `setFocusable`，不用 React `blur()` 绕 |
| 右键菜单被裁剪 | 原生菜单 vs HTML 菜单边界 | 用 Rust 原生菜单，不用 HTML 模拟 |
| 状态切换内容不对 | React | 改组件渲染逻辑 |
| 颜色/模糊/圆角不对 | CSS | 改 token 或 selector |

## 3. 接口契约

### 3.1 物理尺寸契约

**尺寸真值**（单位：逻辑像素，WebView2 内部 CSS 像素）：

| 呈现状态 | 宽度 | 高度 |
|---|---:|---:|
| 折叠 | 360 | 36 |
| 创建面板 | 360 | 280 |
| 控制面板 | 360 | 96 |

**三条不变量**：
1. 宽度恒为 360；窗口高度由折叠、创建面板、控制面板三项语义尺寸决定
2. 物理窗口尺寸 = Tauri / Rust 控制，React / CSS 不写死像素
3. `tauri.conf.json` 启动尺寸 = 折叠态（360×36），与运行时 resize 一致

### 3.2 Rust → JS（`#[tauri::command]` invoke）

| Command | 输入 | 输出 | 异常 |
|---|---|---|---|
| `timer_session_get_active` | — | `TimerSession?`（当前进行中） | DB error |
| `timer_session_get_by_id` | `{id: i64}` | `TimerSession?` | DB error |
| `timer_session_create` | `{taskTitle: string}` | `TimerSession`（新建，status='active'） | taskTitle 为空 / 已有 active / DB error |
| `timer_session_update_focus_ms` | `{id: i64, focusMs: i64}` | `()`（void） | id 不存在 / 状态非 active / DB error |
| `timer_session_pause` | `{id: i64}` | `TimerSession` | id 不存在 / 状态非 active / DB error |
| `timer_session_resume` | `{id: i64}` | `TimerSession` | id 不存在 / 状态非 paused / DB error |
| `timer_session_complete` | `{id: i64}` | `TimerSession` | id 不存在 / 已 completed / DB error |
| `set_floating_size` | `{w: f64, h: f64}` | `()`（void） | 窗口不存在 / 尺寸非法 |
| `app_exit` | — | `()`（void） | — |
| `app_show_main_window` | — | `()`（void） | — |

**`set_floating_size` 是物理 resize 的唯一入口**。前端切换折叠、创建面板或控制面板时必须调此命令，不得用 CSS 高度变化模拟。

### 3.3 后续动态材质增量（不在 V0.2.0 范围，仅作边界参考）

V0.2.1 只验证 `floating` 的平台动态材质与 CSS fallback，
不新增 timer session 业务命令或数据库索引。

### 3.4 JS → OS（Tauri 2 Window API）

| API | 用途 | 不变量 |
|---|---|---|
| `win.startDragging()` | 拖窗 | 必须在 mousedown / pointerdown 后调 |
| `win.outerPosition()` | 读物理位置 | 折叠态 resize 前必读位置以保持锚点 |
| `set_floating_size` IPC | 三项语义尺寸 resize | 折叠 360×36，创建面板 360×280，控制面板 360×96 |
| `win.show()` / `win.hide()` | 全局快捷键切换 | 浮窗用 |

### 3.5 IPC seams

IPC 按职责分为两个显式 seam：

1. timer session 与 app 业务命令通过 `src/lib/tauri-bridge.ts` 的 typed `api.*` 包装调用。
2. 浮窗物理 resize 是底层窗口平台 seam，由 `src/floating/App.tsx` 直接调用 `set_floating_size`。

新增命令时只修改其所属 seam，不为形式统一新增第二层 wrapper。Rust command、注册点、调用点和契约测试必须同步。

### 3.6 全局快捷键

**配置**：`src-tauri/src/lib.rs` 的 `Ctrl+Shift+Space` 注册。
**行为**：按下时切换浮窗显示 / 隐藏（is_visible → 取反）。
**冲突处理**：register 失败时弹系统 dialog 提示用户。

## 4. 数据模型

### 4.1 timer_session 表

| 字段 | 类型 | 约束 | 业务含义 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 自增 |
| task_title | TEXT | NOT NULL | 任务名（UI 层限 50 字符，DB 不强约束） |
| status | TEXT | NOT NULL，CHECK IN ('active','paused','completed') | 3 态 |
| started_at | INTEGER | NULL | 开始时刻（unix timestamp ms） |
| paused_at | INTEGER | NULL | 最近一次暂停时刻（unix timestamp ms） |
| completed_at | INTEGER | NULL | 完成时刻（unix timestamp ms） |
| focus_ms | INTEGER | NOT NULL DEFAULT 0 | 累计聚焦毫秒（暂停冻结） |
| created_at | INTEGER | NOT NULL | 创建时刻（unix timestamp ms） |
| updated_at | INTEGER | NOT NULL | 最后 update 时刻（unix timestamp ms） |

### 4.2 索引

| 索引 | 类型 | 业务含义 |
|---|---|---|
| `idx_timer_session_active` | UNIQUE PARTIAL: `WHERE status='active'` | 强制全局唯一 1 个 active |

### 4.3 业务不变量（由 db 强制）

1. 全局唯一 1 active（partial unique index 强制）
2. status 取值约束（CHECK 强制）
3. focus_ms 非负（DEFAULT 0）
4. paused 行 focus_ms 冻结（应用层每次 update 前 check status）
5. completed 行不可再改（status check + 应用层 guard）

## 5. 技术不变量

### 5.1 单 root div

- 折叠态、创建面板与控制面板共用**同一个** `.floating-root` DOM 节点
- 切换呈现状态时 root 不卸载不重建；只改折叠 / 展开 class，并替换创建或控制内容
- `panelRef` 挂在 root 上，document mousedown listener 用它判断 panel 内外点击

### 5.2 折叠几何可满足性

36px 折叠态高度是硬约束。数学上必须满足：

> 内容高度 + 上下 padding + 边框 ≤ 36px

- 折叠态不加垂直 padding；状态条自身固定为 36px 高并保留 12px 水平留白
- 折叠与展开复用同一状态条结构；展开内容在独立 body 中设置间距，不改变状态条几何
- 折叠态只有一行内容：StatusDot + 任务名 + 计时
- 活动折叠态**不**渲染控制按钮（控制按钮只在展开态出现）
- 用 CSS 隐藏代替物理折叠 = 反需求

### 5.3 材质 single-owner

玻璃材质的唯一 owner 是 `.floating-root::before` pseudo-element：
- 负责 `backdrop-filter`、background、圆角、边缘处理和材质阴影；Windows 透明浮窗保持 `border: 0`
- 浮窗 HTML 入口以及 `html`、`body`、`#root` 保持透明，不得在根页面恢复不透明背景
- pseudo-element 继承 `.floating-root` 圆角；不得使用 `inset 0 1px 0` 顶部高光或 `inset 0 0 0 1px` 闭合白色高光，因为 Windows 实机会分别形成顶部或四周白线
- fallback 表面密度由 `.floating-root` 的局部 `--floating-fallback-fill` 控制；不得修改共享 G3 token 迎合单个透明原生窗口
- `.floating-content` 只负责内容层布局，不叠加根表面背景或模糊
- React inline style、子组件 class、Tailwind utility 不得叠加根表面背景/模糊/阴影
- 共享 token 值仍引用 `src/styles/theme.css` 的 CSS 变量

### 5.4 不抢焦

- `tauri.conf.json` 浮窗配置 `focus: false`
- 前端永不调用 `setFocusable(true)`
- 输入框获取焦点是例外：用户点击输入框后，浮窗可以临时获得焦点以接受输入
- 但启动、展开、折叠等状态切换过程中**永远不**主动抢焦

### 6.2 前端（`src/`）

| 文件 | 职责 |
|---|---|
| `lib/tauri-bridge.ts` | timer session 与 app 业务命令的 typed IPC seam |
| `main.tsx` | 主窗入口（V0.2 沿用 V0.1.6 Style Guide，**不**改） |
| `floating/main.tsx` | 浮窗入口 |

| `floating/hooks/useFocusTicker.ts` | 1 秒 tick 驱动 UI 计时器显示 |
| `styles/theme.css` | 共享 G3 token（CSS 变量） |
| `floating/styles/floating.css` | 浮窗专用样式（含 `.floating-root::before` 材质） |

### 6.3 配置（`src-tauri/tauri.conf.json`）

**浮窗关键配置**：
- `label = "floating"`
- `width = 360`, `height = 36`（启动 = 折叠态）
- `transparent = true`
- `backgroundColor = "#00000000"`
- `shadow = false`
- `decorations = false`
- `focus = false`
- `alwaysOnTop = true`
- `skipTaskbar = true`
- `resizable = false`

## 7. 测试 seams

> 测试只在预定义的 seam 上做。跨 seam 断言（如 jsdom 里断言玻璃视觉）= 假绿。

### 7.1 生产 artifact 契约（L1）

直接读取生产文件验证配置一致性：

- `tauri.conf.json`：启动尺寸 360×36、transparent=true、shadow=false、focus=false
- `floating.css`：`.floating-root::before` 是 CSS fallback 的唯一材质 owner、使用 token 而非 hard-coded 值
- `theme.css`：G3 token 使用统一的共享变量，不在浮窗入口重复定义
- `App.tsx`：单 root、活动折叠态不渲染 controls

**工具**：Vitest + `fs.readFileSync` 读生产文件 + 结构断言。
**位置**：`src/floating/App.window-contract.test.tsx`

### 7.2 React 公共行为（L1）

通过 render + fireEvent 验证 DOM 公共行为：

- 三项呈现状态下的可见内容（折叠单行、创建输入、控制按钮）
- 点击折叠栏按上下文打开创建或控制面板；点击 panel 外、Esc 或失焦折叠
- 开始后折叠 + active session 创建；暂停/恢复后保持控制面板；完成后回到空闲折叠
- 当前任务控制面板不渲染输入框、开始、取消或历史任务入口
- 输入为空时开始按钮不可用

**工具**：Vitest + React Testing Library + happy-dom
**位置**：`src/floating/App.behavior.test.tsx`

### 7.3 IPC 边界（L1）

验证呈现状态切换时正确发出 resize IPC：

- 折叠 → `set_floating_size(360, 36)`
- 创建面板 → `set_floating_size(360, 280)`
- 控制面板 → `set_floating_size(360, 96)`
- mock bridge，断言调用参数

**位置**：`src/floating/App.behavior.test.tsx`

### 7.4 Windows WebView2 实机（L3 — hard gate）

**WSL 测试不能替代**。涉及透明合成、圆角边缘、拖动手感、焦点行为、DPI 缩放的结论，必须在 Windows 11 WebView2 实机上验证。

**验收清单**见 §8.3。

## 8. DoD（验收清单）

### 8.1 L1：生产契约与公共行为（WSL Vitest）

- [ ] 生产配置：启动 360×36，透明/阴影/焦点字段与契约一致
- [ ] React：三项呈现状态的可见内容正确；控制面板无创建输入；点击打开、失焦 / Esc 折叠、暂停 / 恢复保持打开、完成后折叠
- [ ] CSS fallback：单一材质 owner、共享 G3 token、折叠态无不可满足 padding
- [ ] IPC：folded / compose / controls 分别发出 360×36 / 360×280 / 360×96 resize
- [ ] 测试输出无 `NaN`、无缺 export 警告、无未处理异常

### 8.2 L2：工程回归

- [ ] `npm test -- --run` 全量单测通过
- [ ] `npx tsc --noEmit` 类型通过
- [ ] `npm run build` 构建通过
- [ ] `cargo check --manifest-path src-tauri/Cargo.toml` 通过

### 8.3 L3：Windows WebView2 实机（hard gate）

> 没有 L3 证据，只能标记"代码与静态验证完成，视觉待验"，不得宣称样式问题已修复。

**三项呈现状态基准**：
- [ ] 空闲折叠态（360×36）：状态点 + “未命名任务” + 00:00:00
- [ ] 空闲创建面板（360×280）：历史任务入口 + 输入框 + “开始”按钮
- [ ] 当前任务折叠态（360×36）：状态点 + 任务名 + 计时（呼吸动画）
- [ ] 当前任务控制面板（360×96）：状态行 + 暂停/恢复/完成；不显示输入框、开始、取消或历史任务入口

**DPI**：
- [ ] 100% / 125% / 150% DPI 下尺寸、位置、模糊均正确

**交互**：
- [ ] 折叠态点击按上下文打开创建或控制面板；任意展开态 panel 外点击、Esc 或失焦均折叠
- [ ] 开始 → 折叠 + active；暂停/恢复保持控制面板；完成 → 空闲折叠
- [ ] 折叠态 / 创建面板 / 控制面板均可拖动，位置不跳
- [ ] 右键弹原生菜单（4 项），不被裁剪
- [ ] 永远不抢焦（启动 / 切换 / 折叠展开均不抢）
- [ ] 重启后 active session 与计时恢复

**视觉**：
- [ ] 圆角无黑边 / 灰边（focus / unfocus 一致）
- [ ] 折叠态内容不裁剪（36px 恰好容下一行）
- [ ] 玻璃材质质感正确（模糊 + 半透填充 + 高光描边 + 软阴影）

## 9. 准入条件：什么时候才能改产品代码

> 症状补丁循环的根源之一是：还没确认 bug 在哪层，就开始改代码。

修改生产代码前，必须满足以下**任一**条件：

1. **生产契约测试 FAIL**：`App.window-contract.test.tsx` 有断言失败，且失败指向的是生产代码而非测试基础设施
2. **React 公共行为测试 FAIL**：四状态 DOM 行为不符合 PRD
3. **L2 工程回归 FAIL**：类型 / 构建 / cargo check 报错
4. **L3 Windows 实机 FAIL**：有截图或录屏证据显示视觉/交互不符合 PRD
5. **代码审查发现明确违反 §5 技术不变量**

**测试基础设施缺陷（fixture / mock / 测试环境）不归因于生产代码**。先修测试，再复验。复验通过了，就不要改生产代码。
