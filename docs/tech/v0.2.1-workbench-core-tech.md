## 1. 范围边界(bug 归属用)

### 1.1 在范围内(本方案管)

- 建新表 `item` + DROP 旧表 `timer_session`(表迁移,ADR-0011)

- 全局快捷键捕获改造(快捷键→show→聚焦→回车→保存→hide→还原原窗口,ADR 见 domain)
- 展开态并行任务卡列表(内容 / 累计时长实时滚动 / 冷却深浅 / 进度备注直接显示)
- 失真确认闭环(冷却阈值检测 / 跨天停表 / 独立确认气泡 / 5 秒超时暂停 / 待确认窗口 / 记入丢弃)
- 重复捕获轻提示(同名检测,不阻止不合并,ADR-0013)
- **1.3 收进 V0.2.1**:收件箱整理(转待办 / 仅留档 / 删除 / 5 秒撤销)、待办清单展示、暂停(active→todo)、完成(done)、归档查看 / 重新激活
- **1.4 收进 V0.2.1**:自动计时空闲保护——键鼠无操作超阈值(默认 10 分钟)自动暂停 + 系统通知"XX 已自动暂停" + 回来后一键确认是否计入;休眠 / 锁屏自动暂停,唤醒后时长不膨胀
- **激活时间段留痕**:新增 `focus_interval` 表(每次开始记一条,暂停/切走/完成结算 ended_at),供后续并行统计 / 合并

- 前台窗口监听 / 视觉强化 / 建议建卡 → V0.2.2(任务 2.2)

## 2. 接口契约

### 2.1 Rust → JS(invoke)

| Command | 输入 | 输出 | 异常 |
|---|---|---|---|
| `item_create` | `{content: string}` | `Item` | 空内容 / DB error |
| `item_get_active` | 无 | `Item[]`(全部进行中) | DB error |
| `item_get_inbox` | 无 | `Item[]`(收件箱,时间倒序) | DB error |
| `item_get_todo` | 无 | `Item[]`(待办,时间倒序) | DB error |
| `item_get_by_id` | `{id: number}` | `Item \| null` | DB error |
| `item_start` | `{id: number}` | `{ item: Item, switched_from: number[] }`(并行式,switched_from 恒 `[]`) | 非 inbox/todo / DB error |
| `item_pause` | `{id: number}` | `{ item: Item, pending_ms: number \| null }` | 非 active / DB error |
| `item_complete` | `{id: number}` | `Item` | 非 active/todo / DB error |
| `item_set_progress_note` | `{id: number, note: string}` | `Item` | 非 active / 超 100 字 / DB error |
| `item_set_dormant` | `{id: number, confirm_ms: number}` | `Item`(active→todo,结算 + 待确认) | 非 active / DB error |
| `item_confirm_pending` | `{id: number, keep: boolean}` | `Item`(记入/丢弃待确认窗口) | 无待确认 / DB error |
| `item_list_duplicate` | `{content: string}` | `Item[]`(同名活跃卡) | DB error |
| `item_check_dormant` | 无 | `Item[]`(冷却/跨天失真卡) | DB error |
| `item_get_history_titles` | `{limit?: number}` | `TitleRec[]`(历史复用) | DB error |

新增命令 = 三处都要改:`tauri-bridge.ts` + `invoke_handler!` 宏 + `commands/<name>_cmd.rs`。

### 2.2 JS → OS(Tauri 2 Window API / DOM API)

| API | 用途 | 不变量 |
|---|---|---|
| `floating.show() / hide()` | 快捷键捕获唤起/收起 | 不抢原窗口焦点(后台还原) |
| `set_floating_size`(既有命令) | 展开态物理 resize | 保持既有机制,不要改回 JS setSize |
| `new WebviewWindow('bubble')` | 失真确认气泡独立窗口 | 置顶 / 透明 / 无装饰 / 不抢焦点 |
| `win.startDragging()`(既有) | 浮窗拖动 | 保持既有 4px 阈值机制 |

### 2.3 IPC seam

**唯一 seam**: `src/lib/tauri-bridge.ts`。新增命令必须三处都改:① Rust/Backend ② bridge.ts 包装 ③ 调用点。
任何不经过 seam 的调用都是反模式。

### 2.4 deep-module seam(ItemRepo)

所有 `item_*` 命令是**薄 adapter**,调用唯一深模块 `db/item.rs` 的 `ItemRepo`:

```
┌─────────────────────────────────────────────┐
│        ItemRepo (深模块, 唯一外部 seam)       │
│  Small Interface:                            │
│    create(content) -> Item                  │
│    start(id) -> {item, switched_from}       │
│    pause(id) -> {item, pending_ms}          │
│    complete(id) -> Item                     │
│    confirmPending(id, keep) -> Item         │
│    list(query: ListQuery) -> Item[]         │
│    settleDormant() -> DormantResult         │
├─────────────────────────────────────────────┤
│  Deep Implementation (全藏在这里):            │
│  · 五态状态机转换 + 事务                      │
│  · 并行开始(不自动暂停其他 active)            │
│  · focus_ms 结算(pause/complete/dormant)    │
│  · pending_ms 待确认窗口                     │
│  · 失真检测(冷却 2h / 跨天)                  │
│  · 重复捕获检测(不阻止不合并)                │
│  · 查询策略(展开态列表 / 收件箱 / 待办)       │
└─────────────────────────────────────────────┘
```

- **状态机不在** commands 层、不在前端——全在 `ItemRepo` 内,一个事务原子完成状态转换 + 结算;
- 前端只发意图(`start` / `confirmPending`),不持有状态机;**start 是并行式——不自动暂停其他 active 卡,`switched_from` 恒为空**(多卡并行计时,旧「零成本切换 A 退回 todo」语义已废);
- **deletion test**:删掉 ItemRepo,状态机逻辑会散布到 N 个命令 + 前端,复杂性重现 → 它在挣自己的位置;
- **test surface = interface**:Rust 单测直接调 ItemRepo 方法,无需 mock;
- **locality**:改一个状态转换规则只改 ItemRepo 一处,所有调用者自动受益。

## 3. 数据模型

### 3.1 `item` 表(新,取代 timer_session)

| 字段 | 类型 | 约束 | 业务含义 |
|---|---|---|---|
| `id` | INTEGER | PK AUTOINCREMENT | 标识 |
| `content` | TEXT | NOT NULL | 内容,≤200 字 |
| `type` | TEXT | NOT NULL DEFAULT 'task' | 记录类型(任务族 / 速记族) |
| `status` | TEXT | NOT NULL CHECK IN ('inbox','todo','active','done','archived') | 五态 |
| `focus_ms` | INTEGER | NOT NULL DEFAULT 0 | 已结算投入(只增不减) |
| `last_active_at` | INTEGER | 可空 | 最近活跃(冷却/跨天派生) |
| `progress_note` | TEXT | 可空,≤100 字 | 进度备注 |
| `source` | TEXT | NOT NULL DEFAULT 'manual' | 来源 manual / suggested / hook |
| `payload` | TEXT | 可空 | 速记族 JSON(远期) |
| `tag` | TEXT | 可空 | 预留标签 |
| `deleted_at` | INTEGER | 可空 | 软删除时刻(5 秒撤销用) |
| `pending_ms` | INTEGER | 可空 | 待确认失真窗口毫秒(ADR-0012) |
| `created_at` | INTEGER | NOT NULL | 创建时刻 |
| `updated_at` | INTEGER | NOT NULL | 更新时刻 |

### 3.2 索引

- `idx_item_status_created`: `ON (status, created_at DESC)` — 展开态列表加速
- **去掉**旧 `idx_timer_session_active`(部分唯一索引)— 支持多并行进行中
- `status` 为五态,无独立 `paused`:`active→todo` 表示暂停(退回待办),`todo→active` 表示恢复(点开始)

### 3.3 `focus_interval` 激活日志表(新增,用户确认)

> 背景:用户明确「后端应把每次激活的时间段详细记下,避免丢失,失去计算后续业务(并行统计/合并)的方法」。focus_ms 是已结算缓存,`focus_interval` 是时间明细。

| 字段 | 类型 | 约束 | 业务含义 |
|---|---|---|---|
| `id` | INTEGER | PK AUTOINCREMENT | 标识 |
| `item_id` | INTEGER | NOT NULL, FK → item(id) | 所属记录 |
| `started_at` | INTEGER | NOT NULL | 激活开始时刻 |
| `ended_at` | INTEGER | 可空 | 暂停/切走/完成时填;NULL = 进行中 |

**行为**:
- 每次「开始」(item_start)→ INSERT 一条 `{item_id, started_at=now, ended_at=NULL}`
- 暂停 / 切走 / 完成 / 跨天停表 → UPDATE `ended_at=now`
- `focus_ms` 保留为已结算缓存(从 interval 聚合得出,不丢)
- 后续统计(并行时间 / 合并 / 跨天切片)从 interval 计算

### 3.4 业务不变量(由 db 强制)

1. 内容非空才能保存(空内容不建卡)
2. 同一时刻可多条 `active`(多并行)
3. `focus_ms` 只增不减
4. `active` 不跨天:启动扫描把跨天 active 退回 todo
5. `pending_ms` 非空 = 有待确认失真窗口,用户确认后结算并清空
6. 同名卡可并存(不阻止不合并)
7. **激活日志完整**:每次 active 必有对应 focus_interval 记录(started_at 非空);ended_at NULL = 进行中;结算后 focus_ms 与 interval 聚合一致

**不变量归属**(哪个模块强制):
- 由 **ItemRepo**(事务内)强制:状态转换合法性、零成本切换、focus_ms 只增不减、跨天停表、待确认结算;
- 由**前端**强制(仅展示):WIP 软上限提示(>5 轻提示,不阻止)、重复捕获轻提示展示、空内容按钮禁用(前端即时反馈,后端仍兜底)。
