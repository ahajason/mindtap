# V0.2.1 平台原生动态材质 — 技术方案

> 对应 PRD: `docs/prd/v0.2.1-native-dynamic-material-prd.md`
> 对应 Domain ADR: `docs/domain/adr/0010-v0.2.1-native-dynamic-material.md`
> 回归治理: `docs/governance/ui-native-window-regression.md`
> 范围: 仅 `floating` 原生窗口的材质能力接线、候选验证、固定运行期选择与 CSS fallback
> 不在范围: 主窗口、其他窗口、全局 token 重构、四状态业务行为、任务历史复用

---

## 1. 范围边界

### 1.1 在范围内

- 锁定版本的 Tauri 内建窗口效果能力盘点与最小接线；
- Windows 原生候选按 Acrylic、Mica 的顺序逐个验证；
- 每次运行固定选择已确认生产方案或 CSS fallback；
- 系统偏好、能力缺失、接线失败与网页候选渲染失败时的 CSS fallback；
- `floating` 的平台材质 owner、CSS fallback owner 与二者的边界；
- 配置接线、降级行为和 Windows L3 验收证据。

### 1.2 不在范围内

- `main`、其他弹窗或共享主题的材质改造；
- V0.2.0 的物理窗口尺寸、四状态、拖动、右键菜单、焦点和持久化改动；
- 手写 Win32 FFI、重复引入振动或窗口效果依赖；
- 用户可见材质选择、持久化选择、运行期手动切换或自动反复重试；
- 未经过候选比较与许可审查的 React 液态玻璃组件库；
- 任务历史复用与时间盒等后续产品功能。

### 1.3 归属判定

候选接线、降级、材质 owner 或 L3 动态材质矩阵中的问题属于 V0.2.1。窗口尺寸、菜单、拖动、焦点、四状态或持久化在未被本期材质接线改变时，仍归 V0.2.0 的技术方案；主窗口和共享视觉系统问题另行立项。

判断不清时，先回答：修复该问题是否会改变本文件 §6 的任一验收结论？会，则归 V0.2.1；否则不得借本版本扩大范围。

## 2. ownership 与运行期契约

| 事实 | 唯一 owner | 约束 |
|---|---|---|
| 原生环境采样与平台 tint | `floating` 窗口的 Tauri 原生效果配置 | 只允许实际选定的一个原生候选接线；不得由 React/CSS 模拟或叠加 |
| Web 内容形状、圆角、边缘处理 | `.floating-root::before` | 继续是 CSS fallback 的唯一材质 owner；不负责伪造原生环境采样，也不得形成实体白轮廓 |
| 运行期选定方案 | 启动期 material bootstrap | 启动时一次选择，本次运行保持不变 |
| React 网页候选 | 一个受控的浮窗材质边界 | 仅原生候选失败或实机证据更优时引入；初始化/渲染失败只可单向降级 |
| 窗口几何、拖动、焦点、菜单 | V0.2.0 原有 owner | 本期不得接管或复制 |

### 2.1 候选顺序

1. Tauri `2.11.5` 内建 Acrylic；
2. 未通过候选淘汰门槛后，Tauri 内建 Mica；
3. 两者均未通过，或一个 React 候选在同一 Windows L3 矩阵有明确更优证据时，才评估该 React 候选。

每一候选只进行一轮接线和一轮完整 L3；淘汰时先恢复 CSS fallback 并复验基础行为，再进入下一候选。禁止并存多个可生效候选或在同一次运行中动态竞选。

### 2.2 fallback 状态机

```
启动
  ├─ 系统请求减少透明/动画，或目标能力不可用 → CSS fallback（固定到退出）
  └─ 生产方案可用 → 已选生产方案（固定到退出）
       └─ 仅 React 方案初始化/渲染失败 → CSS fallback（固定到退出）
```

原生候选接线失败不是运行时静默兜底的理由，而是开发期证据：恢复 fallback、记录失败，再验证下一个候选。生产中不做材质自动回升或重试循环。

## 3. 接线与模块边界

### 3.1 配置与原生层

| 位置 | 职责 |
|---|---|
| `src-tauri/tauri.conf.json` | `floating` 的原生窗口基础配置与实际选定效果的声明接线 |
| `src-tauri/Cargo.toml` / 锁文件 | 验证 Tauri 内建能力已经可用；除 React 候选获准外不得新增材质依赖 |
| `src-tauri/src/lib.rs` | 仅在框架 API 要求时承担一次性启动接线；不承载 React 或 CSS 材质逻辑 |

Tauri `2.11.5` 已提供 `windowEffects` 与 Acrylic 候选能力。具体字段、平台限制和是否需要启动钩子必须以当前锁文件中的 Tauri 公开 API 复核后再接线；文档不能以静态声明替代该盘点。

### 3.2 前端层

| 位置 | 职责 |
|---|---|
| `src/floating/styles/floating.css` | CSS fallback 的唯一材质层；局部表面密度、圆角和边缘稳定性均在此归属 |
| `src/floating/App.tsx` | 保持四状态和既有交互；只有在 React 候选获选时才承载其受控边界 |
| `src/styles/theme.css` | 沿用既有共享 token；浮窗 fallback 不借机重构或修改全局等级 |

原生生产方案启用时，CSS 不得继续给同一浮窗叠加第二层 `backdrop-filter`、不透明填充或阴影来“增强”原生效果。CSS fallback 的定义必须可独立恢复。当前局部 `--floating-fallback-fill: 80%` 由最坏纯黑背景下 `#475467` 次级文字约 4.79:1 的理论对比度确定，不改变共享 G3 token；自动化只锁定该生产契约，实际可读性与边缘仍由 Windows L3 判定。

### 3.3 React 候选准入

引入前必须记录以下证据：

- React 19 与当前 Vite 构建链兼容；
- 许可适用于产品；
- 透明 WebView2、360×36 折叠几何、现有拖动、原生菜单和不抢焦均不受影响；
- 100% / 125% / 150% Windows L3 通过；
- 初始化或渲染失败后可单向降级至 CSS fallback。

任一条件未通过，候选不得进入生产依赖或生产路径。

## 4. 测试 seams

| 层级 | seam | 允许证明的事实 | 禁止的结论 |
|---|---|---|---|
| L1 | 生产 artifact | 效果接线只作用 `floating`、owner 唯一、fallback 路径存在 | Windows 视觉效果已通过 |
| L1 | 公共 UI / 平台调用边界 | 四状态和既有调用不因候选接线改变 | DWM/ WebView2 合成正确 |
| L2 | 类型、构建、Rust 编译 | 接线可构建、依赖和类型可用 | 动态材质可感知或稳定 |
| L3 | Windows 11 WebView2 | 环境层次、边缘、DPI、拖动和焦点真实表现 | 无 |

已有 `App.window-contract.test.tsx` 只扩展候选接线、single owner 与 fallback 的结构不变量；不得在不加载生产 CSS 的 DOM 环境中写像素或玻璃强度断言。

## 5. 候选淘汰门槛

任一候选出现下列结果即淘汰：

- 破坏四状态、拖动、原生菜单、不抢焦或计时持久化；
- 黑边、灰边、漏底、顶部白线、圆角不连续；
- 在状态切换、焦点切换或 100% / 125% / 150% DPI 下闪烁、跳位、裁剪错位；
- 可见卡顿或输入失响应；
- 无法呈现可感知的后方环境层次，仍为扁平泛灰。

淘汰结论必须有对应的 Windows L3 截图或录屏和环境信息，不允许用本地 DOM 测试替代。

## 6. DoD

### L1：生产契约

- [ ] 效果接线只命中 `floating`，不污染主窗口或共享主题；
- [ ] 原生方案、React 候选与 CSS fallback 各有唯一 owner，未出现叠加材质；
- [ ] 减少透明/动画、能力不可用和 React 渲染失败时存在固定 fallback；
- [ ] 既有四状态、物理尺寸、拖动、原生菜单与焦点契约仍通过。

### L2：工程回归

- [ ] 浮窗专项与全量单测通过；
- [ ] `npx tsc --noEmit` 通过；
- [ ] `npm run build` 通过；
- [ ] `cargo check --manifest-path src-tauri/Cargo.toml` 通过。

### L3：Windows 11 WebView2 hard gate

- [ ] 浅色、深色、高对比或纹理背景分别验证；
- [ ] 空闲/活动 × 折叠/展开、焦点/非焦点分别验证；
- [ ] 100% / 125% / 150% DPI 下检查边缘、位置、裁剪和可读性；
- [ ] 折叠、展开、拖动、resize、右键菜单、不抢焦和重启恢复通过；
- [ ] 实际选定方案呈现环境层次，且没有 §5 任一淘汰症状；
- [ ] CSS fallback 通过基础可用性及边缘稳定性验证。

没有 L3 证据时，状态只能是“代码与静态验证完成，动态材质待 Windows 实机验收”。

## 7. 维护归属

- 原生候选接线、fallback、候选淘汰与 L3 材质矩阵问题 → V0.2.1 PATCH；
- CSS fallback 基础可用性或单一 owner 被破坏 → V0.2.1 PATCH；
- V0.2.0 四状态、窗口几何、菜单、拖动、焦点、持久化本身的问题 → V0.2.0 PATCH；
