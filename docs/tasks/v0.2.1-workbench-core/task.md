> 归属判定: 见 `docs/tech/v0.2.1-workbench-core-tech.md` §1 范围边界
> 关联 retro: `docs/reports/v0.2.1-retrospective.md`(待补)

## Why

PRD 阶段一 S1~S4 生死场景要求工作台账核心:全局快捷键捕获(1.1)、常驻浮窗并行任务条(1.2)、收件箱与待办清单(1.3)、自动计时空闲保护(1.4)。现状 `timer_session` 是独立计时记录(3 态、全局唯一 1 active),无法表达「统一 Item + 五态 + 多并行进行中」的台账语义;且「冷却/晾着」被动变暗的展示无法解决「台账与现实脱节」的元痛点,必须以「失真确认闭环」主动询问取代。

## What

- 建新表 `item`(统一实体,五态)+ DROP 旧表 `timer_session`(ADR-0011)
- 五态状态机(inbox/todo/active/done/archived)+ 多并行进行中(去部分唯一索引)
- 全局快捷键捕获改造:快捷键→show→聚焦→回车→保存→hide→还原原窗口
- 展开态并行任务卡列表 + 收件箱项「开始」按钮
- 失真确认闭环:冷却 2h / 跨天检测 → 独立确认气泡 → 5 秒超时暂停 → 待确认窗口 → 记入/丢弃(ADR-0012)
- 重复捕获轻提示(不阻止不合并,ADR-0013)
- **1.3 收进**:收件箱整理(转待办/仅留档/删除/5 秒撤销)、待办清单、暂停(active→todo)、完成(done)、归档查看/重新激活
- **1.4 收进**:自动计时空闲保护(键鼠无操作 10 分钟自动暂停 + 系统通知 + 回来一键确认;休眠/锁屏自动暂停,唤醒时长不膨胀)
- **激活时间段留痕**:新增 `focus_interval` 激活日志表(每次开始记一条,暂停/切走/完成结算),供后续并行统计/合并
- 折叠态滚动展示并行进行中卡;新增面板「保存+开始」两按钮;折叠条「+」捕获入口
