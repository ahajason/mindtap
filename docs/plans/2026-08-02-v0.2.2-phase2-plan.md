# V0.2.2 开发计划 — 可信台账与复盘

> 阶段二开发计划。基于设计文档 `docs/L-2-review/design.md` 和调研结论。

## 版本信息

| 项 | 值 |
|---|---|
| 版本 | V0.2.2 |
| 名称 | 可信台账与复盘 |
| 基线 | V0.2.1 workbench (tag `v0.2.1-workbench`) |

## 总体阶段

| 阶段 | 内容 | 估算 |
|---|---|---|
| **P1** 后端重构 | 通知系统重构 + 时区 + background thread 统一 | 4 天 |
| **P2** 复盘视图 | `review.rs` + `commands/review.rs` + `ReviewPage` | 4 天 |
| **P3** 主窗改造 | 路由重构 + 侧边栏布局 + Style Guide 隐藏 | 3 天 |
| **P4** 主窗管理 | 搜索/筛选/编辑 + 回收站/删除流程 | 3 天 |
| **P5** 前台监听 | `foreground.rs` + 30s 轮询 + 浮窗视觉强化 | 4 天 |
| **P6** 收尾 | 设置页 + 通知开关 + 测试补齐 + 实测 | 3 天 |

**合计估算**：约 **21 天**（含风险 buffer）

## P1：后端重构（~4 天）

### 1.1 空闲检测统一（Q2 修复）
**文件**：`idle.rs`、`lib.rs`、`BubbleApp.tsx`
- 修改 `scan_and_auto_pause`：调用 `item::pause(id, pending_ms=实际时长)`（带待确认）
- 添加 `emit "floating:dormant"` 事件 → 前端气泡
- 删除 `BubbleApp.tsx` 第 62-92 行的 15s idle pause 轮询
- 保留 `BubbleApp.tsx` 的 `check_dormant` 5min 轮询（失真检测）
- 添加 `notification_enabled` 检查后发系统通知

### 1.2 时区处理（Q3）
**文件**：`time.rs`、`lib.rs`、`app_setting` 新增 key
- 用 `GetTimeZoneInformation` 获取本地时区偏移（替代当前 0）
- 启动时存到 `app_setting` key `local_tz_offset_secs`
- 修改 `local_day_start_ms` 使用真实偏移
- 前端每次拉起时重新获取时区偏移

### 1.3 后台线程统一
**文件**：`lib.rs`
- 30s 线程统一承担：空闲检测 + 失真检测 + 前台监听（P5 时加）
- 改为 `match` 多路复用：`scan_idle()` + `scan_dormant()` + `scan_foreground()`（P5）

### 1.4 测试
- `idle.rs`：`#[cfg(test)]` 测试 `scan_and_auto_pause` 逻辑
- `time.rs`：测试 `local_day_start_ms` 的时区偏移计算

## P2：复盘视图（~4 天）

### 2.1 review.rs 数据模块
**文件**：`src-tauri/src/db/review.rs`（新增）
- `get_daily_review(conn, local_day_start_ms) -> DailyReview`
  - 今日完成清单：`WHERE status='archived' AND archived_at >= day_start`
  - 时间分布：按 item 汇总 focus_interval 时长
  - 晾着任务：`WHERE status IN ('todo','active') AND last_active_at < now - 24h`
  - 未覆盖时段：取所有 `source='auto'` 的 focus_interval → 合并区间 → 反向求 gap
- `associate_gap(conn, item_id, gap_start, gap_end) -> Result`
  - INSERT focus_interval (source='gap_fill', ...)

### 2.2 commands/review.rs
**文件**：`src-tauri/src/commands/review.rs`（新增）
- `item_get_daily_review` → 注册到 `invoke_handler!`
- `item_associate_gap` → 注册到 `invoke_handler!`

### 2.3 focus_interval 扩展
**文件**：`schema.rs`（迁移）
- `ALTER TABLE focus_interval ADD COLUMN source TEXT NOT NULL DEFAULT 'auto'`
- 新增索引 `idx_focus_interval_started_at`

### 2.4 ReviewPage 前端组件
**文件**：`src/routes/ReviewPage.tsx`（新增）
- 四块面板布局：CompletedList + TimeDistribution + StaleTasks + UncoveredGaps
- 调用 `api.item.getDailyReview()`
- 未覆盖时段一键关联 → 调用 `api.item.associateGap()`

### 2.5 测试
- `review.rs`：`#[cfg(test)]` 测试复盘查询、空档查询、空档关联

## P4：主窗管理（~3 天）

### 4.1 ManagePage + ItemList
**文件**：`src/routes/ManagePage.tsx`（新增）
- 全部条目列表，搜索框 + 状态筛选（todo/active/archived）
- 内容编辑（点击标题进入编辑模式）
- 分页或虚拟滚动（条目多时）

### 4.2 删除流程
**文件**：`src/lib/tauri-bridge.ts`、`src/routes/ManagePage.tsx`
- 删除 → toast 带撤销按钮（5 秒窗口，sonner）
- 5 秒内撤销 → `api.item.undoDelete()`
- 5 秒后 → 任务进入回收站
- 回收站视图（`/manage?tab=trash`）：列出 `deleted_at IS NOT NULL`
- `hard_delete` 后端新增（彻底删除）

### 4.3 后端子命令
- `item_hard_delete`（新命令，彻底删除 + focus_interval 引用清除）

### 4.4 测试
- Rust：`soft_delete` + `undo_delete` + `hard_delete` 测试
- 前端：删除流程、撤销、回收站显示

## P5：前台监听（~4 天）

### 5.1 foreground.rs 模块
**文件**：`src-tauri/src/foreground.rs`（新增）
- `get_foreground_app() -> Option<AppInfo>`
  - Windows：`GetForegroundWindow` → `GetWindowModuleFileNameW` → exe 路径
  - macOS：预留（`#[cfg(target_os = "macos")]`）
- `AppInfo`：`{ exe_path: String, window_title: String }`

### 5.2 30s 轮询集成
**文件**：`lib.rs`（后台线程扩展）
- 在 30s 线程中调用 `scan_foreground()`
- 检测前台应用变化 + 持续 > 10 分钟且未计时
- emit `"floating:activity_signal"` 事件

### 5.3 设置项
**文件**：`commands/setting.rs`、`app_setting`
- `activity_monitor_enabled`：bool，默认 false
- 首次启动弹窗告知后默认开

### 5.4 浮窗视觉强化
**文件**：`src/floating/App.tsx`、`src/floating/components/FoldedBar.tsx`
- 监听 `"floating:activity_signal"` 事件
- 浮窗进入视觉强化态（呼吸动画）
- 显示建议文案 "看起来你在做 X，要记一下吗？"
- 一键确认 → 建卡 + 开始计时
- 一键忽略 → 浮窗恢复正常，该信号降频

### 5.5 测试
- Rust：`foreground.rs` 的 mock 测试（模拟 Windows API 返回）
- 前端：活动信号触发、视觉强化、确认/忽略

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Windows API 兼容性（前台监听） | 低 | 高 | 在 P5 开始前 prototyp `GetWindowModuleFileName` |
| 时区偏移计算错误 | 低 | 中 | 写测试验证东八区/西五区边界值 |
| 通知权限请求失败 | 中 | 低 | 静默降级，不阻塞其他功能 |
| P3 路由重构影响现有功能 | 中 | 中 | 渐进改造，先加业务路由，再移 Style Guide |
| 21 天估算过长 | 中 | 高 | 可并行 P5 和 P6（P5 依赖 P1，P6 大部分独立） |
