# 浮窗呈现状态重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将浮窗折叠、创建与当前任务控制收敛为三个可验证的呈现状态，并让窗口尺寸与可见内容一致。

**Architecture:** `FloatingApp` 保持唯一的浮窗交互 owner；局部打开状态与是否存在会话派生出 `folded`、`compose`、`controls` 三种呈现状态。单一 resize effect 依据呈现状态尺寸表调整原生窗口，创建与控制内容继续由已有 `ExpandedPanel` 与 `ControlRow` 负责，不新增全局 store、状态机库或 DOM 高度测量。

**Tech Stack:** React 19、TypeScript、Tauri 2、Vitest、React Testing Library、Tailwind CSS。

---

## 文件结构

| 文件 | 责任 |
|---|---|
| `src/floating/App.tsx` | 定义并派生呈现状态；集中窗口尺寸切换；按呈现状态渲染创建或控制内容。 |
| `src/floating/App.behavior.test.tsx` | 从用户可见行为验证三种呈现状态、尺寸 IPC 与主要状态转换。 |
| `src/floating/App.window-contract.test.tsx` | 验证生产源码仍声明三项语义尺寸，活动控制态不泄漏创建输入。 |
| `docs/prd/v0.2.0-floating-window-prd.md` | 将四状态矩阵与用户可观察行为改为“创建展开 280、控制展开 96”。 |
| `docs/tech/v0.2.0-floating-window-tech.md` | 将物理尺寸与 IPC 契约改为三项语义尺寸。 |

## 不在范围内

- 不改变任务记录的持久化状态或查询语义。
- 不增加“进行中时直接输入新任务”或任务切换流程。
- 不新增前端全局 store、跨窗口事件或状态机依赖。
- 不通过测量 DOM 内容来决定原生窗口高度。

- [ ] **Step 1: 声明呈现状态及尺寸表**

删除 `FOLDED_W`、`FOLDED_H`、`EXPANDED_W`、`EXPANDED_H`，在 `TASK_TITLE_MAX` 之前加入：

```ts
type FloatingPresentation = "folded" | "compose" | "controls";

const FLOATING_SIZE: Record<FloatingPresentation, { w: number; h: number }> = {
  folded: { w: 360, h: 36 },
  compose: { w: 360, h: 280 },
  controls: { w: 360, h: 96 },
};
```

保留 `FRAME_W = 360` 与 `FRAME_H = 36`，因为它们只服务于折叠态默认位置的边界计算。

- [ ] **Step 2: 让 `FloatingApp` 派生唯一的呈现状态**

将 `expanded` state 改名为 `isPanelOpen`，并在三个局部 state 之后加入：

```ts
const presentation: FloatingPresentation = !isPanelOpen
  ? "folded"
  : session
    ? "controls"
    : "compose";
```

将所有 `setExpanded(true)` 改为 `setIsPanelOpen(true)`；将所有 `setExpanded(false)` 改为 `setIsPanelOpen(false)`。不要为 `presentation` 再加 state，避免两个 UI 真值。

- [ ] **Step 3: 用尺寸表替换 resize effect 的布尔分支**

将 resize effect 的依赖从 `[expanded]` 改为 `[presentation]`，并用以下主体替换其异步 IIFE 内的尺寸选择逻辑：

```ts
const { w, h } = FLOATING_SIZE[presentation];
if (presentation !== "folded") {
  const pos = await win.outerPosition();
  if (cancelled) return;
  await invoke<void>("set_floating_size", { w, h });
  if (cancelled) return;
  await win.setPosition(new PhysicalPosition(pos.x, pos.y));
  return;
}

await invoke<void>("set_floating_size", { w, h });
```

这保留既有“展开前读取并回设位置”的防跳位行为，但所有窗口几何只能由 `presentation` 决定。

- [ ] **Step 4: 按呈现状态渲染 body 与根 class**

根节点 class 改为：

```tsx
className={`floating-root ${presentation === "folded" ? "folded" : "expanded"}`}
```

body 条件改为：

```tsx
{presentation !== "folded" && (
  <div className="floating-body">
    {presentation === "controls" ? (
      <ControlRow
        status={session!.status}
        onPause={() => act("pause")}
        onResume={() => act("resume")}
        onComplete={() => act("complete")}
      />
    ) : (
      <ExpandedPanel
        taskTitle={taskTitle}
        onTaskTitleChange={setTaskTitle}
        onStart={handleStart}
        onClearAndDismiss={handleClearAndDismiss}
        maxLength={TASK_TITLE_MAX}
        submitting={submitting}
      />
    )}
  </div>
)}
```

`session!` 在这里安全：`presentation === "controls"` 只在 `isPanelOpen && session` 时成立。不要把输入框、开始按钮或历史入口加到 `ControlRow`。

- [ ] **Step 5: 让成功动作直接收敛呈现状态**

在 `handleStart` 中保存创建命令的返回值，替换 `await api.timerSession.create(title);` 和随后的 `await refresh();`：

```ts
const created = await api.timerSession.create(title);
setSession(created);
setTaskTitle("");
setIsPanelOpen(false);
```

在 `act` 的 `complete` 分支中，替换 `void refresh();` 为：

```ts
setSession(null);
setIsPanelOpen(false);
```

保留暂停、恢复后 `setSession(updated)` 的现有逻辑，且不要关闭面板。成功命令已经返回权威会话，因此这两个 UI 收敛路径不应额外依赖异步重新查询。
