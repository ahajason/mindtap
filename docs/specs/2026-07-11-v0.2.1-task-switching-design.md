## 三 功能范围 (V0.2.1)

### 3.1 SwitchDropdown UI 位置 [事实 = ADR 0009 + 候选]

- **位置**: 仅在**展开态**显示（折叠态不变 — 320×36 极简保留）
- **展开态布局** (从上到下):
  1. 当前任务状态 / 计时摘要 (active 或 paused 时显示，分支沿用 V0.2.0)
  2. **SwitchDropdown section (新增)** — 仅在"无 active session" 时显示
     - 入口: "或选择已有任务" 按钮（仅 1 行，关闭态）
     - 展开: 列表 5 项 task_title（开态，玻璃面板）
  3. InputBar (50 字符)
  4. 主操作按钮 (开始 / 暂停 / 完成)
- **尺寸**: 360×280 **不变**。SwitchDropdown section 高度 ≈ 80px (关闭) / ≈ 180px (展开列表)，向下挤 InputBar 区。**待 grill**: 超过 280px 时是否滚动 / 自动折叠列表 / 限制列表高度。

### 3.2 SwitchDropdown 数据源 [事实 = ADR 0009 候选 A]

| 维度 | 值 | 标注 |
|---|---|---|
| 来源表 | `timer_session` | [事实] |
| 状态过滤 | `status='completed'` | [事实 = ADR 0009] |
| 去重维度 | `task_title` (按 task_title 唯一) | [事实 = ADR 0009] |
| 排序 | 末次 `completed_at` DESC | [事实 = ADR 0009] |
| N | **5** | [事实 = ADR 0009] |
| 时间窗 | 无（不限时间，按 db 全部 completed 内末次时间）| [候选 — 是否仅"最近 7 天"待 grill] |

**SQL 等价** (后端 `ListRecentTaskTitles` 命令):
```sql
SELECT task_title, MAX(completed_at) AS last_used
FROM timer_session
WHERE status = 'completed'
GROUP BY task_title
ORDER BY last_used DESC
LIMIT 5;
```

### 3.3 选后行为 [事实 = ADR 0009 候选 A]

| 步骤 | 动作 |
|---|---|
| 1 | 用户在 SwitchDropdown 列表点一条 task_title |
| 2 | 折叠 SwitchDropdown 列表（收回"或选择已有"按钮态） |
| 3 | InputBar 显示该 task_title（可二次编辑） |
| 4 | 用户按 Enter / 点"开始" |
| 5 | 创建新 timer_session: task_title=该值, status='active', started_at=now, focus_ms=0 |
| 6 | 折叠态 + 计时开始（同 V0.2.0 S2）|

**特性**:
- InputBar 显示完整 task_title（不被 SwitchDropdown 显示截断影响）
- 选中后**不立即**创建 session（必须 Enter / 开始 触发 — 与 V0.2.0 一致：InputBar 是 staging 入口）
- 选中后**不**折叠展开态（用户可再编辑）

### 3.4 pending 态 — V0.2.1 是否引入 [候选]

V0.2.0 3 态状态机 (active/paused/completed) 不含 `pending`。V0.2.1 的"选已有未点开始"状态需要 pending 吗？

**候选**:
| 选项 | 含义 | V0.2.1 倾向 |
|---|---|---|
| A **不引入 pending** | 复用 V0.2.0 3 态，"未开始" = 无 session（InputBar 是 UI staging，db 不存）| ✅ **默认** |
| B 引入 pending | 加一暂存态，db 存 task_title + status='pending' | 否（schema 改动；Q3=B 锁定不直接复用旧 session；与 V0.2.0 设计"展开态是 staging 不落库"冲突） |

**锁定 A**: V0.2.1 沿用 V0.2.0 3 态；SwitchDropdown 选中后**不**触发任何 db 写，仅 UI state 更新。

### 3.5 与 task 表关联 [推断 = V0.3 任务]

V0.2 spec v1.1 §四 锁定: V0.2 schema 不动 + V0.3 加 `task_id` 外键。V0.2.1 **不**新增 task 表:
- task_title 仍存 `timer_session.task_title`（冗余字段，[ADR 0002]）
- SwitchDropdown 从 `timer_session` 直接查，不依赖 task 表
- V0.3 接入 task 表后再评估是否切换 SwitchDropdown 数据源

### 3.6 a11y [事实 = V0.2.0 spec §3.9 沿用]

- SwitchDropdown 触发按钮: `aria-label="或选择已有任务"`, `aria-expanded` 联动
- 列表项: `<button role="menuitem">` + task_title 文字 + 完整 task_title 做 `title` 属性
- 键盘: `Tab` 进出；`↑↓` 在列表项间切换；`Enter` 选中；`Esc` 关闭列表
- 焦点丢失: 自动关闭列表（与 V0.2.0 InputBar 失焦折叠一致）
- 屏幕阅读器: 选中后朗读 "已选 X，点回车开始计时"

### 3.7 错误处理 [事实 = V0.2.0 spec §3.8 沿用]

| 错误 | 处理 |
|---|---|
| `ListRecentTaskTitles` 读 db 失败 | SwitchDropdown 区段隐藏 + 显示"暂无历史"占位 |
| 选中后 Enter 创建 session 失败 | 沿用 V0.2.0 db 写失败处理（红字 + 重试 3 次）|

## 四 数据 schema (V0.2.1 增量)

**V0.2.1 schema = V0.2.0 schema + 1 个新 SQL query (读路径)。0 schema 改动**:

```sql
-- V0.2.1 新增 0 schema 改动;1 个新 query (ListRecentTaskTitles):

-- reads
SELECT task_title, MAX(completed_at) AS last_used
FROM timer_session
WHERE status = 'completed'
GROUP BY task_title
ORDER BY last_used DESC
LIMIT 5;

-- V0.2.0 schema 不动 (status 仍 3 态)
-- V0.2.1 不引入 pending 态 (沿用 3 态)
```

**索引**: V0.2.0 已有 `idx_timer_session_completed_at` ON `completed_at DESC` — V0.2.1 的 GROUP BY task_title + ORDER BY MAX(completed_at) 走 index 顺序扫描，前 5 行足够；V0.2.1 实测慢 / 行数大时再加 `idx_task_title_completed`。

## 六 验收标准 (V0.2.1 release gate)

- [ ] 启动后做几次新任务 (V0.2.0 流程)，制造 ≥ 6 条 completed session, ≥ 3 个不同 task_title
- [ ] 展开浮窗 → 看到"或选择已有任务"入口
- [ ] 点击入口 → 弹出列表,显示**最近 5 个不同 task_title**,**末次使用倒序**
- [ ] 列表项点击 → SwitchDropdown 关闭 + InputBar 显示 task_title
- [ ] InputBar 显示完整 task_title (不被 SwitchDropdown 显示截断影响)
- [ ] InputBar 按 Enter → 创建新 timer_session,status='active', 进入计时 + 折叠
- [ ] 选中后**不立即**创建 session (db 不增加 pending 态)
- [ ] 历史 completed session 不被选中操作破坏 (db 行数 +1,旧行 completed_at 不变)
- [ ] SwitchDropdown 列表键盘可达 (Tab 进 / ↑↓ 切 / Enter 选 / Esc 关 / 失焦关)
- [ ] 折叠态仍不含 SwitchDropdown (320×36 不变)
- [ ] 折叠态 aria-label 仅含 task_title + focus_ms (不含 SwitchDropdown 提示)
- [ ] 无 active session 时不显示已完成区段
- [ ] 无历史 completed session 时 SwitchDropdown 区段隐藏 (不显示空列表)
- [ ] db 文件 schema 与 V0.2.0 spec v1.1 §四 一致 (0 schema 改动)
- [ ] dev 实测 `npm test` 全部 vitest 过 (V0.2.1 新增 ≥ 1 个 it (SwitchDropdown 选中后是否给 InputBar))
