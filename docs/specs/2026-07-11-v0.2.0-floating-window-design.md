# V0.2.0 浮动窗 — 设计 spec

> 一句话: **V0.2.0 = 一个永远在桌面边缘、3 秒进入计时、1 秒切回工作的"我现在在做什么"指示器**。
> 折叠态显计时 + 展开态输文字 + 手动完成；Windows 11 锁平台。

- [候选] = 给出具体候选方案
- `.archive/` 任何内容**整体非事实**（即使文件存在），引用时必须标 [推断]/[候选]

## 二 用户与场景

### 2.1 目标用户 [事实]

V0.2 用户是项目所有者本人（jason），单人本地使用，参见 `CONTEXT.md` "单人本地" 段。**V0.2 不支持多用户 / 团队 / 多设备同步**（用户决策 Q11）。

### 2.2 核心使用场景 [事实]

| 场景 | 用户动作 | 系统反应 |
|---|---|---|
| **S1 工作开始** | 点击托盘 / 启动应用 / Ctrl+Shift+Space | 主窗 + 浮窗都显示，浮窗在折叠态 |
| **S2 录入新任务** | 点击浮窗展开 → 输入 task_title → 点"开始" | 折叠回折叠态，进入 active 状态，开始计时 |
| **S3 查看当前计时** | 瞥一眼浮窗折叠态 | 看到 task_title + 实时 focus_ms |
| **S4 暂停** | 展开 → 点"暂停" | status='paused', focus_ms 冻结 |
| **S5 恢复** | 展开 → 点"恢复" | status='active', 继续累加 focus_ms |
| **S6 完成任务** | 展开 → 点"完成" | status='completed', 折叠态显示"已完成"短状态后归位 |
| **S7 切换任务** | 展开 → 点"完成" + 输入新任务 + "开始" | 上一个 completed；新一个 active |
| **S8 误触隐藏** | Ctrl+Shift+Space | 浮窗隐藏；再次按下显示 |
| **S9 隐藏主窗（不退出）** | 点击主窗关闭按钮 | 主窗隐藏，浮窗继续计时，应用不退出 |
| **S10 退出应用** | 浮窗右键菜单 → 退出 | 应用退出，db 持久化 |

### 3.7 不抢焦策略 (Windows)

[事实 = V0.2.7 patch 同步]: V0.2.0 实施路径 = **V1.0 D15: tauri.conf.json `focus: false` 启动期不抢焦 + 永不在 JS 调 `setFocusable`** (V0.2.5 patch 删 setFocusable 调用, V0.2.7 spec 同步)。**Win11 WebView2 实测 `setFocusable(true)` 会 panic webview 整个闪退** (V0.2.5 retro 反模式 13)。A `WS_EX_NOACTIVATE` 是 spec v1.1 候选未实施。

**实现方式**:
- Tauri 2 浮窗 webview 创建时通过 `RawWindowHandle` 拿底层 HWND
- 给 HWND 加 `WS_EX_NOACTIVATE` style（用 `SetWindowLongPtr(hwnd, GWL_EXSTYLE, ...)`）
- 浮窗被显示/点击时不抢焦点

**实测验证（dev 实测 = commit hard gate）**:
1. IDE 焦点 → Ctrl+Shift+Space 显示浮窗 → IDE 输入框仍能输入（焦点未丢）
2. 浮窗 focus 测试失败 → 切到 Tauri 2 API 抑制策略 → 重测

**候选策略**（如 A 失败可回退）:
- B) Tauri 2 `WebviewWindow.set_focus()` 抑制（API 不一定存在，待实测）
- C) wry/win32 直接设置（最底层，Tauri 升级时易脆）

## 四 数据 schema (V0.2 spec v1.1 锁定)

```sql
-- V0.2 spec v1.1 锁定 schema, V0.2 实施前最后验证

CREATE TABLE timer_session (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  task_title    TEXT NOT NULL,                                -- 用户输入（V0.2.0 上限 50 字符，UI 校验）
  status        TEXT NOT NULL CHECK (status IN ('active', 'paused', 'completed')),
  started_at    INTEGER,                                      -- 进入 active 的 Unix ms（首次）
  paused_at     INTEGER,                                      -- 当前 paused 时刻（NULL = 未暂停）
  completed_at  INTEGER,                                      -- 完成的 Unix ms（NULL = 未完成）
  focus_ms      INTEGER NOT NULL DEFAULT 0,                   -- 累计聚焦毫秒（每秒由前端写入）
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

-- 全局唯一 1 个 active（partial unique index）
CREATE UNIQUE INDEX idx_timer_session_active
  ON timer_session (status) WHERE status = 'active';

-- 时间倒序查 completed（V0.3 主窗时间线准备）
CREATE INDEX idx_timer_session_completed_at
  ON timer_session (completed_at DESC) WHERE status = 'completed';
```

**字段语义**:
- `focus_ms` 在 active 期间由前端每秒更新到 db（spec v1.1 grill 9.1 = A）
- `paused_at` 进入 paused 时记当前时间，恢复 active 时清零
- `started_at` 第一次进入 active 时记，永不修改
- `created_at` schema 创建时（不是首次 active），用于 db 内部审计
- V0.2.0 不需要 `pending` 态（V0.2.1 "选已有" 时再加）

**V0.3 接入 task 表关联**（spec v1.1 grill 9.2 = B 冗余 `task_title`）:
- V0.2.0 schema 不动
- V0.3 加 `task_id INTEGER NULL` 外键 + 同时维护 `task_title` 冗余字段
- 改 task_title 时同步更新 timer_session.task_title（崩溃风险：事务包住）
