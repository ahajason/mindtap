# 0003 — V0.2.0 最小可交付：折叠 + 展开输（无任务选择）

**Status**: accepted · 2026-07-11 · V0.2 立项
**引用警告**: 本 ADR 内推断已标注

V0.2.0 浮窗包含**折叠态**（360×36，显示当前 task_title + focus_ms 计时器）+ **展开态**（输入 task_title → 点开始 → 自动进入 active 并折叠）。**不**支持“选择已有 timer_session / task”。历史任务复用曾是后续候选，但不再属于 V0.2.1；如需恢复，必须以新的版本号独立立项。

## 候选方案

| 选项 | V0.2.0 折叠 | V0.2.0 展开 | 后续版本还做什么 |
|---|---|---|---|
| A 只折叠态 | 计时 + 任务名 | — | 加展开 + 选择 + 输入 |
| **B** ✅ 折叠 + 展开输 | 计时 + 任务名 | 输 + 启动（无选择）| 历史任务复用另行立项 |
| C 一步到位 | 计时 + 任务名 | 选 + 输 一步到位 | — |

## 为什么选 B 而不是 A 或 C

- **不选 A**：用户回答 Q3 时排除了"只折叠"，V0.2.0 须含展开态。**这是用户决策，不是推断。**
- **不选 C**：将历史任务复用与 V0.2.0 最小输入路径一起交付会扩大初版范围。历史方案曾提出 SwitchDropdown，但该方案已 superseded；是否恢复任务复用必须在新的版本需求审查中决定。

## 后果（候选，待 V0.2 spec 确认）

- **+** V0.2.0 = 单一交互路径（输 → 启动 → 折叠 → 计时），验收简单（用户决策）。
- **？** 历史任务复用再次立项时，其边界是否清晰——由未来版本的需求审查决定。
- **−** V0.2.0 用户不能从历史 timer_session 里挑一个继续计时（这是 V0.2.0 范围限制，非副作用）。
