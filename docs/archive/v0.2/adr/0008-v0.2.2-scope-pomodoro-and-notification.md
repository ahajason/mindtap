# 0008 — V0.2.2 范围：时间盒（Pomodoro）+ 完成通知（Windows toast）

**Status**: ❌ 已废弃(2026-08-02,ADR-0014) · accepted(2026-07-11,V0.2 立项)
**引用警告**: V0.2.2 已重定义为阶段二(可信台账与复盘),本 ADR 时间盒方案整体废弃——见 `0014-v0.2.2-phase2-scope.md`。番茄工作法与 Mindtap 基因冲突(PRD 主文档 L46)。完成通知决策点并入阶段二 2.2(打扰级别配置)。本 ADR 仅作历史参考。

V0.2.x 分三个版本节奏:

| 版本 | 范围 |
|---|---|
| **V0.2.0** | 折叠态 + 展开态输 + 手动完成 + 全新 db + 锁 Windows（5 项 ADR 0001-0005 + ADR 0006 + ADR 0007）|
| **V0.2.1** | 平台原生动态材质验证与 CSS fallback |
| **V0.2.2** | 加时间盒（25min 振动提醒 + 休息）+ 完成通知（Windows toast）|
| **后续版本** | 如重启任务历史复用，重新立项并分配版本号 |

## 为什么 V0.2.2 单独成一版

- 时间盒和完成通知都是**叠加功能**，不改 V0.2.0 / V0.2.1 已有交互路径——单独版本方便 dev 实测聚焦。
- 时间盒涉及状态机扩展（`running` 子状态机: focus 25min → break 5min → focus ...），schema 可能要加 `phase` / `phase_started_at` 字段——单版本收口避免污染 V0.2.0 / V0.2.1 的"小步快跑"。
- 完成通知是平台原生 API（Windows toast 用 `tauri-plugin-notification`），跟 V0.2 主线（计时 / 状态切换）解耦。

## 候选方案

| 选项 | 时间盒 | 完成通知 |
|---|---|---|
| A 合并到 V0.3 | — | — |
| **B** ✅ V0.2.2 单独 | 25min 振动 + 休息 | Windows toast |
| C V0.2.2 只时间盒，V0.3 加通知 | 25min 振动 + 休息 | — |

## 后果

- **+** V0.2.x 三个版本各自聚焦，独立验收。
- **+** V0.2.2 时间盒可在 V0.2.0 / V0.2.1 用户反馈基础上调优（25min 是否合理？休息 5min 还是 10min？）。
- **−** V0.2.x 三个版本连续发布，开发节奏压力。
- **−** Windows toast 在 macOS 平台用 `NSUserNotification` API（Apple 平台事实）——但 V0.3 macOS 通知方案待 V0.3 立项独立评估，本 ADR 不预设。

## V0.2.2 spec 阶段必 grill

- 25min 是否可配置（默认 25 / 用户可改？）。
- 休息时长（默认 5min？）。
- 长休息（每 4 个 pomodoro 一次长休息 15min？）。
- 完成通知触发条件（仅 completed？也覆盖 paused→completed？）。
- Windows toast 内容（"已完成 X"？带交互按钮？"查看"按钮？）。
