# V0.2.0 浮动窗 — 设计契约

> **定位**：浮窗视觉、交互和可访问性的唯一设计入口。玻璃参数只引用共享玻璃规范，不在本文重复定义。

## 一、四状态视觉矩阵

浮窗由“是否有活动任务”和“折叠/展开”两个维度组成四个界面状态。折叠态为 360×36，展开态为 360×280，切换只改变高度。

| | 折叠态 | 展开态 |
|---|---|---|
| **空闲** | 灰色状态点 + “未命名任务” + `00:00:00` | 任务输入框 + 开始 + 取消 |
| **活动** | 活动状态点 + 任务名 + 计时 | 状态行 + 暂停或恢复 + 完成 |

四个状态共享同一个浮窗容器。状态切换时容器持续存在，避免材质闪烁、位置跳变和事件边界变化。

## 二、状态设计

### 2.1 空闲折叠态

- 状态条在折叠态和展开态保持同一结构、36px 高度和左右 12px 留白；展开内容只出现在状态条下方，不改变状态条几何。
- 左侧状态点与窗口边缘保持留白，任务名占据可伸缩空间，右侧计时与窗口边缘保持相同留白。
- 任务名区域可收缩并以省略号截断，计时和状态点不收缩。
- 整行恰好容纳在 36px 高度内，不出现第二行或额外垂直留白。
- 短按横条展开；拖动横条移动窗口；右键打开系统菜单。

### 2.2 空闲展开态

- 使用纵向布局，包含任务输入区和操作区。
- 输入框占位提示表达“当前在做什么”，最多 50 个字符。
- 输入为空或全为空格时，开始按钮禁用。
- 点击开始或按 Enter 后开始计时并折叠。
- 点击取消或按 Escape 后清空输入并折叠。
- 点击面板外只折叠，保留尚未提交的输入。

### 2.3 活动折叠态

- 继续使用与空闲折叠态相同的单行结构。
- 左侧状态点表达进行中或暂停，中间显示当前任务名，右侧显示累计计时。
- 进行中状态点使用克制的呼吸动画；暂停状态点保持常亮。
- 不显示暂停、恢复或完成按钮，不出现第二行内容。
- 整个横条均可短按展开或拖动，包括状态点所在区域。

### 2.4 活动展开态

- 上方状态行保留状态点、任务名和计时。
- 下方只显示当前状态可用的控制项：进行中显示暂停和完成，暂停时显示恢复和完成。
- 当前版本不提供活动任务名称编辑区。
- 完成后折叠回空闲状态；点击面板外或按 Escape 时折叠但保留活动任务。
- 输入框和按钮响应自身操作，其余空白区域可拖动窗口。

## 三、材质与层级

- Windows 100% DPI 实机确认共享 L2 的 28% 填充不足以稳定承载深色次级文字；浮窗 fallback 使用局部 80% 表面密度，不修改共享 token 数值。
- 整个浮窗只有一个材质层，统一负责模糊、半透填充、圆角、边缘处理和软阴影。
- 内容层只负责排版和文字，不重复叠加根表面背景、模糊或阴影。
- Windows 透明浮窗不使用 1px 实体外边框；最新实机证据也淘汰了闭合 1px 白色内高光，因为它形成四周可见白线。
- 页面底层在圆角外保持透明，不得从窗口边缘漏出不透明底色。
- 边缘处理不得形成顶部单独白线或四周实体白轮廓；后续高光只有在新的 Windows L3 证据通过后才能恢复。
- 折叠与展开使用同一圆角和材质，不因状态切换出现边缘闪烁。

## 四、状态点

| 状态 | 视觉 | 动画 |
|---|---|---|
| 进行中 | 低饱和薄荷绿 | 约 1.6 秒一次呼吸 |
| 暂停 | 低饱和橙 | 无 |
| 完成 | 浅灰 | 无 |
| 空闲 | 浅灰 | 无 |

状态点位于标题左侧，是行内布局的第一个视觉元素，不定位到右上角。它只作视觉提示，完整状态语义由整条状态行统一提供。

## 五、交互细节

### 5.1 点击与拖动

- 左键按下后的移动距离未超过 4px 时按短按处理；折叠态短按后展开。
- 移动距离达到 4px 时开始窗口拖动，抬起后不再触发展开。
- 折叠态和展开态均支持拖动；输入框和按钮不作为拖动起点。
- 拖动不改变当前任务或折叠状态。

### 5.2 外部折叠

- 展开态在面板外按下鼠标时折叠。
- 面板内部操作不触发外部折叠。
- 输入框失焦本身不作为折叠条件，避免点击按钮时产生竞态。

### 5.3 键盘

| 按键 | 场景 | 行为 |
|---|---|---|
| Enter | 空闲展开态 | 开始非空任务并折叠 |
| Escape | 空闲展开态 | 清空输入并折叠 |
| Escape | 活动展开态 | 折叠并保留任务 |

### 5.4 右键菜单

- 任一状态右键均打开系统原生菜单，不改变折叠状态，也不启动拖动。
- 菜单独立于浮窗内容边界，不被 36px 折叠窗口裁剪。
- 菜单提供显示主窗、自动启动、退出和取消等系统操作。

## 六、焦点

- 启动、显示、快捷键唤起、折叠和展开均不主动抢占其他应用的输入焦点。
- 用户主动点击任务输入框后，输入框正常获得焦点。
- 不通过自动聚焦来实现展开，也不在状态切换后强制恢复焦点。

## 七、可访问性

- 状态行以一个聚合的可访问名称表达任务名和当前计时；状态点本身不重复播报。
- 所有按钮使用明确文字标签，不仅依赖颜色或图标。
- 输入框有可识别的用途提示，开始按钮的禁用状态可被辅助技术识别。
- 所有操作按钮可通过键盘到达，焦点顺序与视觉顺序一致。
- 正文与玻璃背景的对比度满足 WCAG AA；颜色不是区分状态的唯一方式。

## 八、Windows 实机视觉验收

WSL、jsdom 和 happy-dom 只能验证结构与行为，不能替代 Windows 11 实机视觉验收。

### 8.1 基准状态

必须分别记录空闲折叠、空闲展开、活动折叠、活动展开四张基准截图。

### 8.2 DPI

在 100%、125%、150% 三档缩放下检查：

- 物理尺寸和位置稳定；
- 文字、状态点和按钮无错位；
- 折叠内容无裁剪；
- 圆角边缘无黑边或灰边；
- 聚焦与未聚焦状态的材质边缘一致。

### 8.3 通过条件

- 折叠和展开切换不改变宽度、不跳位置、不闪烁材质。
- 活动折叠态严格保持一行。
- 玻璃模糊、半透填充、内高光和软阴影层次清晰，但不形成实体外框。
- 状态点始终位于标题左侧。
- 折叠、展开拖动和系统右键菜单均符合预期。
