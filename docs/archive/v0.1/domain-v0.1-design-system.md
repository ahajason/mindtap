# V0.1 设计系统 — 领域模型

> **性质**: V0.1 阶段无业务实体(timer_session / 数据库 / 跨进程通信 都没引入),本文档是**设计系统领域模型**——把玻璃规范、交互状态、降级规则抽象为可推理的领域层概念。
> **对应 PRD**: `docs/prd/v0.1.0-style-guide-prd.md`
> **对应 Tech**: `docs/tech/v0.1.0-style-guide-tech.md`
> **依据**: 14 个 v0.1-* task 的 "Why" + "What" + V0.1.1/1.2 retro
> **范围**: 设计系统领域规则,不含技术实现
> **不在范围**: 组件接口契约(见 `docs/design/component-format.md`)、视觉数值(见 `docs/design/glass-tokens.md`)

## 1. 玻璃 4 铁律(从 V0.1.2 视觉问题 retro 提炼)

> **状态**: 来源 `docs/research/.../1-design/`(0-originals Apple HIG / Liquid Glass / WWDC25 + 微软 Acrylic + MDN + WCAG),本期设计规范遵循,但具体引用条目**待技术层 + design 层精确化**。

| # | 铁律 | 业务含义 | 违反后果 |
|---|---|---|---|
| 1 | **内容层不堆玻璃** | 用户阅读区(文字 / 表格 / 表单)不允许用最重玻璃等级 | 文字对比度不达 WCAG 4.5:1 |
| 2 | **节制** | 一屏最多 1-2 个重玻璃容器,其余用轻玻璃或实色 | "玻璃感"过载,失去焦点 |
| 3 | **层次清晰** | 玻璃等级要传达信息层级(导航 > 内容 > 装饰),不是装饰 | 用户失去空间感 |
| 4 | **环境融合** | 透明窗口 + 桌面壁纸协同,玻璃颜色随壁纸冷暖微调 | 孤立感,不像原生 macOS app |

## 2. 3 层玻璃等级(领域划分)

> **状态**: 已立项(L1/L2/L3 在 V0.1.1 retro 确定,V0.1.3 deferred 收口)

### 2.1 L1(轻玻璃) — 装饰 / 背景

| 名称 | 值 |
|---|---|
| 适用场景 | 卡片背景 / Sidebar / 装饰面板 |
| 视觉特征 | fill 22% / blur 中 / saturation 中 |
| 反模式 | 不允许做按钮 / 不允许做交互元素底 |
| 实例 | Sidebar 背景、Section 卡片 |

### 2.2 L2(中玻璃) — 容器 / 控件

| 名称 | 值 |
|---|---|
| 适用场景 | 按钮 / 输入框 / 弹窗 / Modal |
| 视觉特征 | fill 28% / blur 高 / saturation 高 |
| 反模式 | 不允许做大面积阅读区底(违反铁律 §1) |
| 实例 | Button / Input / Card |

### 2.3 L3(重玻璃) — 强调 / 浮层

| 名称 | 值 |
|---|---|
| 适用场景 | 浮层 / Dropdown / 通知 / Toast |
| 视觉特征 | fill 36% / blur 高 / saturation 高 / 边框 |
| 反模式 | **不允许做内容层**(用户阅读区不能用) |
| 实例 | Dropdown / Toast / Modal 浮层 |

### 2.4 状态机:玻璃等级选择决策

```
开发者问:这个元素应该用什么玻璃等级?
  │
  ├─ 用户阅读区?(文字 / 表格 / 表单内容)
  │   └─ 用实色 contentContainer,不用玻璃
  │
  ├─ 用户可点击 / 输入?
  │   └─ 用 L2(控件)
  │
  ├─ 浮层 / Dropdown / Toast?
  │   └─ 用 L3
  │
  ├─ 装饰 / 卡片 / Sidebar?
  │   └─ 用 L1
  │
  └─ 不确定?
      └─ 默认 L1,具体反模式由组件格式规范定义
```

## 3. 4 块规范体系(领域概念)

> **状态**: V0.1.0 已落地为主题块 + 样式变量,具体数值见 `docs/design/glass-tokens.md`。本节只描述**领域概念**,不写具体值。

### 3.1 色彩领域

| 名称 | 领域含义 |
|---|---|
| 基底色 | 冷蓝调,92% 不透明度(防穿透) |
| 强调色 | 品牌主色 |
| 文本色 | 主文本 + 次文本 + 弱文本 3 档 |
| 状态色 | success / warning / error / info |

**反模式**:
- ❌ 自创颜色 / 阴影 / 模糊值
- ❌ 用默认色阶替代主题色

### 3.2 玻璃 4 要素领域

| 要素 | 业务含义 |
|---|---|
| fill(填充度) | 玻璃不透明度 |
| blur(模糊半径) | 玻璃模糊半径 |
| saturation(饱和度) | 玻璃饱和度 |
| brightness(亮度) | 玻璃亮度 |

每个等级(L1/L2/L3)有 4 要素值,**4 要素必须协同调整**——只改 fill 不改 blur 会破坏玻璃质感。

### 3.3 圆角 / 间距 / 字号 / 动效领域

| 维度 | 业务规则 |
|---|---|
| 圆角 | button 10px / card 12px / modal 16px / pill 全圆 4 档 |
| 间距 | 阶梯规范(第 5 档 = 20px 而非 24px),不允许魔法数字 |
| 字号 | 全局小号 14px(Button 等控件统一) |
| 动效 | ease-out 缓动 + 150-300ms 时长 |

## 4. focus 3 层模型(领域状态机)

> **状态**: V0.1.1 retro 暴露 focus 状态混乱,V0.1.3 deferred 收口定 3 层模型

### 4.1 Layer 1: Window 焦点

| 状态 | 触发 | 视觉表现 |
|---|---|---|
| `active` | 窗口获焦 | 玻璃 vibrance 完整(fill +0% / blur +0px) |
| `inactive` | 窗口失焦(blur / visibilitychange) | 玻璃 vibrance 降低(fill -8% / blur -6px) |

**业务规则**:
- 监听 3 个事件:窗口获焦、窗口失焦、页面可见性变化
- 写入根元素的"窗口激活"状态属性(激活 / 失焦),样式选择器响应
- 兜底:页面可见性变化 + 5 秒轮询(浏览器失焦事件不触发时)

### 4.2 Layer 2: Navigation 焦点

| 状态 | 触发 | 视觉表现 |
|---|---|---|
| `default` | 鼠标未悬停 | 默认色 |
| `hover` | 鼠标悬停 | 浅色悬停视觉 |
| `active` | 当前路由匹配 | 主色块 |
| `keyboard-focus` | 键盘 Tab 聚焦 | 焦点环 + 主色块 |

**业务规则**:
- **必须用键盘焦点 而非 鼠标焦点**(鼠标点击后焦点环残留违反 macOS 焦点规范)
- active 跟 hover 视觉不冲突(主色块 vs 浅色)

### 4.3 Layer 3: Keyboard 焦点

| 状态 | 触发 | 视觉表现 |
|---|---|---|
| `default` | 鼠标交互 | 无焦点环 |
| `keyboard` | 键盘 Tab / Shift+Tab | 焦点环 + 3 像素偏移 |
| `reduce-transparency` | 系统开启 Reduce Transparency | 4 像素偏移(对比强化) |

**业务规则**:
- Reduce Motion 模式下,焦点环无过渡但环仍可见(无障碍优先)
- 所有交互元素必须有可见的 keyboard 焦点状态

## 5. a11y 降级规则(领域规则)

> **状态**: V0.1.3 deferred 收口,从 macOS 系统 Accessibility > Display 提炼 2 个降级

### 5.1 Reduce Transparency(玻璃降级)

| 名称 | 规则 |
|---|---|
| 触发 | 系统设置 Reduce transparency = reduce |
| 玻璃处理 | 模糊失效,背景 95% 不透明度 |
| focus 处理 | 偏移 +1 像素(对比强化) |
| 不降级 | 旧 macOS 无"减少透明度"系统设置支持 |

### 5.2 Reduce Motion(动效降级)

| 名称 | 规则 |
|---|---|
| 触发 | 系统设置 Reduce motion = reduce |
| 动效处理 | 全部动画 / 过渡时长 → 0.01 毫秒 |
| 滚动处理 | 滚动行为 → 自动 |
| focus 处理 | 焦点环过渡 → 无(但环仍可见) |

**业务规则**:
- 2 个降级可同时触发
- 旧 macOS 无"减少动效"系统设置支持 → 不降级(保留默认体验)

## 6. 拖动 region 规则(领域规则)

> **状态**: V0.1.4 根因 + V0.1.6 fix 沉淀(具体 commit 见 git history)

### 6.1 两层拖动协同

| 层 | 范围 | 职责 |
|---|---|---|
| 原生层 | 窗口背景 | macOS 系统级背景拖动 |
| 浏览器层 | 专用拖动 handle | 浏览器侧拖动区域属性 |

### 6.2 反模式

- ❌ **不要把整窗包成拖动区域**——按钮 / 输入框 / 链接自动取消拖动(非拖动区),整窗包会污染交互
- ❌ **不要在控件上加拖动区域**——控件本身就是交互元素,加拖动会阻断点击
- ✅ **拖动区域只能放专用 handle**(侧栏顶部 + 主区顶部固定条)

### 6.3 决策规则

```
开发者问:这个元素应该加拖动区域吗?
  │
  ├─ 是控件?(按钮 / 输入框 / 链接 / 导航)
  │   └─ 否(避免污染交互)
  │
  ├─ 是空白区但有内容?
  │   └─ 否(避免文字选不中 + 调整大小失效)
  │
  ├─ 是专用标题栏 / 顶部固定条?
  │   └─ 是
  │
  └─ 是侧栏顶部?
      └─ 是
```

## 7. 业务不变量(V0.1 设计系统硬约束)

> **状态**: V0.1.1/1.2 retro + V0.1.3 deferred 收口定

### 7.1 设计规范不变量

1. **玻璃等级只升不降**——L1 < L2 < L3,不允许跨级(例如 L2 不能直接降 L1)
2. **内容层不用玻璃**——用户阅读区永远实色(内容容器)
3. **规范引用单向**——组件 → 规范,规范不引用组件
4. **跨页面一致性**——同一组件跨路由视觉一致(小号按钮在 /button 和 /surface 看起来一样)

### 7.2 focus 不变量

5. **键盘焦点可见**——所有交互元素键盘 Tab 必须可见
6. **鼠标焦点不残留**——鼠标点击不留下焦点环(用键盘焦点可见 而非 鼠标焦点)
7. **窗口失焦不影响焦点环**——失焦后键盘焦点仍在原位,不被重置

### 7.3 a11y 不变量

8. **Reduce Transparency 必须触发**——所有玻璃类名都有对应"减少透明度"降级分支
9. **Reduce Motion 必须触发**——所有动画 / 过渡都有对应"减少动效"降级分支

### 7.4 拖动不变量

10. **拖动区域不污染交互**——按钮 / 输入框 / 链接不在拖动区域内
11. **整窗可拖**——任意空白处按下并拖动窗口跟随
