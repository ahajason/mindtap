# ADR 0012: active 语义 = 「正在被投入」+ 失真确认闭环

- **状态**: ✅ 已采纳
- **日期**: 2026-08-01
- **决策者**: 用户 + Claude Code(grill 对齐)

## 背景

「active(进行中)」这个状态有两种可能语义:

- **含义 A(旧实现)**: 「被启动」——用户点了开始,计时就在跑。active = 一个开关。
- **含义 B(PRD)**: 「正在被投入」——这张卡此刻真实占有用户的时间投入。计时只是度量投入的手段,不是投入本身。

PRD §1.4「计时自动:点开始即累计,切走/空闲/锁屏即停止,不需要用户维护计时的正确性」指向含义 B。但含义 B 隐含「切走即停」,而阶段一没有任何被动信号(窗口监听在阶段二, hooks 在阶段三),V0.2.1 无法精确感知「人是否还在」。

关键矛盾:如果按旧逻辑「active 就计时、用户自己停」,用户忘了停时,时长会无限膨胀——这正是元痛点「台账与现实脱节」。

## 选项

### A: 冷却/晾着展示 = 卡片变暗(被动)
- 优点: 实现简单
- 缺点: **用户可能根本不看浮窗**,变暗的卡片躺在视野边缘,失真被静默——台账照样失真

### B: 冷却/晾着展示 + 跨天停表(时间兜底)
- 优点: 时间兜底防膨胀
- 缺点: 仍是被动展示,失真点不被用户注意

### C: 失真确认闭环(主动询问,方案 C)
- 优点: 失真不再被动呈现,而是**主动询问**;超时暂停 + 待确认窗口,把「这段投入要不要记」的判定权交给用户,台账不虚增也不丢失
- 缺点: 需要确认气泡 UI + 超时逻辑 + 补偿 API(多一块工作量)

## 决策

选了 **C: 失真确认闭环**。

- **active 语义定死为含义 B**「正在被投入」;
- **冷却/晾着 = active 真实性衰减,不是独立状态**(五态不变);
- 失真检测(冷却阈值 2h / 跨天)→ 独立确认气泡「还要继续吗?」→ 5 秒无操作自动暂停(只停不抹)→ 失真窗口标「待确认」→ 用户回来一键[记入]/[丢弃];
- **跨天停表 = 定义**:active 不跨天,启动扫描把跨天 active 退回待办;
- 丢弃「卡片变暗」展示层(被主动询问取代,不做冗余)。

## 反向后果

如果选错了(实际用户确实不响应气泡),失真窗口会积压「待确认」项,引入新的整理成本。但气泡有 5 秒超时 + 跨天兜底,且待确认项可在复盘批量处理,风险可控。未来若气泡打扰度超预期,可退回「变暗 + 时间兜底」的降级模式。
