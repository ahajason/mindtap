## 用户视角变更 (5 行)

1. **折叠态 StatusDot 与标题 baseline 视觉对齐**:之前 V0.2.0.12 把 StatusDot 放回 inline flex 第 1 child 最左,但 StatusDot 8×8 小圆点跟 flex container baseline 对不齐(A-1)
2. **折叠/展开态不再两个 div 切换,改单一 root div 加 `expanded` class**:之前 V0.2.0.12 用 conditional render 切换两棵子树,状态偶发错位(A-2)
3. **右键菜单"自动启动"文案随 autostart 实际状态变**:`已启用 自动启动` ↔ `启用 自动启动`(B-2-1)
4. **原生菜单只在浮窗窗口响应**,主窗快捷键 / 系统托盘不再误触发浮窗菜单(B-2-2)
5. **`onCancel` 拆 `onDismiss` 与 `onClearAndDismiss` 两个语义**:dismiss 仅切回折叠态保留输入;`clear and dismiss` 才真清空 task_title(C-3)

> ⚠️ **C-4 (任务开/完保持展开) 在 V0.2.0.14 被反转**:本 PATCH 试过"任务开 + 任务完成保持展开",user L3 V0.2.0.13 重测发现 race + UX 不顺, V0.2.0.14 改为 active session 时自动折叠。详见 `v0.2.0.14-release-notes.md`。

## 修复的 bug (5 deviation)

| Deviation | 描述 | root cause | 修复路径 | 涉及文件 |
|---|---|---|---|---|
| **A-1** | StatusDot 跟折叠态标题 baseline 不齐, 8px 小圆点视觉偏下 | FoldedBar 是 flex row 但 StatusDot 没用 `align-self` 或 baseline 对齐 | StatusDot 加 `align-self: center` | `src/floating/components/StatusDot.tsx` |
| **A-2** | 折叠/展开偶发不出 / 抖动两棵子树竞争 | conditional render 两棵子树 (`floating-root-folded` + `floating-root-expanded`),状态切换靠 `expanded` boolean 在两个 JSX 块之间切;input blur race 时 `expanded` 状态混乱 | 合并为单一 root div + `floating-root.expanded` class 切换 | `App.tsx` + `ExpandedPanel.tsx` + `StatusDot.tsx` |
| **B-2-1** | "自动启动" 菜单文案永远写"启用 自动启动",autostart 已开时体验不一致 | `menu.rs` `MenuItemBuilder` 写死文字,没读 `app_handle.autolaunch_is_enabled()` | `menu.rs` 根据 `AutostartManager` 当前 state 动态 build text | `src-tauri/src/tray/menu.rs` |
| **B-2-2** | 全局 `on_menu_event` 同时挂到 main + floating window,主窗焦点态触发浮窗菜单回调 | `lib.rs` `.on_menu_event(...)` 闭包内 action 路由不区分 window | action handler 加 `window.label() == "floating"` 守卫,非 floating 直接 log warn 丢弃 | `src-tauri/src/lib.rs` |
| **C-3** | `onCancel` 在"用户失焦"和"用户清空输入"两种场景被合并,导致展开态有时输入框保留有时清空 | `ExpandedPanel` props `onCancel` 单一 closure 调用点同时承载"撤回"和"提交空" | 拆 `onDismiss`(仅切回折叠,保留 draft) + `onClearAndDismiss`(清空 + 折叠) | `src/floating/components/ExpandedPanel.tsx` + `App.tsx` |
