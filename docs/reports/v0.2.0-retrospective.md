## 2. 反模式命名：**"沿用 X 实装"声明 ≠ 已实施**

### 2.1 反模式表现

在 spec / plan / ADR / README 任何文档里写：
> "沿用 V0.1.6 实装"
> "按既有 V0.1.6 sidebar 模式"
> "参考 .archive/ 实装"

然后**实施时**：
- ❌ 没 grep 当前项目代码看 X "实装" 到底是什么
- ❌ 没扫 `.archive/docs/{superpowers,architecture}/` 的**事件清单** + **失败模式**
- ❌ 没在 commit message 写"已 grep V0.1.6 实装是 X，V0.2 实施为 Y"
- ❌ dev 实测硬门被绕过（V0.2 全部 11 个 commit 都没真在 Windows 实测就 commit，靠 push 后用户实测才暴露）

### 2.2 真实案例（V0.2.0）

spec v1.1 §3.1 折叠态：
```
| 拖拽 | OS 原生 drag（沿用 V0.1.6 实装，Windows Tauri WebView2 走 -webkit-app-region: drag + 
        capability core:window:allow-start-dragging，参见 V0.1.6 retro §3.2）| [事实 = V0.1.6 当前代码已落地] |
```

我**真信了**"V0.1.6 当前代码已落地"。但事实：
- V0.1.6 落地的是 `data-tauri-drag-region="deep"`（src/components/layout/Sidebar.tsx:14），**不是** `-webkit-app-region: drag`
- V0.1.6 retro §3.2 已明确说 macOS 走 IPC，Windows 走 `webkit-app-region`，但**项目当前代码用的是 Tauri 2 drag region**
- spec 措辞既不是 V0.1.6 现状，也不是 V0.1.6 retro 教训

### 2.3 防御

**任何 spec / plan 写"沿用 X 实装"前必须：**

1. **grep 当前项目** — 确认 X 实装是什么（不是想象）
   ```bash
   git log --oneline --all -- src/<X 实际位置>
   grep -rnE "<X 关键属性>" src/
   ```
2. **扫 .archive/ 教训** — 不是 .archive/src/ 代码现状，是 .archive/docs/{superpowers,architecture,reports}/ 失败模式 + 调试报告
3. **commit message 写明"已 grep"** — `验证: grep V0.1.6 sidebar.tsx data-tauri-drag-region="deep"; 沿用此模式`
4. **dev 实测硬门** — 按 `dev-verify-before-commit.mdc`，不能合并"待实测" commit

## 4. dev-verify-before-commit.mdc 落实情况

V0.2 实施 11 个 commit，**全部含"待 Windows 端实测"段**：

```
T03 Cargo.toml: 验证 cargo check ... ; Tauri dev 实测: Windows 端 D:\\workspace\\mindtap 跑
T04 tauri.conf: 同上
T08 commands: 同上
T12-T21 UI: 同上
```

按 `no-todo-merge` (V0.1.6 retro lesson 6)：**"commit 不能带'待验证 TODO'字样 merge"**。

但 V0.2 没真拦：
- 11 个 commit 都合并到 develop
- 5 处重蹈中只有 #1 #2 #3 是 Windows 端真暴露后回修
- #4 #5 release notes 已标记"待补"

**根本原因**：WSL 端没有 `npm install` 完整 dev 依赖，**tsc / vitest / 静态 grep 拖动 / 静态 grep CSS 都没在 commit 前跑过**。

应该做的（实际可做）：
- `tsc --noEmit` — WSL 跑过，**但只看了"V0.1.6 dev 依赖错误无关本批"** 没继续
- `grep data-tauri-drag-region src/floating/` — 0.5 秒可跑，**没跑**
- `grep floating-root src/floating/styles/` — 0.5 秒可跑，**没跑**

修复（commit `8872906` + `5cf9c96` 完成后）：
- 写 vitest 时已 mock `getCurrentWindow`，**不需要 WebView2 也能测** component 行为
- WSL 端静态 grep + cargo check + cargo test + clippy + fmt 5 关可覆盖 80% 重蹈风险
- Windows 端实测只负责剩 20% runtime 行为（实际 OS drag / focus / global-shortcut）

## 5. 已沉淀规则（archive-reference-only.mdc 反模式 9）

新增反模式 9："spec 写'沿用 X 实装' 必须 grep X 实装代码 + .archive/ 教训"。

```markdown
### 反模式 9 — spec / plan 写 "沿用 X 实装" 但实施时未 grep X (2026-07-11 V0.2.0 retro)

```text
1. V0.2 spec §3.1 写 "拖拽: 沿用 V0.1.6 实装"
2. 实施时没 grep V0.1.6 sidebar.tsx 看实装是什么
3. 也没扫 .archive/docs/superpowers/plans/2026-06-20-commit-hygiene.md line 1065 "FloatShell V1.5 漏挂 .floating-root 类"
4. commit 时 cargo check + tsc 通过就 push
5. 用户 Windows 实测发现"无法拖动" → 回修 commit 8872906
```

**问题**: "沿用 X 实装"措辞**没经 grep 验证**，与 X 实际状态脱节。V0.2.0 重蹈 5 处 V1.0/V1.5 时代已修 bug（详见 V0.2 retro §1）。

**修复**:
- 任何 spec/plan/ADR 写"沿用 X 实装"前**必须**:
  1. `git log --oneline --all -- src/<X 实际位置>` 看 X 当前代码
  2. `grep -rnE "<X 关键属性>" src/` 看 X 关键字段实际值
  3. 扫 `.archive/docs/{superpowers,architecture,reports}/` 的失败模式 + 调试报告
- commit message 验证段写 "已 grep V0.1.6 sidebar.tsx X=Y; 沿用此模式"
- 不允许 "spec 写 X 沿用 Y 但实施时跳过 grep" 的链路出现
