## 2. 真实根因链（grep 已验证）

### P0-1 折叠→展开 resize（用户实测"点击无反应"）

**根因链**:
1. `App.tsx:89` 折叠态根 div `data-tauri-drag-region="deep"`（V0.2 实施依赖 Tauri 2 attribute）
2. tauri.conf.json:36 floating window `transparent: true` + `decorations: false`
3. `src-tauri/capabilities/default.json:5-7` `"windows": ["main"]`（floating 不在）
4. **Tauri 2 drag-region attribute 依赖 capability per-window 隔离** — floating window 拿不到 `core:window:allow-start-dragging` permission，attribute 不工作
5. 用户点击折叠态 → mousedown 被 attribute 拦截 / 不响应 → setExpanded(true) 不触发 → resize effect 不 fire

**对比 V1.0 (.archive)**:
- V1.0 capability 同样只有 main (`.archive/src-tauri/capabilities/default.json:5`)
- V1.0 **绕开 capability**：`.archive/src/floating/FloatShell.tsx:36-82` 自实现 `onMouseDown` + 4px drag threshold + `dragRef` state + document mousemove/mouseup listener
- V1.0 短按 (dragRef.dragStarted=false) → onToggle() = click 展开
- V1.0 长按超 4px → dragStarted=true → 不触发 onToggle

**修复 (commit 73749be App.tsx)**:
- 删 `data-tauri-drag-region="deep"`，加 `onMouseDown={handleMouseDown}`
- 自实现 `dragRef` state + `handleMouseDown` + `handleMove` + `handleUp` 完整逻辑
- 内 button (ContextMenu 退出 + ExpandedPanel 取消/开始 + ControlRow 暂停/恢复/完成) 加 `data-no-expand` 短路

### P0-2 浮窗无法拖动（用户实测"还是无法拖拽"）

**根因链**:
1. 同 P0-1 根因 1-4 — `data-tauri-drag-region` attribute 不工作
2. V0.2 没扫 V1.0 已有 `useDragLongPress.ts` 长按 + `startDragging()` IPC 实施路径
3. 长按 OS 接管窗口拖拽这条路完全没接

**对比 V1.0**:
- `.archive/src/floating/hooks/useDragLongPress.ts:49` mousedown 300ms timer → `await getCurrentWindow().startDragging()` → Tauri 2 IPC, **不依赖 capability**
- dragRef.draggedRef=true → click 处理器看到不再触发 onClick

**修复 (commit 73749be App.tsx)**:
- handleMouseDown 加 300ms timer → `getCurrentWindow().startDragging()` IPC
- dragRef.dragStarted=true → mouseup 不触发展开

### P0-3 折叠态默认位置（spec §三 3.1 grill 9.5 B = 主屏右下角 -100px）

**根因链**:
1. V0.2 tauri.conf.json floating 无 x/y
2. V0.2 App.tsx 无启动期 setPosition 兜底
3. 浮窗 mount 时位置 = OS 默认（Windows 11 可能 (0,0) 被任务栏遮）

**对比 V1.0**:
- `.archive/src-tauri/src/floating/mod.rs:20,53` Rust 端 `set_position(100, 60)` 兜底（R4 防御）
- `.archive/src/floating/hooks/useWindowPosition.ts:34-97` mount-once useEffect + saved 持久化 + clamp 屏外 + onMoved 持久化

**修复 (commit 73749be App.tsx)**:
- mount-once useEffect (deps: `[]`)
- 读 localStorage `floating-position` + availableMonitors() 校验屏内
- saved 悬空 → 清掉走默认位置 (主屏右下角 -100px, 避 Win 11 任务栏 48px)
- onMoved 持久化新位置

### P0-4 不抢焦策略（spec §九 9.5 = A `WS_EX_NOACTIVATE` vs 实现 = B `set_focusable(false)`）

**根因链**:
1. V0.2 spec v1.1 §三 3.7 写明 `WS_EX_NOACTIVATE` (win32 API, 候选 A)
2. 实施时走 `set_focusable(false)` (Tauri 2 API, 候选 B)
3. **重复设**: tauri.conf.json:40 `focus: false` + lib.rs:51 `set_focusable(false)` (启动期) + App.tsx:43 展开态 setFocusable(true) 覆盖
4. spec 与实现路径分歧，未承认

**对比 V1.0 (.archive)**:
- V1.0 V1.3-e2e-result.md:137 D15: `macOS CanBecomeKeyWindow=false + 跨平台 focus:false` — 直接用 `tauri.conf.json focus: false`，**没有 lib.rs 重复 setFocusable**
- V1.0 macOS 走 NSPanel `CanBecomeKeyWindow=false` (OS 级)

**修复 (commit c008c3c lib.rs + b99667b spec)**:
- lib.rs:50-52 删 (与 tauri.conf.json focus:false 重复)
- 保留 App.tsx setFocusable(true/false) 覆盖 (Tauri 2 API, 等价于 V1.0 macOS CanBecomeKeyWindow)
- spec v1.2 §三 3.7 + §九 9.5 标注"实施路径 = B"

### P0-5 视觉文字白色一片空白（用户实测 + 设计语言不符）

**根因链**:
1. `floating.css:97-101` `:root { color-scheme: dark }` → 浏览器默认 fg = 白色
2. body 无显式 color → fallback 白色
3. **浮窗背景是浅色玻璃**: 折叠态 `.floating-root` `rgba(255,255,255,0.7)` + 展开态 `glass-l3` `var(--glass-fill-3)` = 36%
4. 白色文字 + 浅色玻璃 = 看不见（违反 `glassic-ui-spec.md §八 #4` WCAG AA 4.5:1 强制项）
5. `ExpandedPanel.tsx:94` 按钮 `text-white/70` + `InputBar.tsx:23` 输入框 `text-white` + `ContextMenu.tsx:43` 菜单项 `text-white` — **全白色**！背景浅色 = 看不见

**对比 V1.0 (.archive)**:
- `.archive/src/floating/styles/glass.css:13` `--ink: #1d1d1f` (暗色)
- `.archive/src/floating/styles/glass.css:66` body `color: var(--ink)` (显式声明)
- `.archive/src/floating/styles/focus-block.css:67` `.fold-inner color: #1d1d1f`
- `.archive/src/floating/styles/expand-state.css:17` `.expand-state color: #1d1d1f`
- **全部暗色 + body 显式 color**

**修复 (commit 73749be floating.css + 4 组件)**:
- floating.css:97-101 删 `color-scheme: dark` + body 加 `color: var(--color-text-1)` (= `#1D2939`，与 V1.0 `--ink: #1d1d1f` 等价)
- 4 组件所有 `text-white` / `text-white/70` / `text-white/40` → `text-text-1` / `text-text-2` / `text-text-3` (main `@theme` 暗色三档)
- InputBar `placeholder:text-white/40` → `placeholder:text-text-3`

## 3. 反复犯教训（spec "沿用 V1.0 实装" 必须 grep V1.0 完整路径）

### 教训 1：spec 写"沿用 V0.1.6 实装" ≠ V0.1.6 真有该实装
- V0.2 spec §三 3.1 写 "沿用 V0.1.6 实装，Windows Tauri WebView2 走 `-webkit-app-region: drag`"
- V0.1.6 实装 = `data-tauri-drag-region="deep"`（main window 用），不是 `-webkit-app-region`
- spec 写错 + 没扫 V1.0 完整实装路径 → 反复犯 V1.0 已修过的同款错

### 教训 2：capability per-window 隔离陷阱（V1.0/V0.2 都犯）
- `.archive/src-tauri/capabilities/default.json:5` `"windows": ["main"]`
- `src-tauri/capabilities/default.json:5-7` `"windows": ["main"]`
- **两者同样错** — floating window 不在 windows 数组 → 任何依赖 capability 的 attribute / IPC 都拿不到
- V1.0 早期踩坑后用 Tauri 2 IPC `startDragging()` 绕开
- V0.2 没扫 V1.0 教训 → 重复踩

### 教训 3：drag vs click 冲突（V1.0 完整解决，V0.2 完全没做）
- V1.0 `.archive/src/floating/FloatShell.tsx:36-82` 自实现 onMouseDown + 4px drag threshold + dragRef state + document listener
- V1.0 `.archive/src/floating/FloatShell.test.tsx:24-118` 5 个 drag 测试用例（短按 toggle / 拖动 5px 不 toggle / 拖动 3px 仍 toggle / data-no-expand 短路 / grid-rows 0fr→1fr）
- V0.2 完全没自实现 onMouseDown → 折叠态 root div 依赖 Tauri 2 attribute → 不工作 → click 也不响应

### 教训 4：spec 写"OS 级最稳" 实施走"API 简单"（不承认 = 反模式 9）
- spec v1.1 §九 9.5 = A `WS_EX_NOACTIVATE` (win32 API)
- 实施 = B `set_focusable(false)` (Tauri 2 API)
- spec 与实施分歧 + lib.rs 与 tauri.conf.json 重复设
- **修复**: spec v1.2 改 9.5 = B + 标注 "实施路径 = B" + lib.rs 删重复设

### 教训 5：浅色玻璃 spec 与 V0.1.6 retro 调整冲突（spec 是 single source of truth）
- V0.1.6 retro 故意降 fill 35→22% / shadow 蓝→黑调（"降 fill 让玻璃质感主导"）
- spec v1.1 是 V0.2 立项时拍板的 single source of truth，**V0.1.6 retro 调整没合并到 spec**
- V0.2 实施沿用 V0.1.6 retro 调整（fill 22%/28%/36%）→ 不符合 spec
- **修复**: 沿用 V1.0 glass.css `--ink` 暗色（V1.0 与 spec 同源，文字暗色 + 浅色玻璃 = 可读）
