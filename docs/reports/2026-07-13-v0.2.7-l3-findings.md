### Issue A ❌ P0-9 复活: 右键被抢占 (最严重)

**用户原始描述**:
> "现在右键被抢占，当右键点击的时候变成了折叠和展开的切换，并不是右键菜单。"

**歧义点澄清 — 需要用户确认**:
1. 是**所有状态**下都触发? 还是只有折叠态 / 只有展开态?
2. 期望弹的是哪个菜单:
   - (a) React 渲染的 ContextMenu 组件 (`src/floating/components/ContextMenu.tsx`)
   - (b) OS 原生 context menu (文件/链接/查看源代码 等)
   - (c) 其他
3. "折叠和展开的切换" 具体是: 右键第一次按 → 折叠, 第二次按 → 展开?
4. 是否在 DevTools Console 看到任何 contextmenu event listener log?

**历史脉络 (反模式 13 + P0-9)**:
- **V0.2.5 反模式 13**: Win11 WebView2 transparent 浮窗调 `setFocusable(true)` 会 panic, 严禁调用
- **V0.2.6 P0-9**: commit 6990327 改用原生 `addEventListener("contextmenu", onContextMenuCapture, true)` capture phase, 替代 React 合成事件 `onContextMenu`
- **V0.2.7 fix 范围**: App.tsx:147-184 / :239-247 / tauri.conf.json — **未明显触及右键路径**, 所以 P0-9 修复可能未被 V0.2.7 破坏, 但其他改动可能引入新问题

**假设 root causes (按可能性从高到低)**:

| # | 假设 | 证据方向 |
|---|---|---|
| A1 | 折叠态根 div 的 `onMouseDown` 把右键当成 left button 0 处理, 触发 setExpanded toggle (MouseEvent.button 默认值? listener 没区分 button 字段?) | 读 `src/floating/App.tsx` 折叠态根 div 的 mousedown handler |
| A2 | onContextMenu 仍挂 React 合成事件, V0.2.7 改动覆盖了 P0-9 capture phase 原生 listener (如重写了 useEffect 但没保留 addEventListener cleanup) | 读 App.tsx 看是否有 `addEventListener("contextmenu", ..., true)` 还有 + removeEventListener cleanup |
| A3 | V0.2.7 加的 `try { void dragRef.current.win?.startDragging(); }` 错误处理覆盖了右键路径 | 看 onMouseDown 中右键处理 |
| A4 | WebView2 在 transparent:false 模式下 contextmenu 默认行为被 React root 拦截 (但 WebView2 应不响应合成 preventDefault, 见 P0-9) | DevTools 选中根 div → Elements → 检查 event listeners panel |
| A5 | `data-testid="floating-root-folded"` 这个 div 本身绑了 onClick 或 onMouseDown 而没有区分 button 字段 | grep App.tsx 看 onMouseDown 处理 |

**排查方向** (建议按顺序):

```bash
# 1. 在 D:\ 端用 DevTools (F12) 看 contextmenu event:
#    选中 .floating-root, Elements panel → Event Listeners tab → 找 contextmenu
#    预期: 应有 1 个 capture phase 原生 listener (P0-9 修的), 不应有 onContextMenu React 合成

# 2. 在 WSL 端读源码
grep -n "onContextMenu" src/floating/App.tsx
grep -n "addEventListener.*contextmenu" src/floating/App.tsx
grep -n "removeEventListener.*contextmenu" src/floating/App.tsx
grep -n "onMouseDown" src/floating/App.tsx

# 3. 检查 mousedown handler 是否区分 button
grep -n "e\.button\|event\.button" src/floating/App.tsx
# 缺: 大概率未区分 → A1 假设成立
```

**Pass 判定 (修好后)**:
- 右键浮动 → 弹 ContextMenu 组件 (含 "显示主窗" 等按钮)
- 左键短按 → 折叠↔展开切换 (现状)
- 长按拖动 → 拖窗 (现状)

### Issue B ⚠️ P0-1: 呼吸灯错位 (StatusDot 时有时无, 仅右上漏一部分)

**用户原始描述**:
> "呼吸灯错位，好像有时候会出现有时候消失，呼吸灯好像跑到了右上角仅漏出一部分。"

**歧义点澄清 — 需要用户确认**:
1. "呼吸灯" = `src/floating/components/StatusDot.tsx` 渲染的右上角小圆点? (verify yes by Dot test status)
2. "错位" 是指:
   - (a) 位置偏了 (应该在 -top-0.5 -right-0.5 内部)
   - (b) 大小变了 (小于预期)
   - (c) 多闪几次突然消失
3. "有时出现有时消失" 模式:
   - (a) 跟展开/折叠状态切换有关? 还是独立的?
   - (b) 启动后稳定存在? 还是从一开始就闪?
   - (c) 时间规律 (每隔 N 秒闪一下)
4. "仅漏出一部分" — 漏出的是哪边 (上 / 右 / 整个圆环切 1/4 / 切 1/2)?
5. 仅折叠态有, 还是展开态也有? (折叠态才显示呼吸灯的设计, 但如果是 absolute 定位偏了, 可能折叠态显示残影)

**假设 root causes (按可能性从高到低)**:

| # | 假设 | 证据方向 |
|---|---|---|
| B1 | 父容器 `.floating-root` `overflow: hidden` + 子 dot absolute 定位 -top-0.5 -right-0.5 → 圆点被父容器裁掉 1 半 | DevTools 选中 dot, 看 box, 看 .floating-root computed overflow |
| B2 | dot 用了 `animate-pulse-dot` keyframes scale 0.8→1.0, 起始 transform 让 absolute 位置偏 | Chrome DevTools Animations panel 看 dot 的 keyframe |
| B3 | 折叠态根 div padding/border 变化导致 dot 的 `right` 参照变了 | 切 expanded 时看 dot box 是否同步变 |
| B4 | dot 上同时有 `aria-hidden` + `transition-opacity`, 切换 expanded 时 transition 中间帧 opacity=0 | App.tsx 折叠态 / 展开态 dot 是否 unmount |
| B5 | backdrop-filter / glass-l1/l2/l3 渲染顺序导致 dot 被 z-index 低的层盖住 | DevTools Layers panel 看 z-index 栈 |

**排查方向**:

**D:\ 端 DevTools 检查**:
- 折叠态下选中 dot → Computed → box, transform, opacity, animation

## 三、Bug 5 cosmetic 瑕疵 (用户说"先标记完成, 后续顺手修复")
