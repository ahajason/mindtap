## 1. 真根因排查（V0.2.5 6 P0 全部一次到位）

### P0-A: 展开闪退真根因 (Win 11 WebView2 浮窗 `setFocusable(true)` panic)

**根因链**:
1. V0.2.4 commit 90ecc71 改 tauri.conf.json floating `transparent: true` → `transparent: false + resizable: true`
2. App.tsx useEffect 展开时调 `await win.setSize(360, 280)` + `await win.setFocusable(true)`
3. tauri.conf.json floating `focus: false` 启动期, webview 不能 receive focus events
4. **Tauri 2 实际在 Win 11 WebView2 浮窗 (`focus: false` 启动 + `setFocusable(true)` 切换) 触发 webview 内部错误 → 整个 webview panic 闪退**
5. 5 个 patch (V0.2.0/V0.2.1/V0.2.2/V0.2.3/V0.2.4) 都漏改这条根因 = spec §三 3.7 写错 (`setFocusable(true)` 覆盖路径 Win 11 WebView2 实际不 work)

**修复** (V0.2.5 commit df8c252):
- App.tsx useEffect 展开/折叠 useEffect **删 `setFocusable(true/false)` 调用** (沿用 V1.0 V1.3-e2e-result.md:137 D15 跨平台 focus:false 路径: tauri.conf.json focus:false + 永不 setFocusable)
- 浮窗始终 `focus: false` = 不抢 IDE 焦点 (V0.1.6 retro + V0.2.0 retro §1 #2 + V0.2.1 retro 反模式 9 沿用)
- spec v1.3 §三 3.7 写 "实施路径 = B (Tauri 2 set_focusable)" 是错的, V0.2.5 沿用 V1.0 D15 实际: tauri.conf focus:false 一致
- spec v1.5 同步修订 §三 3.7 标注 "V0.2.5 patch 改 spec 实施路径 = V1.0 D15"

### P0-B: 报错没有 message 提示 (lib.rs `eprintln!` 改 `tauri-plugin-dialog` 弹 message box)

**根因链**:
1. V0.2.4 commit 90ecc71 改 lib.rs graceful is_err 改用 `eprintln!` (stderr)
2. **`eprintln!` 写入 stderr, Tauri 2 应用没有 console 终端, stderr 写到日志文件, user 看不到**
3. 即使 Tauri 2 启动时 dump stderr, user 实测看到 "快捷键还是无效" = 进程没死但 user 不知道

**修复** (V0.2.5 commit df8c252):
- 加 tauri-plugin-dialog 依赖 (Cargo.toml line 21 + package.json dependencies `@tauri-apps/plugin-dialog: ^2`)
- lib.rs plugin init + register + db init 失败时 调 `app.dialog().message(...).title(...).show(...)` 弹 message box (user 看到)
- plugin init 失败: "全局快捷键插件初始化失败, 浮窗快捷键可能无效。"
- register 失败: "Ctrl+Shift+Space 已被其他应用占用, 浮窗无法用快捷键显示/隐藏。\n\n建议: 在系统设置里关闭其他应用(如中文输入法)的全局快捷键..."
- db init 失败: "数据库初始化失败: {err}\n\n应用无法启动。请删除 %APPDATA%\\com.mindtap.desktop\\projects.db 后重试。"

### P0-C: 仍然向上弹出 (V0.2.4 transparent:false 后 webview 真正 resize 但 React 渲染未对齐)

**根因**:
- V0.2.4 commit 90ecc71 改 `transparent: false + resizable: true` 让 webview setSize 真正 work
- App.tsx useEffect 展开 `setPosition pos.y` (折叠态 y 不变, 下方展开) ✅
- React ExpandedPanel 渲染 360x280 内容 ✅
- 浮窗根 div 高度 36 (折叠态) → setSize 后高度 280 (展开态)
- **理论上"向下展开"**, 但 user 实测"仍然向上" 可能是 user 没重 build (V0.2.4 commit 90ecc71 transparent:false 实际生效需要 build)

**修复** (V0.2.5 commit df8c252, 完整沿用):
- App.tsx useEffect 展开 `await win.setSize(new LogicalSize(EXPANDED_W, EXPANDED_H))` 在 setPosition 之前 (沿用 V1.0 macOS 路径)
- React 内部 用 `align-items: stretch` 折叠态, 展开态 `align-items: stretch` + `padding: 12px 14px` 让内容从顶部开始
- 已沿用 V0.2.3 commit 30eec1d 改 + V0.2.5 完整沿用

### P0-D: 仍然需要双击展开 (React 19 strict mode useEffect deps [] 双调用)

**根因**:
- App.tsx useEffect deps [] 文档监听器 (handleMove + handleUp)
- React 19 strict mode dev 双调用 useEffect: mount → cleanup → re-mount
- 每次 mount addEventListener, cleanup removeEventListener, 最终 1 个 listener
- **但** user 实测双击 = 真实可能根因: tauri.conf.json `transparent: true` (V0.2.4 commit 90ecc71 之前) 浮窗 transparent, webview 不 resize, React 渲染 ExpandedPanel 360x280 在 320x36 webview 内 截断看上去"点击没响应" (实际响应了但视觉错位)
- V0.2.5 改 transparent:false + resizable:true → webview 真正 resize 到 360x280 → 视觉"向下展开"

**修复** (V0.2.5 commit df8c252, 完整沿用):
- App.tsx useEffect deps [] 文档监听器改用 useRef 存 handler + onMouseMove/onMouseUp 闭包 (避免 stale closure)
- const onMouseMove = (e: MouseEvent) => {...}; const onMouseUp = () => {...}
- React 19 strict mode 双调用也安全 (ref 总是最新值, 闭包每次创建新引用)

### P0-E: 没有状态指示的呼吸灯 (StatusDot 没 pulse 动画)

**根因**:
- V0.2.4 commit 90ecc71 + V0.2.3 commit 30eec1d 改 [V0.2.0 误导] StatusDot 右上角 absolute + ring + bg-emerald-400(本就是 V0.2.x 误改,V1.0 archive StatusDot = inline-block flex 第 1 child)
- 但**没 pulse 动画** — spec §三 3.1 写 "[V0.2.0 误导] 状态指示 | 折叠态右上角小圆点 (active=绿 / paused=橙 / completed=灰)" 但没写 "呼吸"(注:V1.0 archive StatusDot = 最左 inline-block flex 第 1 child), .archive focus-block.css line 80 有 `@keyframes pulse 1.6s ease-in-out infinite`

**修复** (V0.2.5 commit df8c252):
- floating.css 加 `@keyframes pulse-dot` (沿用 .archive focus-block.css 1.6s ease-in-out) + `.animate-pulse-dot` utility
- StatusDot 改 `isPulsing = status === 'active'`, className 拼 `animate-pulse-dot` if isPulsing

### P0-F: 多了黑边框 (.glass-l1/l2/l3 utility 内嵌 border 1px solid 在 transparent 浮窗)

**根因**:
- V0.2.0 retro + V0.2.1 retro 改 floating.css 加 `.glass-l1/l2/l3` utility with `border: 1px solid`
- FoldedBar 用 `glass-l2` className, ExpandedPanel 用 `glass-l3` className
- V0.2.5 patch 改 tauri.conf.json transparent:false, 浮窗不再 transparent, 但 border 1px 仍 visible

**修复** (V0.2.5 commit df8c252):
- floating.css `.glass-l1/l2/l3` utility 改 `border: 0` (沿用 V1.0 .archive/floating.css 简洁模式)
- FoldedBar 完全不用 glass-l2, 改 inline style (background rgba(255,255,255,0.45) + boxShadow + backdrop-blur-md)
- ExpandedPanel 完全不用 glass-l3, 改 inline style PANEL_STYLE (background rgba(255,255,255,0.6) + backdropFilter + boxShadow)
- 全部视觉走 spec §三 3.1 + glassic-ui-spec §二 L1/L3 体系 (35%/50% fill + 蓝调 shadow), 不依赖 .glass-l1/l2/l3 utility
