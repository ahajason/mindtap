## 2. 5 bug 真根因 → fix 完整对照 (本版主成果)

### Bug 1: `act()` 函数无 try/catch → 闪退
**真根因**: `src/floating/App.tsx:239-247` 的 `async function act` 内 3 个 `await` 没用 try/catch, 任一 invoke reject → unhandled rejection → React 18 error boundary → 整个 tree unmount → WebView2 浮窗"闪退"
**Fix**: 包 try/catch + catch 内 `console.error("[act:${action}] failed", err)` (反模式 13 错误可见性)
**L1 验证**: `App.fix.test.tsx:15-32` (2 tests) — act 函数体内含 try/catch + catch 块调 console.error
**L3 验证**: 用户实测"目前没问题"
**真错判定**: ✅ 真修

### Bug 2: 缺 `win.startDragging()` IPC → 拖动完全失效
**真根因**: `src/floating/App.tsx:147-184` 的 `onMouseMove` 内, `dragStarted=true` 后**没有调用** `win?.startDragging()` 让 OS 开始拖窗
**Fix**: line 181 加 `try { void dragRef.current.win?.startDragging(); } catch (err) { console.error("[drag] startDragging failed", err); }`
**历史根脉**: 反模式 15 — V0.2.6 commit `48f4dbd` "修了拖动沿用 useDragLongPress.ts:49 startDragging" 实际**完全没改**, 直到 V0.2.7 4 月后才真改
**L1 验证**: `App.fix.test.tsx:34-52` (line-aware grep, 排除注释行, 唯一非注释命中 line 181)
**L3 验证**: 用户实测"已经修复" — 反模式 15 防御关键测试
**真错判定**: ✅ 真修

### Bug 3: tauri.conf.json floating 段硬编码 x:1500 y:920 → 多屏错位
**真根因**: `src-tauri/tauri.conf.json` floating 段 `x:1500, y:920` 强制浮窗出生在那个绝对位置, 4K/副屏/小屏启动看不见
**Fix**: 删 `x` 和 `y` 字段 (允许 OS 用 setDefaultAtTopRight 计算)
**历史根脉**: 反模式 14 — V0.2.5 commit `1b162eb` "删硬编码" 实际没删, V0.2.6 `48f4dbd` 又"删" 没删, 直到 V0.2.7 第三次才真删
**L1 验证**: `App.fix.test.tsx:54-68` (2 tests) — floating 段不含 `^\s*"x": -?\d+` / `^\s*"y": -?\d+`
**L3 验证**: 用户实测"目前没有发现问题"
**真错判定**: ✅ 真修

### Bug 4: resize useEffect await 之间无 cancelled 检查 → 串行 IPC race
**真根因**: `src/floating/App.tsx:47-72` 的 `useEffect [expanded]` 串行调 `await win.outerPosition() / setSize() / setPosition()` 4 步, 但只在 useEffect 开头 1 处 `if (cancelled) return`, **await 之间无检查**
**场景**: 用户高频点击折叠态 → 在 await setSize 中途 expanded 已变 false → 继续 await setPosition → 状态错乱 (尺寸是 expanded 但 expanded=false)
**Fix**: 每个 await 后立即 `if (cancelled) return` (line 47-72, 4+ 处 cancelled 检查)
**L1 验证**: `App.fix.test.tsx:71-98` (2 tests) — cancelled flag ≥ 4 处 + 每个 await 后立即有检查
**L3 验证**: 用户实测"目前没问题"
**真错判定**: ✅ 真修

### Bug 5: 展开 setPosition 偏移 -20px → 贴右边缘截断
**真根因**: 公式 `Math.round((FOLDED_W - EXPANDED_W) / 2)` = -20 偏移, 把 x 减 20; 浮窗拖到右上角后再展开 → x = 1584 → 1564 (-20), 右边溢 4px  <!-- [V0.2.0 误导] -->
**Fix**: 删公式, `setPosition(new PhysicalPosition(pos.x, pos.y))` 直接用 pos.x
**L1 验证**: `App.fix.test.tsx:100-114` (2 tests) — 公式不存在 + setPosition 用 `pos.x, pos.y`
**L3 验证**: 用户实测"已修, 但与折叠态不是等宽, 没有下拉动画, 先标记完成"
**真错判定**: ✅ 主流程真修 (cosmetic 见 §四)

- V0.2.6 33 commit 中 14 个有 claim/实际不一致 (见 v0.2.6-final-fix-retrospective §2)
- 浮窗 5 bug 中 Bug 2/3 是直接复发了反模式 15 — "修了" 实际没修
- **V0.2.7 防御**: L2 反模式 15 grep (commit claim → grep 代码), 见 `docs/plans/2026-07-13-v0.2.7-test-verification-plan.md` §二

### 反模式 16 (NEW): 测试断言只覆盖字面包含而非行为生效
**双重复发案例** (极其重要):
- **来自外部**: `App.test.tsx:115-122` 拖动测试只断言"不展开", 漏断"调了 startDragging" → V0.2.5/V0.2.6 反复修都漏改的真根因之一
- **V0.2.7 自己复发 (2026-07-13 self-audit)**: 原 `App.fix.test.tsx` Bug 2 #1 正则 `/win\.startDragging\s*\(\s*\)/` 命中**注释行** (line 176: `// V0.2.7 修: 4px 阈值满足后调 win.startDragging()`), 没命中**真实调用行** (line 181: `dragRef.current.win?.startDragging();`)
  - 后果: 即使代码里把 `win?.startDragging()` 调用删了, 测试照样 PASS
  - 修法: `countStartDraggingCalls()` 逐行扫描, 排除 `//` 和 `*` 开头的行, 再断言剩余行 ≥ 1
  - 落地 commit: `5700860` + memory `V0.2.7 self-audit` 段

**铁律**:
- 写"源码 grep + regex 断言"型测试时, **永远排除注释行** (注释行里可以提到任何函数名, 误命中风险 100%)
- 优先写行为断言 `expect(win.startDragging).toHaveBeenCalled()`, 不要写源码字面包含断言
