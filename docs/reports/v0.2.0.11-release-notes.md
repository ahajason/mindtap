## 用户视角摘要(5 行)

1. **右键折叠态能弹 ContextMenu**(显示主窗 / 退出);之前 `top:-84` 菜单跑到 viewport 外看不见
2. **[V0.2.0 误导] 呼吸灯(状态点)在浮窗右上角内**,不再穿透到 viewport 角落错位 4px(注:V1.0 archive StatusDot = 最左 inline-block flex 第 1 child,本就是正确的,所谓"右上角错位"是 V0.2.x 误导下的伪问题)
3. **黑边(focus 后也)消失**:`tauri.conf.json` floating 段开启 `transparent: true` + 显式 `backgroundColor: "#00000000"`,WebView2 半透明合成不再出灰色描边
4. **浮窗不再有 transition 误匹配**:`prefers-reduced-motion` 媒体查询移除,即使系统偏好 reduce-motion 也不会误关(本来就没动画)
5. D:\ 端需 Ctrl+C 重启 `scripts\dev.bat` 才能看到 C transparent 效果(WebView2 透明需重启)

## 技术摘要(开发者)

### A — ContextMenu 定位 + button guard + 展开态渲染

- [V0.2.0 误导] `ContextMenu.tsx`(HTML React):加 `clampToViewport()` 函数,`MENU_W=144 / MENU_H=80 / VIEWPORT_MARGIN=4` 常数,做 viewport 双向 clamp(V0.2.0.12 已删 HTML 改 V1.0 archive Rust 原生 Tauri Menu)
- `App.tsx`:`onContextMenuCapture` 加 `if (e.button !== 2) return;` 守卫(左/中键不弹菜单)
- [V0.2.0 误导] `App.tsx`:ContextMenu 渲染从折叠态 JSX 移到外层 Fragment(折叠 + 展开态共用)(V0.2.0.12 改为外层调 `show_floating_context_menu` IPC)

### B — `.floating-root` 加 `position: relative`

- [V0.2.0 误导] `floating.css` `.floating-root` 块加 `position: relative;` 作为首条声明,让 StatusDot `absolute top-1 right-1` 找根 div 当祖先(V0.2.0.12 改回 V1.0 archive: StatusDot inline-block flex 第 1 child,不需要 relative)
- [V0.2.0 误导] `StatusDot.tsx` 注释纠错:V0.2.0.7 改 `top-1 right-1` 是必要非充分,真正 fix 是根 div 加 relative(V0.2.0.12 改回 V1.0 archive inline-block flex 第 1 child,V0.2.0.7 改类名本就误导)

### C — tauri.conf.json floating transparent + backgroundColor

- `tauri.conf.json` floating 段:`transparent: false` → `true` + 加 `backgroundColor: "#00000000"`
- `App.test.tsx` V0.2.6 旧反向 lock-in describe(`transparent:false`)替换为 V0.2.0.11 锁住(`transparent:true` + `backgroundColor` + `resizable:true` 保留)

### D — 移除 transition + prefers-reduced-motion

- `floating.css`:删 `.floating-root` 块 `transition: width 200ms ease-out, ...` 行 + 整个 `@media (prefers-reduced-motion: reduce) { .floating-root { transition: none } }` 块
- `App.fix.test.tsx`:删 V0.2.0.9 Bug 5 cosmetic describe(4 it)+ 加 V0.2.0.11 D 锁住(3 it)
