# V0.3.0 平台原生动态材质 — 设计契约

> **定位**：定义浮窗在动态材质验证中的视觉边界、状态连续性和可访问性。四状态内容与窗口交互沿用 V0.2.0 设计契约；本文件不定义主窗口或全局主题。

## 一、视觉目标

浮窗是桌面上的紧凑控制面，而非独立的大面积内容卡片。动态材质应当让其表面随身后环境表现出可感知的层次，同时为计时、任务名和操作保留稳定的阅读对比。

“更透明”“更亮”或“像某一平台名称”都不是通过标准。视觉成功必须同时满足：

1. 后方环境层次可感知；
2. 内容可读；
3. 圆角和边缘连续；
4. 在状态和焦点切换中稳定；
5. 不干扰已有窗口交互。

## 二、固定结构与状态连续性

- 空闲折叠、空闲展开、活动折叠、活动展开继续共用同一个浮窗容器；
- 折叠状态仍是一条 36px 的单行状态条，展开只在状态条下增加内容；
- 折叠、展开、拖动和焦点变化不创建第二个视觉容器，也不触发材质重新选择；
- 动态材质只影响容器表面，不改变状态点、标题、计时、输入框和按钮的层级、可见性或可访问名称；
- 平台效果不可用时，视觉可降级为既有基础表面，但浮窗形状、内容和交互不变。

## 三、材质层次

### 3.1 原生生产方案

当原生候选被选为生产方案时，它负责环境采样和平台色调。Web 内容层保持透明、圆角连续且不追加第二层模糊、半透明填充或阴影；否则原生与网页材质叠加会导致泛灰、边缘断裂或状态切换闪烁。

### 3.2 基础表面

基础表面只承担可读的网页底面：内容背景可读、圆角完整和边缘稳定。它不应被描述为已经采样桌面环境，也不应伪造原生动态材质。

基础表面沿用既有共享玻璃规范的模糊与阴影 token，并使用浮窗局部 80% 白色表面密度保证复杂背景下的可读性，不修改共享 token。80% 是首轮安全基线：在最坏纯黑背景上混合后，次级文字 `#475467` 的理论对比度约为 4.79:1；它仍须通过 Windows 100% 实机复验，未通过时只调整该局部密度。透明窗口仍遵守：无实体外边框、圆角外页面透明，边缘不得形成顶部独立白线或四周实体白轮廓。

### 3.3 替代视觉方案

替代视觉方案只在完成准入和证据比较后出现。即使被采用，也只作为浮窗表面的一条路径；其内部失败时只可降级到基础表面，不显示错误面板、选择控件或额外提示。

## 四、运行期行为

- 启动时一次性确定当前运行的表面；
- 折叠、展开、拖动、焦点切换与 DPI 改变期间不重新探测或切换；
- 系统要求减少透明效果或减少动画时，直接显示基础表面；
- 替代视觉方案在启动或显示时失败时，单向切换到基础表面并保持到退出；
- 用户看不到材质选择、状态提示或恢复按钮。

## 五、视觉淘汰信号

候选在下列任意信号出现时不通过：

- 边缘出现黑边、灰边、漏底、顶部白线、圆角中断或实体外框；
- 折叠/展开、拖动、焦点切换、窗口大小变化或 DPI 改变时，材质闪烁、跳位或裁剪；
- 表面影响文字与控件可读性，或产生可见卡顿与输入延迟；
- 对照不同背景后仍只呈现扁平、泛灰的静态表面。

## 六、可访问性与系统偏好

- 材质变化不能是状态的唯一表达；计时、任务和操作仍以文字和语义暴露；
- 正文与表面的对比度必须保持 V0.2.0 的可读标准；
- 减少透明和减少动画不是失败提示，而是正常的、无额外干扰的 fallback 路径；
- 焦点和非焦点状态均不能因为材质而降低内容可辨识度或破坏圆角边缘。

## 七、Windows L3 视觉矩阵

每个候选和最终基础表面均按下表观察：

| 维度 | 必测条件 | 观察点 |
|---|---|---|
| 背景 | 浅色、深色、高对比或纹理 | 环境层次、可读性、泛灰或漏底 |
| 窗口状态 | 空闲/活动 × 折叠/展开 | 容器连续、内容不裁剪、无闪烁 |
| 焦点 | 聚焦、非聚焦 | 边缘一致、文字清晰、无白线 |
| 缩放 | 100%、125%、150% | 圆角、位置、边缘、内容几何 |
| 操作 | 拖动、展开/折叠、resize、右键菜单 | 位置稳定、手感、原生菜单与不抢焦 |

每次实机验收必须同时记录候选名称、Windows 版本、显示运行环境、缩放档位、背景类型和截图/录屏位置。没有这组上下文，截图不能作为候选选择证据。
