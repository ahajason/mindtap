# V0.2.1 工作台账核心 — 设计 spec

> **定位**：浮窗「捕获 + 并行任务条 + 收件箱整理」的视觉、交互、可访问性设计契约。玻璃参数只引用共享规范，不在此重复定义。
> **对应 Domain**：`docs/domain/v0.2.1-workbench-core-domain.md`
> **对应 Tech**：`docs/tech/v0.2.1-workbench-core-tech.md`
> **术语**：`UBIQUITOUS_LANGUAGE.md`(捕获/保存/开始/暂停/进行中)

## 一、屏幕与状态

### 1.1 屏幕列表

| 屏幕 | 载体 | 触发 |
|---|---|---|
| **折叠条** | 浮窗 360×36 | 常驻(滚动展示并行进行中卡) |
| **新增面板（compose）** | 浮窗展开(输入专用) | 折叠条「+」/ 全局快捷键 |
| **并行列表（list）** | 浮窗展开(卡片列表) | 折叠条主体点击 |
| **失真确认气泡** | 独立小窗 280×80 | 失真检测触发 |

### 1.2 状态列表

| 状态 | 触发条件 | 视觉差异 |
|---|---|---|
| **折叠态·无活动** | 无进行中 | 状态点灰 +「收件箱 N · [+]」 |
| **折叠态·有活动** | 有进行中 | **滚动展示并行卡**(内容+计时),每 2-3 秒轮换;有「+N」指示其余 |
| **折叠态·待确认** | 有待确认失真窗口 | 折叠条上出现小圆点「待确认 N」(ADR-0012) |
| **新增面板** | 折叠条「+」/ 快捷键 | 单输入框 + **[保存] [开始]** 两按钮 |
| **并行列表** | 折叠条主体点击 | 进行中卡 + 待办 + 收件箱项(各自带动作) |
| **失真气泡** | 冷却/跨天触发 | 独立小窗,「写代码 还在进行中,还要继续吗?」[继续] [暂停] |

## 二、组件契约

### 2.1 折叠条（复用既有 FoldedBar + 滚动 + 「+」）

**职责**：常驻单行——并行进行中卡滚动展示 + 捕获入口。
**Props**（语义级）：
- 进行中卡列表（滚动展示）/ 收件箱数 / 待确认数 / 捕获入口
**视觉规范**：
- glass 等级：沿用既有折叠条（玻璃表面）
- 待确认小圆点：新控件，位置在右侧计时旁，用状态点同款样式但不同色（如琥珀色），不新增玻璃层
- **滚动展示**：多 active 时每 2-3 秒轮换显示一张进行中卡（内容 + 滚动计时）；「+N」指示其余并行卡
**交互状态**：
- **主体点击**（任务名/计时区）→ 进入并行列表
- **「+」点击** → 进入新增面板（捕获入口，不嵌套在列表内）
- 无 active 时 → 显示「收件箱 N · [+]」
**a11y**：
- role: status；aria-label 含当前进行中内容 + 并行数 + 收件箱数 + 待确认数

### 2.2 新增面板（compose，改造既有 ExpandedPanel）

**职责**：捕获输入专用，无卡片列表。
**Props**（语义级）：
- 输入值 / 变更回调 / 保存提交 / 开始提交 / 取消 / 上限 / 提交中
**视觉规范**：
- 输入框沿用既有（占位「当前在做什么」）
- **两按钮**：「保存」（主，primary）+「开始」（次）——保存进收件箱（不开始），开始直接投入计时
- 输入为空时两按钮均禁用
**交互状态**：
- **回车 → 保存**（进收件箱 + 收起 + 焦点归还，PRD 1.1 默认主路径）
- **Tab → 开始 → 回车** → 直接开始计时（键盘优先）
- **取消 / Esc → 回落列表**（从列表进面板时）或收起（从折叠条进面板时），保持页面连贯
- 点面板外 → 只折叠保留输入
- 不显示卡片列表、历史下拉（历史复用已有存量，保留）
**a11y**：
- 输入框自动聚焦；两按钮各自 aria-label（保存 / 开始）；回车默认保存

### 2.3 任务卡（新 TaskCard）

**职责**：一张并行任务卡，四要素直接显示。
**Props**（语义级）：
- 内容 / 累计时长（实时滚动）/ 冷却深浅 / 进度备注 / 来源（manual）
- 收件箱项：额外「开始」按钮
- 进行中卡：点击「开始」= **进入并行进行中**(不暂停其他卡) + 「暂停」按钮(主动暂停退回待办)
**视觉规范**：
- glass 等级：卡片落非玻璃背景上（Liquid Glass 铁律——内容必须在非玻璃背景上）
- 冷却深浅：用透明度表达失真档位（活跃 100% / 冷却 65% / 晾着 40%），不新增控件
- 进度备注直接显示在卡上，不点开
**交互状态**：
- 卡片 hover → 略提亮；点击卡片区 = 开始（进入并行进行中）；收件箱项有「开始」按钮；进行中卡有「暂停」按钮（手动暂停退回待办）
**a11y**：
- role: button（可点击开始）；每卡 aria-label 含内容 + 累计时长 + 冷却状态 + 可暂停

### 2.4 失真确认气泡（新 Bubble）

**职责**：失真任务「还在进行中,还要继续吗?」主动询问。
**Props**（语义级）：
- 任务内容 / 待确认时长 / 确认回调（继续/暂停）
**视觉规范**：
- 独立小窗 280×80，玻璃拟态（透明 + 模糊 + 无装饰），延续 Liquid Glass
- 位置：屏幕右下角（避让右上角浮窗）
- 层级最高，不抢键盘焦点
**交互状态**：
- 5 秒无操作 → 自动暂停（只停不抹）；气泡转入「待确认」
- 用户回来 → 看到「刚才这 X 时间要计入吗?」[记入] [丢弃]
**a11y**：
- 气泡不抢焦点；两按钮可键盘操作；aria-live 提示

## 三、交互细节

### 3.1 全局快捷键捕获

**触发**：Ctrl+Shift+Space（沿用既有,仅改造行为）
**动效**：浮窗展开 + 输入框聚焦（不抢原窗口焦点,仅临时获得输入权）
**响应**：输入 → 回车 → 保存进收件箱 → 浮窗收起 → 焦点归还原窗口
**约束**：空内容不保存;Esc 取消;连续捕获 10 条不打断输入流

### 3.2 并行任务条（PRD 1.2）

**触发**：浮窗展开
**响应**：显示全部进行中卡 + 收件箱项;每卡四要素直接显示;点某卡「开始」→ 该卡进入进行中,其他进行中卡保持并行计时（多卡并行）
**约束**：超过 5 个进行中 → 浮窗轻提示「在推进的事有点多」(不阻止)

### 3.3 失真确认闭环（ADR-0012）

**触发**：冷却 2h 无更新 / 跨天
**响应**：独立气泡「写代码 还在进行中,还要继续吗?」[继续] [暂停] → 5 秒无操作自动暂停 → 气泡转入「待确认」 → 用户回来 [记入] [丢弃]
**动效**：气泡 200ms 淡入（不抢焦点）；超时暂停后气泡平稳过渡为「待确认」态
**约束**：计时只停不抹;失真窗口待确认;判定权在用户

### 3.4 重复捕获轻提示

**触发**：捕获时检测到同名已有卡
**响应**：浮窗内极轻视觉标识（如同名小圆点），不打断输入流
**约束**：不自动合并;判断交还用户
