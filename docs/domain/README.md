# L1 Domain — 领域模型(模板)

> **本文件夹**: `docs/domain/`
> **职责**: 业务实体(概念,不是表)/ 状态机 / 用户流程 / 业务不变量(用业务语言)/ 业务级 ADR
> **严禁出现**: 表名、字段类型、SQL 语句、IPC 命令、文件路径

## 一、命名

```
docs/domain/
├── v<MAJOR>.<MINOR>-domain-model.md        # 领域模型主体

    └── <NNNN>-<topic>.md                   # 业务级 ADR
```

## 二、领域模型主体模板

```markdown
# V<MAJOR>.<MINOR> 领域模型

> 本文档定义 <版本> 阶段的业务实体、状态、规则。
> 不写"怎么存"(那是 L2 Tech 的事),只写"业务是什么"。

## 1. 实体(Entity)

### <实体名>
**业务定义**: ...
**关键属性**(纯业务语言):
- <属性 1>: <业务含义>(不给类型)
- <属性 2>: ...
**生命周期**: ...

## 2. 状态机(State Machine)

### <实体名> 状态机
```
[<状态1>] ──[动作1]──► [<状态2>]
   ▲  │                     │
   │  └────[动作2]─────────┘
   │
[动作3]
   │
   ▼
[<状态3>]
```

### 状态语义
- **<状态1>**: ...
- **<状态2>**: ...

### 状态转换规则
- 动作 X 只能在状态 Y 下触发
- 同一时刻全局唯一 1 个 <状态名>

## 3. 业务不变量

> 这些是"违反了就业务崩塌"的规则,不写技术实现。

  → ...
```

## 四、写作纪律

1. **可以出现**:`timer_session`、`focus_ms`、`task_title`、`status`、`active`/`paused`/`completed`(这些是**业务概念**,允许)
2. **严禁出现**:`INTEGER`、`TEXT`、`partial unique index`、`SQL`、`invoke`、`Mutex`、`src-tauri/`、`tauri-bridge.ts`
3. **业务不变量用业务语言**:"全局唯一 1 个 active session" 而非 "WHERE status='active' partial unique index"
4. **ADR 三标准**(必须同时满足才入 ADR,否则进 PRD §3 业务规则):
   - 硬要 reverse(决定本身难撤回)
   - 惊讶无上下文(新 agent 接手会问"为什么")
   - 真实 trade-off(真有 N 个合理选项)
