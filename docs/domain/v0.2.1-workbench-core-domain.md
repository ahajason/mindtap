# V0.2.1 工作台账核心 — 领域模型

> 本文档定义 V0.2.1 阶段的业务实体、状态机、用户流程、业务不变量。
> **不写"怎么存"(那是 L3 Tech 的事),只写"业务是什么"。**
> 对应 PRD: `docs/轻念Mindtap产品需求文档.md` 阶段一 任务 1.1(全局快捷键捕获)+ 1.2(常驻浮窗·并行任务条)。
> **范围**: V0.2.1 = 捕获 + 并行任务条;V0.2.2 = 状态流转(收件箱整理/待办/归档)+ 自动计时空闲保护(1.3 + 1.4)。
> 本文档**取代** `docs/domain/v0.2-domain-model.md`(V0.2 独立 timer_session 模型),是工作台账方向的新领域模型。

## 1. 实体(Entity)

### 1.1 Item(一条记录)

**业务定义**:产品内所有记录是同一个实体,用类型区分两族——任务族(有状态机、计时、并行推进)与速记族(生活记录,远期)。这是 PRD §3.1「统一实体」的首次落地,取代 V0.2 的 timer_session(独立计时记录)。

**关键属性**(纯业务语言):
- **内容**:这条记录记了什么(≤200 字)
- **类型**:任务 / 速记族(V0.2.1 只有任务族)
- **状态**:这条记录当前所处阶段(5 种,见 §2)
- **累计投入时长**:在「进行中」状态累计的投入(只增不减,自动累计)
- **最近活跃时刻**:最近一次有动作(开始/暂停/备注/完成)的时刻
- **进度备注**:「我做到哪了」,≤100 字,可空
- **来源**:手动 / 建议 / hook(hook 远期)
- **创建时刻 / 更新时刻 / 软删除时刻**:标识与生命周期

**生命周期**:
- 捕获 → 进入「收件箱」
- 浮窗点「开始」→ 进入「进行中」,计时自动累计
- 暂停 / 切走 / 空闲 / 跨天 → 退回「待办」或待办区
- 完成 → 「已完成」;次日自动归档,归档只读,可重新激活
- 任意状态可删除(5 秒可撤销,软删除,完整能力在 V0.2.2)

## 2. 状态机(State Machine)

### 2.1 Item 状态机(五态,支持多并行)

```
         捕获(非空即存)
              │
              ▼
         【收件箱】───────────[开始]──┐
           │  ▲                       ▼
           │ 仅留档              【进行中】◄──[开始]──【待办】
           ▼  │                    │  │                  ▲
         【归档】                  │  └──[暂停/切走/      │
           ▲                      │      超时]──► 待办  │
           │                      │                     │
           └──[重新激活]──► 待办   │                     │
                                  │                     │
                              [完成]                    │
                                  ▼                     │
                              【已完成】──[次日自动]──► 归档
                                   │                    │
                                   └────────────────────┘

任意状态 ──[删除]──► 软删除(5 秒可撤销,完整能力在 V0.2.2)
```

### 2.2 状态语义

| 状态 | 语义 | 累计投入时长变化 |
|---|---|---|
| **收件箱** | 刚捕获,未整理 | 不计时 |
| **待办** | 已整理待开始(含暂停/超时退回) | 不计时 |
| **进行中** | 正在被投入,计时滚动 | 累计增加 |
| **已完成** | 完成封存 | 冻结 |
| **归档** | 只读,可重新激活 | 冻结 |

### 2.3 状态转换规则

| 动作 | 前置状态 | 后置状态 | 副作用 |
|---|---|---|---|
| **捕获** | (无) | 收件箱 | 内容非空即可存;零前置选择 |
| **开始** | 收件箱 / 待办 | 进行中 | 把其他「进行中」的任务**退回待办**(零成本切换,一次动作);开始计时 |
| **暂停/切走** | 进行中 | 待办 | 结算投入;失真时把失真窗口标「待确认」 |
| **超时暂停** | 进行中 | 待办 | 结算投入;**失真窗口只停不抹**,标「待确认」 |
| **完成** | 进行中 / 待办 | 已完成 | 结算投入;记录完成时刻 |
| **次日自动归档** | 已完成 | 归档 | 系统自动 |
| **重新激活** | 归档 | 待办 | 只读解除,可重新开始 |

### 2.4 注意维度(派生展示,非状态)

「进行中」任务按**最近活跃时刻**自动派生:
- **活跃**:2 小时内无动作 → 正常显示,计时滚动
- **冷却**:2~24 小时没碰 → 失真信号,触发确认气泡
- **晾着**:超过 24 小时没碰 → 失真信号,触发确认气泡

> 冷却/晾着**不是状态位**,是「进行中」的真实性衰减,靠失真闭环主动询问(见 §4.3)。

## 3. 业务不变量(违反即业务崩塌)

1. **捕获无门槛**:内容非空即可保存;空内容不保存
2. **计时自动**:点「开始」即累计,暂停/切走/空闲/锁屏/跨天即停止,**不需要用户维护计时的正确性**
3. **投入只增不减**:累计投入时长**永不自动减少**;失真窗口是否计入由用户确认,系统不武断抹除
4. **进行中不跨天**:「进行中」当天结束即退回待办(跨天兜底),时长不膨胀
5. **进行中数量不限,但有 WIP 软上限**:超过 5 个轻提示,不禁止
6. **切换零成本**:在另一张卡点「开始」,上一个自动退回待办,一步完成
7. **完成/归档只读**:只可重新激活
8. **数据永存本地**:不自动清理;删除必须用户主动且可撤销
9. **不抢焦点**:浮窗 / 确认气泡**永远不抢当前键盘焦点**
10. **重复捕获不阻止**:同名任务可并存,系统只轻提示,不自动合并

## 4. 用户流程(User Flow)

### 4.1 捕获(全局快捷键,PRD 1.1)

```
[用户] 任意应用内按全局快捷键
  → 浮窗展开 + 输入框聚焦(不抢原窗口焦点,仅临时获得输入权)
  → 输入内容 → 回车
  → 保存进收件箱、浮窗收起、焦点归还原窗口
  → 空内容不保存;Esc 取消
  → 全程 ≤3 秒、≤3 次点击;连续捕获 10 条不打断当前输入流
```

### 4.2 并行推进(PRD 1.2)

```
[用户] 浮窗展开
  → 看到全部「进行中」卡 + 收件箱项(每张卡:内容 / 累计时长实时滚动 / 冷却深浅 / 进度备注直接显示)
  → 点某收件箱项「开始」→ 进入「进行中」
  → 再点另一张卡的「开始」→ 前一张自动退回待办、这张开始计时(一步完成)
  → 超过 5 个「进行中」→ 浮窗轻提示「在推进的事有点多」(不阻止)
```

### 4.3 失真确认闭环(方案 C,PRD 4.2 借鉴 Toggl)

```
[系统] 检测到「进行中」任务失真(冷却阈值 2h 无更新 / 跨天)
  → 弹出独立确认气泡(不抢焦点):
       「写代码 还在进行中,还要继续吗?」[继续] [暂停]
  → 用户 5 秒内无操作(可能忘了 / 可能还在专注)
       → 自动暂停退回待办,计时只停不抹
       → 失真窗口(失真点→暂停点)标「待确认」
  → 用户回来 → 看到「刚才这 X 时间要计入吗?」[记入] [丢弃]
       [记入] → 结算进累计投入
       [丢弃] → 丢弃该窗口,投入不变
  → 跨天无人回应 → 跨天兜底退回待办,防膨胀
```
