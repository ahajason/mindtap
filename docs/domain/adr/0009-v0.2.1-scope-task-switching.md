# 0009 — V0.2.1 范围：选已有 task_title（SwitchDropdown）

**Status**: accepted · 2026-07-11 · V0.2.1 立项
**引用警告**: 本 ADR 内推断已标注 · 沿用 V0.2 spec v1.1 的事实标注约定

V0.2.1 在 V0.2.0 折叠 + 展开输（无选择）的基础上，于展开态加 **SwitchDropdown** 组件，从历史 completed timer_session 中挑一条 `task_title` 复用 — 创建新 timer_session 后立即 active。**不**支持删除历史 session、不支持直接复用旧 session（避免历史被覆盖）。

## 候选方案

| 选项 | V0.2.1 折叠 | V0.2.1 展开 | 后置版本还做什么 |
|---|---|---|---|
| A 仅复用 (复用旧 session) | 不变 | 加 SwitchDropdown → 复用旧 session 直接 active | V0.3 加删除历史 |
| **B** ✅ 复用 task_title + 新 session | 不变 | 加 SwitchDropdown → 选已有 task_title → 创建新 session → active | V0.3 加删除历史 |
| C 仅手动输（不选） | 不变 | 不变 | V0.3 加 SwitchDropdown |

## 为什么选 B 而不是 A 或 C

- **不选 C**：与 [ADR 0003] V0.2.1 = "选已有 timer_session" 决策冲突。V0.2.0 流程已含手动输，V0.2.1 必须加新动作，否则 V0.2.1 没交付。
- **不选 A**：复用旧 session = 把历史 completed session 改回 active，丢失 `completed_at` 与历史序列。
  - **优点**：少一次写入，db 体积增长小。
  - **缺点**：历史不可逆污染；多次"做完再回来"会让同一个 session focus_ms 反复改；用户看不到"之前做了多久"的真值。
  - **接受 A 等价于接受"历史可被未来覆盖"**—与 [ADR 0005] 永久保留语义冲突。
- **选 B**：创建新 session 复用 task_title — 历史 completed session 完整保留（用于 V0.3 主窗时间线），同时用户无需重复输入。
  - **历史保留的代价**：db 体积增长（按用户决策 Q10 永久保留，V0.3 评估是否归档）。

## SwitchDropdown 在 V0.2.1 是**展开态**的子组件（非折叠态）

- 折叠态 320×36 = V0.2.0 锁定不变（含 50 字符上限；SwitchDropdown 列表项文字可能超出，折叠态不承载）
- 展开态 360×280 = 加 SwitchDropdown section（在 InputBar 上方）
- 折叠态保持极简 = `.archive/` V1.0 PRD §7.4 折叠态设计意图契合 [推断 — 是否沿用待 V0.2.1 spec 阶段确认]

## 列哪些 session — 候选

| 选项 | 含义 | V0.2.1 倾向 |
|---|---|---|
| **A** ✅ 仅 completed + task_title 去重 + 末次使用倒序 + N=5 | 最近 5 个不同 task_title | 默认 |
| B 全部 completed session + 不去重 | 长列表 | — |
| C 全表 + 状态过滤 (active/paused/completed 都显示) | 列表太杂 | — |

**决策 = A**: 不去重 = 长列表 (一个 task_title 多次完成)。task_title 唯一 + 末次使用倒序 = 给 V0.3 主窗时间线看历史最相关的 5 个。

## 选后行为 — 候选

| 选项 | 含义 | V0.2.1 锁定 |
|---|---|---|
| A 创建新 session 复用 task_title | 新 session, status='active', started_at=now | **✅ 锁定** |
| B 复用旧 session 直接 active | 旧 session, status='active', completed_at=NULL | 否（见上） |

## 后果

- **+** V0.2.1 交付与 [ADR 0003] 一致；V0.3 加历史删除 UI 时无 schema 改动（仅 UI）。
- **+** 历史 completed session 不被覆盖 → V0.3 主窗时间线落地时数据完整。
- **−** db 体积会因"新 session 复用旧 title"而增长；按用户决策 Q10 永久保留，V0.3 立项时评估是否加 `archived_at`。
- **−** SwitchDropdown 列表项 task_title 可能超 50 字符（V0.2.1 列表项显示需截断；选中后输入框显示完整）。
- **?** V0.2.1 是否引入 `pending` 暂存态（"选已有后未点开始"的中间态）— 待 V0.2.1 spec 阶段 grill。
