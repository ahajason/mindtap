# 0003 — V0.2.0 最小可交付：折叠 + 展开输（无任务选择）

**Status**: accepted · 2026-07-11 · V0.2 立项
**引用警告**: 本 ADR 内推断已标注。文中关于“V0.2.1 任务切换”的候选与后果只记录 2026-07-11 当时的路线，已被 ADR-0010 取代，不再定义当前 V0.2.1。

V0.2.0 浮窗包含**折叠态**（320×36，显示当前 task_title + focus_ms 计时器）+ **展开态**（输入 task_title → 点开始 → 自动进入 active 并折叠）。**不**支持“选择已有任务”。该能力如需恢复，必须以新的版本号独立立项。

## 候选方案

| 选项 | V0.2.0 折叠 | V0.2.0 展开 | V0.2.1 还做什么 |
|---|---|---|---|
| A 只折叠态 | 计时 + 任务名 | — | 加展开 + 选 + 输 |
| **B** ✅ 折叠 + 展开输 | 计时 + 任务名 | 输 + 启动（无选择）| 加"选已有 timer_session" |
| C 一步到位 | 计时 + 任务名 | 选 + 输 一步到位 | 没东西做（砍 V0.2.1 版本）|

## 为什么选 B 而不是 A 或 C

- **不选 A**：用户回答 Q3 时排除了"只折叠"，V0.2.0 须含展开态。**这是用户决策，不是推断。**
- **不选 C**：选已有 timer_session 需要展开态多一个 SwitchDropdown。
  - `.archive/src/floating/components/SwitchDropdown.tsx` 文件存在（`.archive/` 内容，整体非事实，不预设 V0.2.1 是否复用）。
  - `.archive/docs/projects/v1.0/v1.3-floating-bugfix-iter1-f0.1.md` 修复报告存在（`.archive/` 内容，整体非事实，是否参考待 V0.2 spec 独立评估）。
  - **但**：SwitchDropdown 是否仍是 V0.2.1 的"选已有"实现方式，**未与用户确认**——V0.2.1 spec 阶段重新评估。
  - **且**：选 B 的"迭代风险更低"是**推断**，未实测。V0.2 spec 阶段需用户确认产品迭代节奏偏好。

## 后果（候选，待 V0.2 spec 确认）

- **+** V0.2.0 = 单一交互路径（输 → 启动 → 折叠 → 计时），验收简单（用户决策）。
- **？** V0.2.1 加 SwitchDropdown 时边界是否清晰——**待 V0.2.1 spec 阶段评估**。
- **−** V0.2.0 用户不能从历史 timer_session 里挑一个继续计时（这是 V0.2.0 范围限制，非副作用）。
